## 迭代 246 · v4.112.0 · 第十三期 R13-X1 「今天」：五条时间流收成一条

- 【版本升至 4.112.0】R13-X1 今天：打开时计首屏就是一屏「今天」—— 微信消息、日程、日记、照片按时刻排成一条轴，每条都能打开原 App，且「没接入」「钟读不到」「今天真没事」三件事分开说（三件内核 + 页签 + 24 项判据，含计划书点名的边界口径与排序负控制）
- 【本版做什么】三件内核按「定死口径」「行长什么样」「怎么排怎么判态」切开：config/today-terms.js 4117 字节零 import 叶子（五态闭集、三源态闭集、四源序、四 kind、两项限额、排序口径），config/today-rows.js 4088 字节（单条事件行归一），config/today-timeline.js 7729 字节（归并排序 + 五态判定 + 一句话读数）。主件首版实测 9708 字节超了 X1 给的 8K 预算，故拆出行归一这一件——拆完调用面一字未变，聚合件仍原样转发 collectSource 与 idOf、titleOf 三个出口
- 【本版治什么】五个 App 五条时间流：消息按会话看、日程按日历看、日记按天看、照片按相册看，用户要回答「今天到底发生了什么」得开四个 App 自己对时刻。本仓另有世界侧脉冲与事件档案，但没有任何一处是「我的今天」这个横向面
- 【本版做什么】边界先定死再写代码：今天的边界取剧情日的零点切，三条理由写在术语件头注里——用户读到的每个时刻都是剧情时刻、用墙钟切会把剧情里一晚切成两半、睡眠周期切与世界历切都需要本仓当前没有的权威定义。剧情钟读不到时如实报 no-clock，不退回墙钟：退回就是把 1943 年的今天读成 2026 年的今天
- 【本版做什么】三件事分开记，是本项最容易被糊掉的一处：at 读不出来当场丢弃并记账（不给 0 充数，0 会被排到 1970 年，那是替用户编了个时刻）、没有 id 也当场丢弃（点不回去的条目放进时间轴等于让用户点死链）、时刻对但不在今天只记 outOfRange 不算丢弃（否则一个正常的历史列表会把丢弃数顶到很大，界面报出一堆假警报）
- 【本版做什么】五态不是布尔：ok 有事件、empty 都接上了真没发生、partly 只接上一部分且还没有事、absent 一个源都没接、no-clock 边界定不下来。absent 与 empty 的处置相反（去装 App 与确实没事），压平就是本仓最贵的老账。视图五态各自画，且只有三种「算不出来」带「不等于今天没事」这句话
- 【自己抓到的缺陷形态】端到端自测时「无宿主」被报成 no-clock 而不是 absent：App 侧原本只有一道「钟读不到」的分支，把「手机还没起来（一个源都没有）」与「时钟没同步（源在但钟读不到）」压成同一句话。两者处置相反——等它就绪与去同步时间。修法是在该分支内先算 live0（接上了几个源），为零报 absent，否则报 no-clock；判据 D2 两条端到端各测一遍
- 【自己抓到的缺陷形态】主件首版 9708 字节超预算，而被要求拆的理由不是「拆着好看」：行归一（什么算一条可用的事件）与排序（怎么排、怎么判态）本是两件事，混在一件里改任一件都要读另一件的判断链。拆成 today-rows 后主件 7729 字节，两个方向的改动都不再互相牵连
- 【交棒改写】dead-export 与 bind-audit 当场抓到 TODAY_KINDS 只声明不消费（四 kind 定义在术语件却没人读）：修法不是删常量，而是让 App 侧四源取数真的用 TODAY_KINDS.message、memo、diary、photo 填 kind 字段——口径写在数据里就必须有代码在读它，这与本仓那句「手抄清单必然会漏，能算就别抄」是同一件事的两面
- 【本版做什么】跳转按当下能做到的写：四个源 App 都没有 openRef 定位口，故按钮文案只写「打开日记」，不写「打开这一条」——写做不到的话就是一句假承诺。要做精确落点须先给四个 App 补 openRef 与 clearRef，那是另一项工作（v3660 的 C1、C2 会逐 App 验详情态同步与删中间项后仍命中同一条），明确不在本项里顺手做
- 【自己抓到的缺陷形态】判据差点又写成假绿三形：其一用「两段数据」测排序方向，两段时比较符号不变，方向坏没坏不可观测，C2 因此用三条并与只改早一条的对照；其二想用区间内的数据测 at 小于等于零那一支，但那支在区间过滤之后其实不可达（区间已排除 0），破坏也不可见，B1 因此改用含 0 的伪区间 -1e15 到 1e15；其三若破坏只改比较器一支会造出不对称比较器，E2 因此只改方向源本体、比较器一字不动
- 【运行时验证边界】判据证明的是边界口径成文、四源取数与区间过滤、五态互不同形、同刻稳定次序、截断记账、取钟只走 time-source、视图五态各自画、跳转不写做不到的承诺，以及两条真源码破坏（抹掉无 id 丢弃、把方向写死成相反值）。不证明真机上四个 App 的 storyAt 字段覆盖得全：相册历史数据多数只有墙钟 createdAt，本版按「时刻不可用」丢弃并记账，界面会如实报出丢弃数——这是已知边界，不是缺陷
