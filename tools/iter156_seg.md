## 迭代 156 — v3.99.0 · R3-O9 手机桌面与返回路径减负
- 【定位 · 真缺口（本轮实测，不是推演）】config/task-entry.js 的 TE_CARDS 到 v3.98 为止是**全量平铺**：7 组任务卡（今天的事 / 找往事 / 人脉 / 创作 / 整理素材 / 余额 / 看诊）每组又挂 3~5 个 App 目标，新会话第一屏就是把 80+ 入口一次铺开。验收原文要的是「**三步内**完成找联系人 / 查看今天约定 / 继续上次创作」，而现状既没有「先看什么」的默认秩序（高频四类与案头等权），也没有「按卡隐藏」的能力（要么全看、要么去删数据）。
- 【本版做什么（不新建入口 App、不做路由框架）】新模块 config/desk-focus.js（**纯函数**，零 DOM 零 storage 零计时 API）：focusOf 默认聚焦与按卡隐藏、restorePlan 返回路径恢复读数、threeStepOf 三步可达判定；apps/taskentry/taskentry-app.js 接三处（hideCard 只改显示意图、markLeft 与 restoreReading 给恢复读数、view model 里的 focus 读数）；apps/taskentry/taskentry-view.js 把卡列表分**两档**渲染（首屏 / 工具区）并加隐藏与恢复按钮。
- 【五档不同形（本仓点名的形态纪律）】三步判定：dock（桌面图标一步直达，chat 走微信 dock，本就不在任务卡表里 ⇒ 不得误报「找不到这一类」）/ focus（卡加第一个目标 2 步）/ tools（须先展开工具区 3 步）/ hidden（被按需隐藏 ⇒ 只能从搜索进，**不是 0 步**）/ absent（未登记 ⇒ 判不了）。恢复读数三态：restored 与 lost 与 absent 逐格具名 —— **未记不是「丢了」**（从没打开过编辑草稿时不该看到「草稿丢失」，也不该说「全恢复了」）。
- 【本版自己抓到的缺陷形态（形态锚）】focusOf 首版只按 rank 排，而 past 与 people 经 DF_CARD_ALIAS 同为 record（**rank 相同**）⇒ Array.sort 对相等元素不稳定：正序输入得 today / past / people / create，倒序输入得 today / people / past / create —— 「先看什么」随数据来源漂，而这一档正是全版要交付的东西。修法：新增 DF_CARD_ORDER 登记表作**次键**，排序写成 rank 差先比、相等再比登记次序，顺序从此与输入无关（判据以正序倒序双输入同读数为证）。
- 【判据自伤（判据侧，不是实现缺陷）】当版定向套件首跑 3 红：① D3 的破坏锚点把 `if (!b || !a)` 改成 `if (false)` 后 b 仍为 null，`hasOwnProperty.call(b, f)` 当场抛 TypeError ⇒ **异常逃逸冒充「转红」**（看着红了，却根本没走到判据上）；修法是改破坏归一化口（null 收成空快照），破坏真改变行为且不逃逸；② D4 按 12 空格缩进抄锚点、还漏了 else if 前缀，而真源码是单行 else if 形态 ⇒ 锚点实测 0 命中；锚点必须逐字抄真源码整行，不得按印象重排缩进；③ E1 是版本锚，属待抬版的预期失败（抬版后转绿）。
- 【交棒改写（本轮实做）】tests/system-v3980.test.mjs 的 E1 **主动改写为下界形**：原版硬锁 update-log 的 latest 与 head 与入口常量都是 3.98.0，而这三样都是**会随抬版前移**的当版读数，硬锁会让下一版一抬版就红（那是抬版仪式，不是缺陷）。改写后只锁两件不回退的事实（该版台账条目仍在、该版迭代段不可抹）加一条单调下界（入口版本不得低于该版），当前版本面交给当版档 tests/system-v3990.test.mjs 的 E1。本仓既有先例同样走此法。
- 【不新建第二套（计划原文点名）】不新建记忆库、不新建路由框架、不新建桌面配置页；聚焦归类只有 config/desk-focus.js 一份口径（登记表 DF_FOCUS_IDS 与别名表 DF_CARD_ALIAS 只有一处），隐藏名单只有一处（App 的 _hidden），视图不自己改状态（两个按钮都走 App 的隐藏入口）。
