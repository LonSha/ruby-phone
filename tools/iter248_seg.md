## 迭代 248 · v4.114.0 · 第十三期 R13-X7 「这个月」清单

- 【版本升至 4.114.0（五源同源）】R13-X7 这个月清单：房租、水电、体检、家里让买的东西，过去只活在角色的嘴里，说过就算；现在有一张真表，办好留回执、过期会留痕，而「过期」没有一条路径能变成「已扣款」（四件内核 + 一层视图 + 32 项判据，含五道真源码破坏）
- 【本版做什么】四件内核按「叫什么名字」「过不过期」「做哪一步」「存哪一格」切开：config/errand-terms.js 零 import 叶子（四态闭集、十一因由、四类后果、五项限额、六个可办 app），config/errand-lifecycle.js 只答到期了没有，config/errand-actions.js 只答这一步能不能做，config/errand-store.js 是唯一一组存储口
- 【本版做什么】后果件最要紧的不是它记了什么，而是它没记什么：consequence 只有 kind 文本时刻已读四个字段，刻意不给金额格。没有金额格，就没有任何一条代码路径能把「这件事过期了」悄悄变成「钱已经扣了」——想扣钱必须走财务 App 自己那条已经可撤销的路
- 【本版做什么】过期只产生后果事件、不自动扣钱：advanceErrands 只把到期的条从 pending 挪进 expired 并挂一条后果，金额、余额、账本一个字节都不碰；结算永远发生在用户真的去办或真的去付的那一刻
- 【本版做什么】当日到期不算过期：判定用整日边界比而不是比毫秒，今天要交的房租在今天任何一刻都还是待办，过了零点才算过期。这条是替用户挡掉最多误报的一刀
- 【本版做什么】终结态不被时间改写：已办完与已作废的单子，日子到了也不会被打回待办、也不会补一条后果；时间只对「还没人动过」的那一列生效
- 【自己抓到的缺陷形态】判据自带的那条排序断言把 id 字符串当成了条目本体去查，拿到 undefined 之后再读 dueAt 直接崩。修法不是加空判定糊住，而是把期望顺序四个 id 逐字写死，排序错了就当场红
- 【自己抓到的缺陷形态】负控制头一版打的地方天然被上一层拦住：已办完与已作废本来就因为不等于 pending 而被放行，单破坏那一处分支行为一点不变，于是破坏版与原版读数一模一样、判据根本没验到东西。改为逐对替换并断言每一对恰中一次，同时破坏两层放行条件，行为才真变
- 【交棒改写】原打算把清单的读写图省事塞进动作件，结果是动作件要同时管口径与管盘，判据一律测不动它。改为存储单独一件、动作件只吃列表又吐出列表，动作就成了纯函数
- 【交棒改写】清单本来还想在一处写一遍「四态文案」，视图又写一遍，两处一旦不一致就会出现同一条单子在台账里叫已办完、在界面上叫已完成。改为文案表只在内核声明一次，视图只按态取字
- 【交棒改写】清单页最初想自己开一个页签，而事务台在页签源表里登记的是单页形态，多开一页会当场把页签一致门打红。改为挂在事务台的同页插槽，一屏里两段各说各的：上面说到哪一步，下面说欠着什么
- 【本版做什么】提示词里两段不许压成一段：「进行中事务」说的是事情办到哪一步，「这个月清单」说的是还欠着什么；压在一起角色就会把一次缴费读成筹备有进展
- 【本版做什么】判据另立六面：口径闭集与分界成文、四个动作各自的拒法与回执、当日到期与终结态两种不改写、清单页三档不同形且空表说空不劝慰、接线在假 DOM 里只挂一次、五道真源码破坏
- 【运行时验证边界】判据证明的是四态与十一因由闭集、当日到期不算过期、终结态不被时间改写、四个动作的 ok 与 why 分支、后果件没有金额格、清单页在三档下不同形、事务台同页只挂一次、以及五道真源码破坏。不证明真机上的排版与触感，也不证明跨 App 深链跳转：本版只做到指向可办 app 的枚举，真要跳过去还得另接；另有一类本仓反复登记的老形态——看起来没坏但显示不对，本版不能保证这一形态在真机上一出现就被发现
