## 迭代 196 · v4.37.0（2026-01-12）

- 【版本升至 4.37.0（五源同源）：第五期 R5-X1 随身物品与借还事项的可操作卡片】手机侧此前全仓零借还关系引用：微信赠礼只画一条聊天气泡（`chat-view.js` 的 `case 'gift'` 只读 `msg.giftName`），于是「这把钥匙为什么在乙手里、该不该归还」在手机上**没有任何落点**；而用户看到的是一条「我送你一把钥匙」的消息 —— 那不是「实物已转移」。本项要治的正是这半句：**把一条赠礼聊天当成实物已转移**。
- 【契约件新增六态：问不了 / 这件没借过 / 只可写草稿 / 读到了 / 没有出口 / 读不到】压平任意两态都会造出处置相反的处境长得一样：装插件 vs 换件 vs 写草稿 vs 再试一次。其中「上游在、这一件**没有**履约数据」与「插件不在场」最容易被压成一格 —— 前者是「这件没借过」，后者是「问不了」。
- 【所有者与持有人分列】借出只改后者。合成一格就答不了「该不该归还」—— 而那一问正是本项的验收原文。
- 【赠与不产生欠还】`loan`/`handover` 才算借出；`gift` 一律不算。这是本项最容易写坏的一处：把赠礼当成借出，用户会被要求归还一件已经送出去的东西。判据 D1 锁住它，且赠与**不给**「发起归还确认」按钮 —— 亮一个走不通的按钮比不亮更贵。
- 【不认识的动作名如实具名】上游给了词表外的动作名时归 `other` 并**原样留下原名**，读数行点名它（「上游动作名「X」不认识，按「其他」列出」）。静默丢掉会让用户以为那次交接不存在。
- 【同名物品按来源区分】`sourceKey` 是「哪一条事实说的这件事」；两件同名物各带各的 key ⇒ 卡片不串（与卡内同名异人同款口径）。
- 【本版按计划原文做降级模式】上游 M5-X1 未实现 ⇒ 只做**只读卡 + 本地草稿**：没有履约口时明说「只可写草稿」，草稿**不改任何持有关系读数**（判据 C5 逐字比对前后两行），换会话整块作废。
- 【控制器四口】`itemCustody` / `itemCustodyDraft` / `itemCustodyDraftCount` / `itemCustodySelfCheck`；取数抛了如实报「读不到」，**不假装**「没有借还关系」（两者处置相反）。
- 【视图物品卡】面读数 / 「该不该还」独立一行（那是用户来这一屏的理由，混在状态行里会被读成附注）/ 历次交接 / 草稿；三处容器级委托事件；样式双侧投递。
- 【与上一版的接续：R5-O8 的**回源核对**读数形态 + R5-O9 的「唯一出处」纪律】计划原文写的是「复用 memory/联系人 UI 与 M5-X1 投影」——本版把它真正复用起来，不是另起一套：物品卡的**来源可辨**与 R5-O8 的**回源核对**同规（同名两件各带各的 `sourceKey`，与「同一本书只读一次、读到的正文进读数」同族：都是**读数要能对上是哪一条事实**）；而「该不该还」那一句与 R5-O9 的时间方向三态同规（**唯一出处**：三种方向三句不同、判据 A2 锁住视图与控制器都不许自己拼那一句）。R5-O8 那两处形态（读口只认 `chapters`、阶段入口先让出）在本版各有一处同族落点（读口只认「有没有给出关系」、草稿态不许读成读到了）。
- 【本版自己抓到的缺陷形态】D5 首版把破坏写成「让派发相恒为 true」，而 `plugin` 为 null 时那会当场抛 ⇒ 走的是 `unreadable` 分支，**红得落点不对**（破坏确实发生了，但判据判的不是那个落点）。修法是改破坏**派发相的兜底**：没有履约口也不报「只可写草稿」。这与 R5-O9 的 D1 同族 —— **破坏写法不足/落点不对会让负控制假绿**。
- 【判据 tests/system-v4370.test.mjs 二十二条】六组：口径（六态互不同形、所有者与持有人分列、纯契约零副作用、视图接线与样式双侧）/ 内核行为（借出该还、赠与不该还、部分归还与已回手分形、缺格不猜、三态三句、不认识动作名具名、同名按来源区分）/ 接线行为（读到了 / 这件没借过 / 取数抛了 / 无插件只可草稿 / 草稿只在本机 / 换会话作废）/ 五条定点破坏负控制（各带原版必真的反向对照）/ 版本锚。
- 【不做：不复制物品账】手机只存筛选/草稿/引用；持有关系的事实真源在上游物品事件与约定账。本版**不建第二份物品表**，也不扣真实钱包。
- 【不做：不新增孤立 App 图标】卡片并入既有记忆 App 的「问往事」页（与追问面、资料导入面并列），不另开一个 App。
- 【看起来没坏但显示不对】本版两处缺陷都不报错、不崩界面，只是「赠礼被读成借出」与「草稿被读成事实」。
- 【运行时验证边界】本版未做浏览器/真宿主取证。「申请归还→确认→卡片回到甲」属**真宿主 + 上游 M5-X1** 面（上游未实现）；本版判的是它的可判定前件（有履约口时读数走履约面、没有时明说只可写草稿、草稿不改任何事实读数）。docs/runtime-verification-boundary.md 的当版实测数字由 tools/refresh_doc_readings.py 现场跑两道门写入。
