## 迭代 191 — v4.32.0 · 第五期 R5-O5 自然语言搜索的日期、类型与主题同时生效
# 占位：下列条目由 tools/bump_v4320.py 写入 ITERATION_LOG.md 与本版 update-log 条目
- 【版本升至 4.32.0（五源同源）：第五期 R5-O5 自然语言搜索的日期、类型与主题同时生效】
- 【本版自己抓到的缺陷形态（三条，都不报错）：一是闭区间把今天算进来 —— 「昨天还款」把今天刚记的一笔也列出来，而今天与「昨天」是两件事；二是类型条件抽了不用 —— 界面写着「类型 财务」，结果里照样混进昨天日记，条件只是抽给用户看的；三是候选阶段机械整句 —— 「昨天 林安安 还款」整串在正文里连续出现是不可能的，候选集整句零命中，过滤器再准也是在空集上筛】
- 【config/search-facets.js：相对时间词改**闭开区间**（from = 起始那天、toExcl = 今天零点），于是「昨天」恰是「从昨天零点起、到今天零点止」—— 今天与未来都不进区间。为什么不是把「昨天」当单日闭区间：记录的时间戳带时分，单日闭区间会漏掉昨天 23 时之后的时刻；闭开区间一句话说清两端，两边都不含糊】
- 【matchFacets 新增上界判定分支：有 toExcl 时用 day 大于等于 toExcl 判掉；没有 toExcl（显式 ISO 区间，两端由用户写死）仍按闭区间判 —— 两套语义各自具名，不混成一条。被时间筛掉的行仍如实具名 time，不静默丢；读不出时间的行一律不因时间被筛掉（不拿空值当 0 判掉真命中的行）】
- 【类型条件真参与筛选：新增 FACET_KIND_SOURCES（内容类型 → 它落在哪些既有检索源上，源 id 取自引擎 buildDefaultSources 的登记名）与 kindOfRow（读不出即空数组、不猜）。语义是**白名单** —— 用户说「财务」就是要财务那几处，日记（已知源、不属任何财务源）必须被筛掉；未登记的源不因类型被筛掉（宁可多留一条，不可静默丢一条），筛掉的行按 byReason.kind 如实归因，多类型条件取并集】
- 【交棒改写：候选召回改用主题词 —— 新增 recallTermsOf（人名最强优先、类型触发词加回、残余主题词按空格切开，唯一出处），引擎新增 _scoreTerms 并在 query 与 searchAll 接 opts.terms；不传词表时逐字沿用整句比中，旧调用点行为一字不改。触发词必须加回：facetsOf 抽关键词时把它剥掉了，「昨天 还款」这类无人名问句的召回词表会是空的，调用方只能退回整句、整句又零命中，等于本版没修】
- 【search-app.js：候选阶段把主题词交给引擎（拆词只许 recallTermsOf 一份，本层不自己切句，拆不出词即空数组、引擎沿用整句），新增可注入时钟 deps.now 供判据固定时钟；search-view.js 把闭开上界如实显示成「时间 起 ~ 止（不含 止）」—— 显示成闭区间会让用户以为今天也算在内，而本版正是为了修掉这件事】
- 【新增判据 tests/system-v4320.test.mjs（六组）：A 时间区间（闭开上界 / 今天与未来被排除 / 昨天在内 / 显式 ISO 仍是闭区间 / 跨月与午夜边界 / 读不出时间的行不被筛掉）；B 类型条件（抽得出即真参与筛选 / 多类型并集 / 未知源不因类型被筛掉 / 逐条可归因）；C 三条旅程端到端（固定时钟 2026-10-12T12:00:00Z，真 search-app + 假引擎假存储：昨天还款旅程、今天还款被排除、昨天日记被排除、清除日期后合理扩展）；D 候选召回（整句零命中时逐词仍召回、不传词表行为一字不改、分片档同款）；E 负控制四条（退回闭区间则今天被算进来、类型抽了不用则日记混进结果、候选整句则零命中、拆召回词表则空集），每条配原版同款判据必真的反向对照；F 接线与版本锚（视图如实显示闭开上界、词表拆分唯一出处、不请求外部 API、不直接写盘）】
- 【本版自己抓到的缺陷形态：R5-O5 判据第一版有多处打偏，全在套件自身而不是被测代码 —— 一是把闭开上界记成明天（实际是今天零点），实现与判据同步订正；二是把类型条件的语义当成「读不出就放过」，而白名单下日记必须被筛掉，行要带 sourceId 才量得到时间边界（不带量到的是 kind）；三是给 search-app 量固定时钟时发现 facets 直接用 Date.now，遂加 deps.now 注入而不是改实现去迁就判据；四是负控制锚点随实现改动需同步更新。四处都不影响被测代码，但都会让判据量到别的东西】
- 【既有判据订正（写明理由）：tests/system-v3970.test.mjs 的 B9 原锁**闭区间**语义（断言今天的行必须在区间内），而「昨天把今天算进来」正是本版点名的缺陷形态，改锁闭开边界（今天的行在区间外且具名 time、昨天的行在内）—— 不删掉这条，是因为闭开边界必须有人看着，否则下次改动会悄悄退回闭区间；C1 原把调用点文本逐字钉死（engine.query 第二参写 scopeOpt），本版在候选阶段多接一格召回词即失配，改锁语义（这一口确实过筛、且接上召回词）。两处都是判据锁错了面，不是被测代码坏了】
- 【运行时验证边界：本版留下的边界形态仍是本仓反复遇到的那一类 —— 看起来没坏但显示不对 —— 候选召回词与本地时间基准在真宿主上是否如判据假设、面板上「不含 今天」那行会不会被样式挤掉，一个字符都不报错；本版判据为真跑（真契约件 + 真引擎 + 真 search-app，固定时钟，含三条旅程与四组定点破坏），但真实 App 里的搜索面板未跑，本版不能保证其在真实宿主上的最终效果，待实机复核；登记入 docs/runtime-verification-boundary.md】
- 【不做（本版边界）：不承诺未测的语义准确率（只保证已登记的相对时间词与触发词）、不猜未登记的人名与类型（认不出就如实具名并整条不参与筛选）、不新建第二份切词或类型判定实现（唯一出处仍在 config/search-facets.js）、不改引擎相关性排序口径（排序仍归 scoreHit，本层只过滤不重排）】
