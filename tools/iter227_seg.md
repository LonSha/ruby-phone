- 【undoState 五态：已撤销必须压过其余，部分不许说成可全撤】mapTransactionRow 给每笔算 undoState：undoable（committed 且有 compensator 且无可逆步骤）/ partial（committed 但含不可逆步骤）/ undone（已回滚）/ pending / failed。★ 判定次序有语义：rolled_back 必须**先判**，否则一个已撤销的行会被算成 undoable，界面就给出「已撤销却还能再撤」的按钮（G1 负控制专打这一处）。余额映射同理：一个可信数都没有时返回 null 而不是 0 —— 0 元是可信的数，与「没有数」不同形。
- 【回滚不留静默：撤销后行仍在列表，谱系是「再加一条」不是「抹掉中间那条」】executeRollback 是纯内核：它算补偿计划、把状态置 rolled_back，但**不动账**；真正把钱与归属改回去的是真源的 _applyCompensations（LIFO 逆序，逐项失败不影响其余项）。撤销后的事务行**留在列表里**带 rolledBackAt 与补偿条数（从列表消失＝静默恢复，计划明令禁止，G3 负控制专打这一处）；转赠撤销后资产归属回到原主，且 provenanceChain 由 2 条变 3 条（追加一条「撤销归还」记录，不是把 transfer 那条删掉）。含不可逆步骤的事务（如购置会铸资产上链留谱系）撤销后记 partialRollback: true 与 irreversibleSteps —— 状态是「部分完成」而不是「成功」，钱退回来但已铸的来历撤不掉。
- 【三态不同形 + 三键一次写齐】读到了有 N 条 → 正常列表带计数；读到了 0 条 → 「还没有发起过交易 / 还没有登记过任何资产」；读不到 → 「读不到（这是「读不到」，不是「没有发生过交易」）」——三面各一句独立措辞，F 类判据逐句正则钉住。三把键（ue_ / la_ / et_economy_tx_v1）同属一笔账：save() 一次写三键、restore() 一次读回，半截持久化会让「钱扣了但资产没登记」。新键 et_economy_tx_v1 已在 config/storage.js 的 CHAT_DATA_PATTERNS 登记 /^et_/（随会话隔离）并在 scripts/keys-audit.mjs 的 KEY_REGISTRY 逐条登记。
