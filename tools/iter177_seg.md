- 【修前实测的缺口(读码可复算,不是推演)】apps/reading/reading-view.js 的 _renderReader 写的是 `paras.map((p, i) => ...).join('')` —— **整章一次铺进 DOM**;而进度只有 chapter 与 fontPx 与 theme 三格,段内位置**一格都没记**。故改字号、切主题、摘录回跳一律回到**本章开头**(而不是同段)。已实现的 IndexedDB 附件与摘录不在本项射程内(计划原文逐字:不再把「正文落盘」列为新功能)。
- 【新补三支 · config/list-window.js(既有六支一行未改)】paraWindowOf 以**锚点为中心**切 ± 半径;anchorOf 把任意「段落身份」归一成下标(数字优先,`para:` id 次之,读不出如实 null);paraLine 一句话读数。为什么必须与既有两支分开:windowOf **头部**切、tailWindowOf **尾部**切,而「读者停在第 N 段」要看的是**它前后各 R 段** —— 三种切片方向各不相同,硬塞进任一支都会得出「用户不在他要看的位置」。
- 【邻域上限:默认 ≤250 段】验收原文给的是「可视邻域不超过 250 段」。实现上 pageSize 走既有 normalizePageSize(硬上限 200),而默认半径取 (size-1)/2 ⇒ 窗口 199 段,仍在 250 之内;显式半径上限 200 ⇒ 窗口至多 401。两处都写了判据。
- 【三态分开】items 本次该渲染的段 / start 与 end 它在全章里的区间 / hasBefore 与 hasAfter 两头是否还有更多——「已到开头」与「还没加载」不得同形。四种 reason 互不相同:has-more / whole-chapter / empty-chapter(**真空章**)/ paras-not-array(**拿不到章节**,与空章分开)。
- 【锚点归一不补 0】anchorOf 对 null 与 undefined 与空串与畸形一律返回 null —— **不补 0**:0 是合法首段,与「没给锚点」处置相反(这一条在 R4-O1 与 R4-O4 各治过一次,本轮是第三次,故写进判据并配负控制)。
- 【data-para 仍记**全章下标】视图切片后渲染的每一段仍带全章下标(win.start + k)。这是本项最关键的一处:段身份一旦错位,点击摘录就会**拿到别的段**(而界面看起来完全正常)——本仓最贵的那族静默错结果。判据与负控制都盯它。
- 【进度只加一格,键名不变】沿用既有 ruby_reading_progress_<bookId> 键,只**加一格** `para`。加载时「有就贴、没有就不设」——读不出保持 null 而不是补 0。
