## 迭代 140 — v3.83.0 · 计划 R-O7 诊断从「有读数」到「能处置」（五态互不同形 + 失败五项必答 + 域内统一码面 + 真回执 + 一步到入口）

- **【定位 · 计划 R-O7 的真实缺口（修前逐条核对）】** 计划原文四条：① 统一五态显示语义（空 / 未知 / 缺席 / 失败 / 部分成功）互不同形；② 每个失败给出失败阶段、影响范围、可否重试、是否需要切宿主、是否需要用户确认；③ 为续玩交接、财务、搜索、存储、生命周期统一错误码与回执格式；④ 诊断项可直接跳到对应 App 或恢复操作。修前实测：五态在页面上**塌成灰与红两色**（`empty` 与 `absent` 同形，用户会在「本来就没有」的项上反复排查一个不存在的问题）；「读取失败」只给一句话，五项处置信息一项都没有；同一件事故在不同页面上各写各的字符串，检索不到一起；世界书写入的结论**没有回执**留档。
- **【新模块 · config/diagnose-action.js】** 处置面真源：五态常量、失败五项（stage / scope / retry / hostSwitch / needConfirm）、七个域（resume-handoff / finance / search / storage / lifecycle / worldbook / injection）、按域登记的稳定错误码（`域.现象` 两段式）、`buildDisposal` / `disposalLine` / `canJump` / `codeTableSelfCheck`。
- **【五态互不同形（本版存在的全部理由）】** `empty`（面在、值为空 —— 好读数，处置是「不用动」）/ `unknown`（读到但不足以判断）/ `absent`（面根本不在 —— 等升级或装齐）/ `failed`（明确失败，有回执）/ `partial`（部分成功，**不等于**失败：它的处置是「看哪一半成了」）。判据顺序**显式写死**（失败 > 部分成功 > 缺席 > 未知 > 空）—— 顺序本身就是口径。
- **【失败五项缺一即拒判】** 缺项等于让用户自己去猜；不完整时 `ok=false` 且 `why` 逐条点名缺哪几项，一行读数也如实说「失败读数不完整」（不静默降级成一条普通读数）。
- **【错误码归域、不许自造】** 码面只在 `CODE_TABLE` 里登记（唯一真源）；域外即拒、现象串必须是小写连字符形。`codeTableSelfCheck` 逐域自证：**空表必须说出来**（否则「没登记」与「全合规」同形 —— 这正是本仓点过名的形态）。
- **【接线 · 真回执而不是推测】** `config/worldbook-manager.js` 的 `writeMemoryEntries` 在**每一处返回**留一份 `_lastWriteReceipt`（含 `at` / `ok` / `reason`）；诊断内核从宿主的 `VirtualPhone.worldbookManager` 读它 —— 这是「读数必须来自生产 trace 或真实回执」的落地。**没有回执就说没跑过**（unknown），不编失败。
- **【接线 · 诊断内核与视图】** 诊断内核新增 `disposalFace`（域数 / 码面数 / 五态计数 / 逐项读数与处置入口 / 一行总读数；`需要动的项` 与 `能一步跳转的项` 分开报，跳不过去的项**点名计数**）与 `disposalFaceText`；视图新增 `_disposalHtml` 与一张诊断卡（五态 chip + 逐项 + 处置入口）。视图仍只排版，结论全由内核给出。
- **【注入面的两个「0 块」分列处置】** `all-dropped`（候选有、预算关门）⇒ 阶段「预算裁剪」、影响「注入上下文」、可重试、不需切宿主、不需确认、入口 `settings`；`candidates-empty`（召回没给素材）⇒ 阶段「召回取数」、需切宿主、入口 `memory`。**两者处置方向相反**，压成一句「0 块进上下文」就是错读数。
- **【新增套件 · tests/system-v3830.test.mjs（12 用例）】** A 结构面 2 条（真源与出口 / 内核真取这面且视图走转发）、B 行为面 2 条（五态与顺序与五项拒判与域码与跳转 / 计划原文点名的三种情形文案不同形）、C 接线面 2 条（真跑 collectDiagnose / 真跑 writeMemoryEntries 并把真回执读回来）、D 负控制 5 条（absent 塌成 empty / 五项不再必答 / 域外也给码 / 空码表被判合规 / 回执不再留档）、E 版本锚 1 条。
- **【本版自己抓到的缺陷（一处）+ 对旧读数口径的一处交棒改写】** ① 处置面初版直接引用了不存在的 标识符 worldbookWrite（本仓从没有这个变量）—— 它在无头环境下会被 catch 静默成 null，而有头时是真的 ReferenceError；已改为从宿主实例的真回执 _lastWriteReceipt 读。② 注入面的两个「0 块」此前在页面上**同形**（旧读数只比较 verdict 字符串），本版交棒改写为：同一 verdict 必须落到**不同的失败阶段与不同的处置入口** —— 那是「部分成功与失败不可合并」这条纪律在注入面上的具体形态。
- **【用户可见的边界（与 docs/runtime-verification-boundary.md 同源）】** 本版挡得住「**看起来没坏但显示不对**」这一族：五态塌成灰与红两色、失败只给一句话、同一事故两串不同的码、以及「写了但没回执」。本版 **不能保证** 用户点了处置入口真跳到那个页面（本环境无真宿主）、也不能保证搜索与生命周期两个域在真机上的失败形态与这里的分类一致。边界原文见运行时验证边界文档。
- **【边界 · 诚实三条】** ① 本版把「处置」写成**数据 + 判据**，但**未做真宿主实机**（本环境无 SillyTavern 实例）：证明的是「五态分得开、五项齐备、码面统一、跳转有判据」，不是「用户点了按钮真跳到那个页面」；② 搜索与生命周期两个域本版只登记码面与「面在不在」，**没有回执就不报失败**（不编读数）；财务域的处置项待 R-X3 确认提交向导落地后接入；③ `partial` 态目前只有注入面与写回面会用到，其余域的「部分成功」入口留白并由一键自证看守（空表会说出来）。
