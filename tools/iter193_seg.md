## 迭代 193 · v4.34.0（2026-12-01）

- 【版本升至 4.34.0（五源同源）：第五期 R5-O7 全书连续找句可取消且不反复重建】阅读侧全书找句此前每次调用都现建索引、用完即弃：200 万汉字的书首查 16.25ms、续查 17.77ms、第三次 16.53ms —— 三次同量级，且 App 上没有任何「建了几次」的观测口（探针取到的是 null，不是 0）。
- 【修前的真正代价是形态而不是耗时】建索引与扫全书各是一段同步台阶，期间计时器与点击事件排在宏任务队列里轮不到 —— 用户点「取消」不会有任何反应。本版把同仓 global-search-engine 在 v3.60.0 为搜索立过的纪律接到阅读侧。
- 【契约件 SEARCH_LIMITS 增两格节奏上限】buildChunk 与 scanChunk 与四格「结果上限」分开注释：分片只影响让出节奏，不影响扫到的章与命中的条数 —— 这两件事混成一格，日后调粒度就会动到结果口径。
- 【新增两个分片生成器，声明处不写 export】buildIndexChunks 与 searchBookChunks 按章让出；全仓零消费导出门禁的抽取路径不认 export function* 且 fail-closed 拒判（E9/B5 锁着「生成器声明必须被兜住」），故出口走文件末的具名转出块 —— 不为了加一个出口去放宽一道门禁。
- 【buildSearchIndex 与 searchInBook 改为抽干生成器】分片成为唯一真源：本仓忌同一口径两份实现，两份必然漂移，而漂移的表现是「同一查询在取消路径与普通路径上命中不同」——不报错、只是错数。
- 【新增 indexVersionOf：版本键 = 书 ID + 内容指纹】缺一即为空，空键一律不复用 —— 宁可重建，不可错认版本；正文一变键就变，旧索引自然落空，不会把改版前的段号端上来。
- 【控制器：索引按版本复用，有界且不落盘】_indexCache 超出上限先丢最旧的那一份（不设界就是拿用户内存赌他的书库有多大）；一个字都不落盘，它是**由正文派生的可重建物**，不是第二份正文库。
- 【控制器：建与扫分片让出宏任务】微任务等于没让（同一轮事件循环里会被抽干）；宿主没有 setTimeout 就退 setImmediate 再退微任务，不因宿主差异抛错。
- 【控制器：可取消，任务身份是唯一凭据】newFindTask / cancelFind / currentFindTask：布尔说不清「是谁取消了谁」，而换书、换会话、再点一次查找三件事的正确处置是一样的（不许画上去），故统一用「当前任务是谁」来判。
- 【取消语义两处读数诚实】被取消 ⇒ cancelled 且一条命中都不给（半份结果比空结果更糟：用户会以为「只有这些」）；被后一次查询顶掉 ⇒ stale，界面据此不许把它画上去。取消态返回体只有一处装配点（_cancelledFind）。
- 【本版自己抓到的两个缺陷形态】① 首版只在跨过片边界时让出，于是章数少于片长的书一次都不让出 —— 40 章的书点取消毫无反应、60 章的书却能取消，同一功能两种脾气；修法是两个阶段入口各先让出一次。② 首版比中阶段另手搓了一个取消结果体，chaptersScanned 等格直接缺失（「扫到哪」变成 undefined）；修法是统一由 _cancelledFind 组装。
- 【视图：取消入口 + 进度一行读数】「正在建索引 N/M 章…（可点取消）」；运行态与进度随会话作废；再点查找先把上一轮顶掉。
- 【读数：改前/后双格基线】新增探针 tests/audit/reading_find_scale_probe.cjs 与基线 tests/audit/reading_find_scale_baseline.json，改前那组 R4/R5 如实留痕为**不成立**（那正是本版要治的两条）；两格由 tools/compose_reading_find_baseline.py 从两次现场读数合成，不手抄。
- 【判据 tests/system-v4340.test.mjs 二十二条】六组：口径 / 内核行为（分片与同步逐字段等价）/ 接线行为（三次只建一次、换版本重建、换书不串、取消可响应、索引不落盘且有界）/ 四条定点破坏负控制 / 改前改后读数锚 / 版本锚。
- 【不做：不在没有基线时宣称更快】分片让出把一段同步台阶换成许多轮宏任务，绝对耗时可能变长（本机首查 86ms vs 改前 16ms），换来的是「期间计时器与点击事件能跑到」；计划要的是记录读数，不是承诺更快。
- 【不做：不把缓存误称永久复制正文】索引只在内存里、条数有界、进程退出即无、一个字都不落盘。
- 【取消反馈 ≤200ms 属真 DOM 层读数】归浏览器门；本版判的是它的可判定前件：片间真让出宏任务、取消后不再扫下一片、读数如实 —— 把前件当结论写进 Node 层就是自造判据。
- 【交棒改写】R5-O8 研究摘录重开后自动回源核对可复用本版的取消与任务身份（计划原文：「O7 的取消/任务身份可复用但非强前置」）；R5-O9 追问条件可见可改待办。
- 【看起来没坏但显示不对】本版两处缺陷都不报错、不崩界面，只是「取消按钮时灵时不灵」与「扫到哪读成 undefined」。
