## 迭代 194 · v4.35.0（2026-12-15）

- 【版本升至 4.35.0（五源同源）：第五期 R5-O8 研究摘录重开后自动回源核对】阅读侧「创作素材清单」此前只吃运行时缓存里的正文：重启后直接进研究页（没先打开过书）时缓存是空的，于是每条摘录都落成 FINGERPRINT「未定论」。那个态不算撒谎（它说的是「这次没读正文」），但它把两件不同的事压成同一格 —— **附件压根没存过**（缺失）与**这次没读**（正在核对）；更硬的一条是修前**没有任何入口**能让这一屏变好。
- 【契约件新增 readBooksForAnchors：按书逐本读正文的生成器】让出粒度是「每本」而不是「每 N 本」：一本书本身可能就是百万字级，按本让出才贴近取消预算；读不到就如实写进读数（chapters 为 null 且 why 说清是没存过），并**照样产出这一条** —— 跳过它等于把「没读到」伪装成「没有这条摘录」。
- 【契约件新增 researchListChunks：研究清单按书分片】与同步入口逐字段等价（同一 researchItemsOf 装配），差别只在读正文与归条之间逐本让出；声明处同样不写 export（门禁不认 export function*）。
- 【唯一装配点 researchItemsOf】清单条目的装配只有一处：同步入口与分片入口都从这里取 —— 两份装配必然漂移，而漂移的表现是「同一批摘录在两条路上得到不同的出处结论」，不报错、只是错数。
- 【buildResearchList 改为抽干分片版】分片成为唯一真源，与 v4.34.0 的建索引/找句同规。
- 【清单读数增两格回源读数：books 与 read】几本在书目里、几本这次真读到正文；读数行如实说「这次读到正文 N/M 本」，读到 0 本时**明说一本都没读到** —— 否则「没核成」会被读成「都对得上」。
- 【控制器 researchListAsync：异步、分片、可取消】读口一律复用既有的 bookReadOf（缓存优先、再附件），本件不另开第二条读取路径；读到的正文顺手进运行时缓存，下一次查找与核对不必再读一遍附件。
- 【控制器新增任务身份 newAnchorTask / cancelAnchor / currentAnchorTask】与查找同规：换书、换会话、再点一次「重新核对」三件事的正确处置是一样的（不许把上一轮的读数画上去），故统一用「当前任务是谁」来判；没有任务时如实报「没有」，不编一个假的成功。
- 【视图：重开研究页自动回源核对一次】为什么必须自动：清单每条都带出处读数，而读数要正文才算得出来 —— 重启后不先打开书就看清单，修前会显示一片「未定论」，等于把「还没核」显示成「核不了」，而用户没有任何办法把它变好。自动那一跑用 setTimeout 排在绘制之后，不把这一帧拖到读附件之后。
- 【视图：手动重跑 + 取消 + 进度读数】「正在核对清单出处 · 已读 N/M 本（没核完之前这屏的读数不当结论）」；换会话一并作废运行态并**先取消正在跑的那一轮**。
- 【本版自己抓到的两个缺陷形态】① 读口若额外要求 `r.ok === true`，「读到了正文」会被判成「读不到」—— App 的读口 bookReadOf 给的是 {id,title,contentHash,chapters,why}，本来就没有 ok 格；多加一条要求会把读到与读不到压成同一格，而那正是本版要治的形态（判据 A1/D2 锁住，破坏副本上 read 直接落 0）。② 让出只放在「跨过边界」时，书目为空就一次都不让出，取消永远受理不到（与 R5-O7 同一族形态：同一功能两种脾气，用户只会认为按钮时灵时不灵）；修法是阶段入口先让出一次，判据 B3 判的正是「第一次让出时还没读任何一本」。
- 【判据 tests/system-v4350.test.mjs 三十七条】六组：口径（读口只认 chapters、出口在具名转出块、唯一装配点、纯契约零副作用、回源读数两格、自检第八项真跑）/ 内核行为（分片与同步逐字段等价、逐本让出、阶段入口先让出、读不到照样产出、自带正文不被覆盖、同书只读一次、读口抛错不当核对通过）/ 接线行为（冷启动真读到正文、附件缺失如实、改版落需确认、取消不返回半份清单、任务身份、读口复用、视图入口与自动那一跑）/ 四条定点破坏负控制（每条配原版必真的反向对照）/ 版本锚。
- 【不做：不重建研究笔记功能】清单条目就是既有那一批摘录，只是出处读数这次是真核出来的；没有新开一份摘录列表，也没有新增笔记字段。
- 【不做：不只改「未核对」文案】修前的问题不在字，在「没去读」—— 改字是掩盖，不是修；本版动的是读正文这一步。
- 【交棒改写】v4.34.0 的出口块 export { buildIndexChunks, searchBookChunks }; 被 A4 判据锁着**精确形态**，本版**另起一块** export { researchListChunks };，不改历史那一块 —— 改历史判据与放宽门禁只差一步。
- 【看起来没坏但显示不对】本版两处缺陷都不报错、不崩界面，只是「读到了却说读不到」与「取消按钮时灵时不灵」。
- 【运行时验证边界】本版未做浏览器/真宿主取证。取消反馈与「跳回原句」属**真 DOM 层**读数（计时器 + 点击 + 渲染 + 滚动），归浏览器门 tests/browser/gate.mjs；本版判的是它们的可判定前件（分片真让出、取消后不返回半份清单、读数如实、冷启动真读到正文）。docs/runtime-verification-boundary.md 的当版实测数字由 tools/refresh_doc_readings.py 现场跑两道门写入。
