## 迭代 242 · v4.108.0 · 第十三期 R13-O6：空态四态与 reason code（三种处境不再同一句话）

- 【版本升至 4.108.0】R13-O6 空态四态分形：ok / empty / blocked / absent + reason code 词表 + 六个高频 App 真接线（五源同源）
- 【本版治什么】全仓空态文案数百处，但「真的没有」「有但被挡住」「取数面不在」三种处境共用同一句话。用户看到「还没有照片」无法判断该去拍一张、该去清筛选，还是该去看诊断 —— 三种处置相反，界面却给同一句
- 【本版做什么】新建 config/empty-face.js：四态闭集、reason code 七码词表与归属表、faceOf 归一函数（判定顺序写死在模块里）、faceHtml 渲染（属性与文案同步产出）。零 import 叶子
- 【本版做什么】判定顺序刻意固定为「取数面在不在 → 权限 → 锁定 → 筛选 → 空」：反过来的话，一次存储读失败会被读成「真的没有」，退回本模块要消灭的毛病
- 【本版做什么】真接线六个高频 App：相册（一张都没有 / 分类滤空 / 列表没读上来 三态互不相同，且滤空态给「清除筛选条件」按钮）、群像、钱袋、剧情线、日记、记忆（感官页与场景页分 empty、覆盖度不可用分 absent）
- 【自己抓到的缺陷形态】首版把 filtered 当成无条件 blocked：列表本来就空时仍报「被筛掉了」，用户清完筛选还是空 —— 这是把人往错的方向支走。已改为「确有内容且被滤掉」才 blocked，并把该判断写进模块而不是信任调用方
- 【本版做什么】判据 tests/system-v4109.test.mjs 十四项：A 四态闭集与词表 / B 判定顺序（含空列表加读失败必须报 absent 的反例）/ C 四态文案两两不同（断言的是不同，不是都非空）/ D 真接线与「空与读不到同时被区分」/ E 四向负控制
- 【交棒改写】empty-face.js 是面（说清是哪一种），time-source.js 是取数口（从哪取），setting-effect.js 是时机（何时生效）。三者收的都是「同一件事只有一个说法」，不重叠
- 【运行时验证边界】判据证明的是四态判定与属性在场，不证明浏览器里那行文案的位置与样式。六个 App 的空态外观需真机确认
