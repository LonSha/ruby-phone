## 迭代 197 · v4.38.0（2026-01-26）

- 【版本升至 4.38.0（五源同源）：第五期 R5-X2 把大目标拆成可推进的剧情任务】`apps/plotline` 已有「线索与未完事项板」（v4.27.0 · R4-X6），它能列**账里有什么**，但**没有任何一格能表达用户自己的目标与前置条件**：全仓零 `goal` / `prereq` / `blocked` 命中。于是用户想把「搬家」拆成「签约 → 取钥匙 → 搬东西」时只能在聊天里自己记 —— 而手机里那一屏永远只显示**已经发生的事**。
- 【契约件新增五态：问不了 / 上游没记过 / 只有计划 / 有计划也有事实 / 读不到】压平任意两态都会造出处置相反的处境长得一样。「上游没记过这条」与「插件不在场」最容易被压成一格：前者是「确实没有」，后者是「问不了」。
- 【计划与事实两格分列（本项最要紧的一处）】`planDone` 来自用户勾选（本机草稿），`factState` 来自上游。合成一格就会出现「用户勾了一下，界面说这件事发生了」—— 而那正是本项要治的那类错读数。三句各不相同：**勾了且事实达成** / **勾了但事实没有** / **事实达成但没勾**。
- 【受阻与缺数据分形】前置**已知**未完成 ⇒ 「先做：签约」；前置**根本没记** ⇒ 「判不了顺序：这条目标的前置没人记过（不是「没有前置」）」。压成一格会让用户以为系统知道顺序，而其实什么都没记。
- 【三层上限与超深截断】计划原文验收「展开三层」；超深的层**如实报被截断**，不静默丢。传入的自定义深度被夹到上限（不许超）。
- 【不产任何分数】计划原文「不以九宫格计数充当任务推进」—— 本件设 `GT_FORBIDDEN_KEYS` 并在自检里**真跑**一次深度扫描。
- 【纯计划模式明说「不是已发生的事实」】上游 M5-X2 未实现 ⇒ 按计划原文「先做计划编辑后接事实状态」落纯计划模式，且读数里明说这一屏只是计划（不许称「已记忆」）。
- 【控制器五口 + 换会话作废】`goalNode` / `goalPlanToggle` / `goalPlanCount` / `goalTreeSelfCheck` / `goalPack`；换会话整块作废目标草稿（与追问轨迹/物品草稿同族：不作废会把上一段勾过的画进新会话那一屏）。
- 【视图目标树卡】面读数 / 「计划 vs 事实」独立一行（那是用户来这一屏的理由，混在状态行里会被读成附注）/ 三层展开 / 勾选与取消；四处事件；样式双侧投递（源面 `plotline.css` 与运行时投递面 `phone.css`）。
- 【与上一版的接续：R5-O9 的「唯一出处」纪律 + R5-X1 的两格分列形态】计划原文写的是「复用导航/对象选择器，不新建工作流运行器」——本版把它真正复用起来，不是另起一套：「计划 vs 事实」那一句与 R5-O9 的**时间方向三态**同规（**唯一出处**：三句各不相同，判据 A2 锁住视图与控制器都不许自己拼那一句）；而 `planDone` 与 `factState` 两格分列与 R5-X1 的**所有者/持有人分列**同规（同一族：合成一格就答不了用户真正要问的那一问）。R5-O9 那两处形态（唯一出处、不认识不许兜底）在本版各有一处同族落点（「计划勾了但事实没有」独立成句、超深如实报截断而不静默丢）。
- 【本版自己抓到的真缺陷（当场修）】派发相第二个入参首版传的是「用户有没有打名字」而不是「本机是否真有这条计划」⇒ 只要打了名字就报 `planned`，于是「没建过这条计划」与「有一条计划」被压成同一格：用户看到「你在计划里还没勾」，而其实他**根本没建过**（两者处置相反）。判据 C2 当场抓到，修法是 `hasOwnProperty` 真判草稿在不在。
- 【本版自己抓到的两处判据缺陷】① A4 首版判「全文不得出现 `document.createElement`」—— 而既有 plotline-view 别处**本来就有**（历史代码），判全文会把既有形态算成本版缺陷；改为只判目标卡那一段。② C3 首版夹具给 `{goal:name}`，那是「上游认下目标名但没给别的关系」⇒ 走 `tracked` 而非 `no-goal`；夹具必须让上游**真的什么都不给**（与 R5-X1 的 D5 同族：夹具落点不对）。
- 【判据 tests/system-v4380.test.mjs 二十二条】六组：口径（五态互不同形、计划与事实两格、纯契约零副作用、视图接线与样式双侧）/ 内核行为（勾了但事实没有、受阻说清先做哪一件、缺数据说判不了顺序、三层上限与截断、不产分数）/ 接线行为（有事实面 / 无插件纯计划 / 这件没记过 / 取数抛了 / 勾选只在本机 / 换会话作废）/ 五条定点破坏负控制（各带原版必真的反向对照）/ 版本锚。
- 【不做：不做团队协作平台】目标树是**本机计划**：只存草稿/引用，不写任何上游账，也没有成员/权限/分配那一族概念。
- 【不做：不以九宫格计数充当任务推进】本件不产任何进度百分比与分数（`GT_FORBIDDEN_KEYS` 自检真跑）。
- 【看起来没坏但显示不对】本版三处缺陷都不报错、不崩界面，只是「没建过的计划被读成有一条计划」「既有代码被算成本版缺陷」「夹具落点不对」。
- 【运行时验证边界】本版未做浏览器/真宿主取证。「点下一步打开原约定」与「撤回签约后 UI 同步」属**上游事实面 + 真宿主**读数（M5-X2 未实现）；本版判的是它们的可判定前件（事实态变了读数跟着变、计划侧不被事实侧改写、受阻与缺数据分形）。docs/runtime-verification-boundary.md 的当版实测数字由 tools/refresh_doc_readings.py 现场跑两道门写入。
