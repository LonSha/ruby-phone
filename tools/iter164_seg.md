## 迭代 164 — v4.05.0 · 第三期 E 包手机侧第六项:R3-X9 地点探索与场景漫游
- 【定位 · 计划原文 R3-X9 的真实缺口(修前实测,不是推演)】计划原文要的是「在既有地点页加示意拓扑与地点卡:去过与待探索与可进入,相关人物与往事与约定;点击生成出行或探索提案,不自行移动角色。用户验收:从当前地点选目的地可带出已知线索;未知路径标未知且不编距离;正文或用户确认到达后才更新;无地图坐标也能用列表或拓扑;已有世界状态仍由原 owner 持有」。修前实测:apps/place 三层只有「此刻看到了什么」的投影(场所链与在场角色与到访史与楼层覆盖),没有任何一处能把「想去哪」算成一条可读的路,也没有一处把去过的与没去过的分开;到访史只在读得出来的时候才显示,读不出来时页面也不说这是读不到还是真没去过。用户点不动,也没得点。
- 【新内核 · config/place-roam.js(纯函数,只 import num-gate.js 一处)】四态清单 exploreList 与三态路径 buildRoute 与地点卡 roamClues 与出行提案 buildTravelProposal 与九词归因 ROAM_REASONS 与五上限 ROAM_LIMITS 与只占位不读数据的 normalizeRoamInputs 与自检 roamSelfCheck。所有出口都是纯函数,不改入参(判据钉住);代码本体里没有 window 与 document 与 localStorage 与 fetch 与 eval 与 new Function 与 setTimeout 与 srcdoc 与 require,一道都不许有。
- 【四态与三路由与九归因词:不合形即失败】四态是去过与待探索与可进入与未知,四态文案必须一一对应,两态同形即判失败(同形等于把两种处境糊成一件事)。三路由是精确与同祖与未知:目标在当前链下方即精确,同祖换路即同祖,认不出即未知。归因词九词各归各的处境,读不到面与面里没有与没这面必须分开说,不许用「没有」一个词糊三种处境。
- 【证据优先:读不到不许吞掉直接证据】状态判定写死优先级:树面自带去过为真即去过,这是直接证据,不因别的面读不到而作废;其次才看到访史面读得出且次数大于零;再次才是到访史面读不到即未知;最后才轮到可进入与待探索。读不到不是没去过,这条在判据里是两个方向都钉住的:不带标记的树上每一处都未知,同一条直接证据在树上就必须仍是去过。首版把读不到放在最前,把直接证据吞掉了,是自己抓出来改的。
- 【提案对象里没有距离与耗时格:禁的是逻辑不是字样】出行提案与路径对象里根本没有距离与耗时与分钟与时长与米与公里这些格,判据两道查:对象身上不许有(逐键对齐 hasOwnProperty),代码本体里不许出现。第二道刻意只看去注释与去字符串字面量之后的代码本体,因为禁的是算距离这件事,不是连提醒用户「这里不编距离」的措辞都不许写;首版只看去注释,于是自检里那句提醒把自己判红了。
- 【只在读得懂的时候开口:认不出即拒不就近凑】目标不在树里即拒,理由写认不出,绝不挑一个近的节点顶替;没有当前位置即拒,不假装能算出一条路;已经在这一处即报已经在,不给一串空跑步骤。路径里某一段在树里认不出,就那一段标不认得并如实计数,后面的段照列但都是猜不得的,不许把整条路点亮。
- 【往事与约定只读镜像:不新开第二个 owner】约定账的 owner 仍是日历那一层,本层只读镜像,读到的条目按注了地点才归到地点头上,没注地点的条不归任何地点。读不到时返回空,而不是空数组,这两者意思相反:前者是没这面,后者是这面里真没有。本层一个字节都不写这个账。
- 【本层只产出提案文本:走动只发生在正文里】点「去这儿」只把提案文本投进聊天输入框那一条既有通道,发送与否由用户决定;本层不移动角色,不写任何地点状态,也不改到访史。提案三行结构:先去哪儿,路上认不认得,最后明说这只是提案。认不出目标时提案不给半截话,文本一律空串。
- 【视图层位置即读法:先看原地再想去哪】探索卡排在「同楼同刻」之后与「设置」之前,位置本身就是读法顺序。清单行四态各带自己的字样与自己的类名,未知态用暖色而不是灰(灰等于没啥可看,与待探索容易混),当前所在的那一处单独标出。开关关掉即整卡不渲染,行数可在设置里调,调的是显示条数不是数据。
- 【本版自己抓到的缺陷形态(合并前已修)】1 去注释那段正则的反斜杠被工具多转义了一层,去注释这道自身静默失效,于是注释里提一嘴的词被当成代码命中,同一类同形异码的坑在本仓是第三次重演,最后改成逐字符扫描彻底不用正则;2 判据里把字符串的 includes 结果与负一比较,而它返回布尔,这条判据于是永真,顺手把同型写法全清了;3 负控制的断言写反了,破坏后应当没有未知了却断言还有未知;4 负控制对照面用了带直接证据的同一棵树,原件里本来就有去过的条目,拿它当「全部未知」的对照天然不成立,改用不带标记的树,并且给破坏副本补了一条看得见塌过去的痕迹;5 判据期望值没有跟着口径改:状态判定改成证据优先后,B1 与 D1 还是按老口径写的,红了才发现是判据错不是实现错;6 用固定长度切片去查视图里的一句话,卡片变长就截不到,判据会静默变假,改成切到下一个方法定义处;7 补丁脚本中途断言失败即退出,而写盘在最后,前几处已改的内容全没落盘,重跑时看到的是旧文件,改成失败也先把已改内容存盘。
