## 迭代 136 — v3.79.0 · 计划 R-O6 第二层（非必要动画 / 后台降频与恢复重取 / 有界被动采样）
- **【定位 · 第一层留下的三个真缺口】** R-O6 第二层原文三条：③ 优先移除非必要动画与粒子；④ 后台降频与恢复后重取一起设计，避免恢复瞬间全量重算；⑤ 性能读数被动采样、有界保存，守护器自身不得常驻拖累。修前**逐条实测**的处境是：全仓 `prefers-reduced-motion` 与 `animation-play-state` **零命中**；卡片布局首页的黑胶唱盘在面板隐藏（display:none）之后**仍 running**；宠物 video 在面板关闭与页面隐藏两种状态下都还在播；全仓 `PerformanceObserver` 与 `document.getAnimations` **零命中** — 已有读数全是主动调用式，「用户实际体验到了什么」在两次调用之间是空白。
- **【交付一 · 动效档位与降频闸的统一出口】** 新增 `config/motion.js`：四档 `auto / full / reduced / still`，解析优先级**用户显式 > 系统政策 > 既有默认**；写两个**语义不同**的载体 — `data-motion` 写解析后的档（不写原始 auto，免得 CSS 侧再去问政策）、`data-still` 仅 reduced 与 still 档存在。为什么 full 档必须**移除** `data-still` 而不是写 0：属性存在即生效，写 0 仍会被「带 data-still」的规则命中，那是本仓治过的「属性在但不表达这件事」。
- **【交付二 · 后台处境与用户偏好不得同形】** 闸门产出 `data-bg`（成因 foreground / panel-hidden / doc-hidden / both-hidden 四态互不同形），它是**当下处境**，恢复后必须立刻消失；而 `data-still` 是**用户偏好**，跨前后台持续成立。两者塌成一个属性，现场就答不出「为什么它是静止的」。四态的成因分开报，是因为三种「不活跃」的处置并不相同。
- **【交付三 · 恢复重取合成器（计划原文第 ④ 条点名要避免的形态）】** `createResumeScheduler` 把「没人在场时攒下的重取请求」**合成一次** flush：同 key 覆盖（保留最新那次）、上限有界且超出**如实丢弃并计数**、flush 前先清空台账（任务内再登记不得造成自噬循环）。为什么必须合成：面板关了又开、页面切走又回，若每个消费方各跑一次全量重算，恢复瞬间就是一次尖峰。
- **【交付四 · 有界被动采样器（守护器不得成为被守护对象）】** 新增 `config/perf-sampler.js`：只订阅浏览器**自己**产出的 longtask 条目（阈值 50ms 由浏览器定，**不自造阈值** — 自定阈值等于自己造口径）；环形缓冲定长数组加写指针，溢出覆盖最旧并计数；`arm` / `disarm` 幂等且后台断开订阅；`supported` / `probed` / `count` 三态**互不同形**（「没测到」与「测得 0 条」不得塌成一个读数）。
- **【交付五 · 装饰类与状态类的边界】** 修前 14 处 infinite 动画分散在 phone.css 与四张 App 局部样式表里，逐处打补丁会漏（本仓的清单式漏项形态）。改为两族统一表达：**装饰类**（只提供氛围、不承载状态信息）reduced 与 still 两档都停；**状态类**（承载「正在进行」这件事）**只有显式选 still 才停**。为什么状态类不得进 reduced：那会让「用户选了少动」把正在播的语音弧线与正在输入的指示器一起停掉 — 那是把减动做成「把用户在看的东西停掉」。
- **【交付六 · 政策兜底与静止档】** 政策块带上「脚本尚未写过档位」的条件，**让位于**写入的档：只要 JS 写过属性就交给它说了算，用户显式选全开时这一块必须**不能再**停任何东西（否则用户的选择被系统默默地否掉，而界面上看不出来）。静止档另有一族「连状态类动画与过渡一起停」的规则。
- **【交付七 · 接线四处（缺一处等于没接上）】** ① 动效运行时在 `loadData()` 之后、VirtualPhone 重建**之前**起（档位必须在首帧前写出，否则用户先看到一段动效再被停掉）；② 运行时挂到 `window.VirtualPhone.motion` 这个**唯一出口**；③ 宠物控制器新增 `setActive()` 降频口，锁屏时钟在页面隐藏期不再重算、恢复时补一次重取；④ 设置页新增动效档位下拉作**唯一写入口**，`scripts/keys-audit.mjs` 登记该键。★ 可见性闸绑在宠物的**创建点**而不是 mount：实测只在 mount 里绑会漏 — 悬浮球关闭时宠物仍被创建，于是闸门根本没装上。
- **【交付八 · 浏览器层两份场景（判据面读浏览器自己的结果）】** 新增 `o6-motion-throttle` 与 `o6-longlist-extreme` 两份场景。前者的判据读 `document.getAnimations()` 的 playState 与 video 的 paused —— **不读我们自己写的属性**（属性只是请求，playState 才是结果）；后者把长列表探针推到 4000 楼，并声明本读数**不是**帧率（写进读数本身，而不只是注释）。
- **【本版自己抓到的缺陷（四处真缺口 + 三条假绿负控制，全部由门禁或实测当场报出）】** 见下条 — 这是本版最贵的一段，因为其中三处是「门全绿而问题照在」。
- **【真缺口一 · body 级浮层在降频规则之外】** `data-bg` 的通用子树通配盖不到 `#music-floating-root`：它由 `document.body.appendChild` 创建、position:fixed、z-index 2147483640，**不在 phone-screen 子树内** — 于是面板关闭或页面切走时，其内 `vinyl-spin infinite` 唱盘照转。收口补一段按名列的浮层规则。★ 选择器取浮层的**后代**而不是浮层本身：面板自己的 `.closing` 是关闭动画（0.2s forwards），停了就关不掉。
- **【真缺口二 · 三处装饰类动画未归类】** 蜜语「关注」脉冲与游戏厅猫呼吸同属装饰类，修前在 reduced 档照转。它们躺在 App 局部样式表里，逐处看容易漏 — 这正是把判据改成**按动画名 + 分类闭合**的直接理由。
- **【真缺口三 · 判据射程只到一张样式表（本条最贵）】** 探针 L8 原先只扫 `phone.css`，而**递归全仓**实测到带 infinite 的动画共 **21 处 / 19 个名字 / 7 张 CSS**，漏掉的 **14 处**恰好是「门全绿而动画照转」那一族 — 与修前那句「prefers-reduced-motion 全仓零命中」是同一个病。故两处改口径：扫描面改**递归全仓**；判定改**按名 + 分类闭合**（每个名字必须归入装饰类或状态类之一，未归类一律算未覆盖并点名）。这样将来任何一处新动画都躲不过去，不靠人记得回来补名单。
- **【假绿负控制一 · 破坏不可观测】** D1 初版把采样器上界写成 `Number.MAX_SAFE_INTEGER` — 那仍是**有限数**，判据照旧通过（实测：探针 exit 0、断言实得 0）。这不是判据弱，是**破坏一处产品从不走到的分支**（本仓治过的形态：装饰破坏）。改为拆掉计数上界，count 不再停在 limit。
- **【假绿负控制二 · 锚点缩进失配】** D2 初版锚点写成 8 空格缩进，而真源码是 4 空格 ⇒ 恰中 0 次，拦的是**判据自己**而不是产品。
- **【假绿负控制三 · 测的不是它要守的那条判据】** D4 初版自写一份计数比较（covered 与 infinite 比大小），与判据的判定面不同且阈值过松 — 破坏后覆盖数仍不小于 infinite 数，断言当场不成立。按本仓纪律改为**在真源码上破坏 → 用同款真判据重跑**，并要求它**点名**那个没被覆盖的动画。
- **【本版自己踩的坑（两条，都由实测报出）】** ① 负控制跑错层：动效面属长列表探针，它的镜像根要求 chat-view 的完整输入闭包 — 放在只铺采样面的套件里跑，只会 fail-closed exit 2（那证明的是输入面缺失，不是判据会响）；归位到持有那份闭包的套件。② 镜像根是**缓存**：先跑的负控制会把它破坏掉，后面的判据看到的是别人弄坏的那份（实测：前三处破坏过 chat-view 之后，第四处读到 L1/L2/L6/L7 一并转红）。修法是给需要干净输入的负控制**另铺一份**副本根。
- **【边界 · 诚实三条】** ① 后台降频用 `document.hidden` **属性替换**模拟，不触发浏览器真实节流窗口 — 本层证明的是「代码收到隐藏信号后真停了」，不是「手机上省了多少电」；② 动效与降频的真读数归浏览器层场景，本层（Node）只能证明接线与判据会响；③ 真机上的滚动流畅度与帧率**仍未测**，官方口径见边界文档。
- **【边界 · 用户可见的那句仍须与工程文档同源】** 本层挡得住「看起来没坏但显示不对」这一族的镜像（动画在后台照转、采样器悄悄涨、恢复瞬间全量重算），但**不能保证**目标设备上的省电与流畅度 — 那两项归真机验证。那句话与 docs/runtime-verification-boundary.md 逐字同源，用户侧读到的就是它。
