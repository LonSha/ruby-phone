## 迭代 178 — v4.19.0 · 第四期 R4-O7 通知按事情收拢
# 占位:下列条目由 tools/bump_v4190.py 写入 ITERATION_LOG.md 与本版 update-log 条目
- 【本版做的是第四期优化项第七件:R4-O7 通知按事情收拢,而不只是按发送者覆盖】计划原文要的是「同一约会的改期聚为一组,另一笔转账不被并掉;按 App 与联系人静音、稍后看,保留重要约定提醒」,验收原文给三组实测:同发送者两事件、跨 App 同事件、重复提醒;并明写不做:不重造通知中心、不开启后台 LLM 归类、不许把未读数下降当体验改善证据。
- 【修前实测的缺口(读码可复算,不是推演)】config/system-notifications.js 的 push() 只有**一道合并**:同 senderKey 且 3 分钟内。于是同一件事的两次更新只要换了发送者(或隔了 3 分钟)就是两条;而同一个人的两件不同事(改期与转账)在读数上**无法分开**。计划原文点名的正是这句:「同一发送者的不同事件与同一事件的多次更新缺少面向用户的整理方式」。
- 【新契约件 · config/notice-digest.js(纯函数,零 DOM 零存储零联网零时钟)】只做四件事:**事情身份**(从 meta 取 eventKey,缺了就保守分开)、**按事收拢**(同 eventKey 合成一组,可跨发送者与跨 App)、**静音规则**(按 App 与联系人与事件类型三条维度)、**未读与详情对应**(组内 unread 可数、代表条 id 可点)。时钟不走 Date.now —— 纯函数自己看时间会让「同一输入两次调用得同一结果」失效,而判据正靠它(R4-O5 已立此规)。
- 【事情身份三级,顺序即语义】一 有非空 meta.eventKey ⇒ event 态(可跨发送者、可跨 App 收拢);二 没有 ⇒ sender 态(**保守分开**:同一发送者的两件不同事仍各自成组,缺事件 ID 时**不猜**);三 连 senderKey 也没有 ⇒ solo 态。空串与纯空白的 eventKey **不算有**。
- 【跨 App 同事件归一组】例:「微信说改期」与「日历提醒改期」带同一个 eventKey ⇒ 收成一组并标 spansApps,这正是计划原文「不只是按发送者」的落地形式。判据里配了负控制:破坏 eventKey 判断或让 key 带 appId,跨 App 归组立即散开。
- 【四态互不同形】event 按事收拢 / sender 按来源兜底 / solo 单条 / empty 无通知。压平任意两态都会造出处置相反的处境长得一样:按事与按来源兜底在界面文案上必须分得开(「同一件事 ×3」与「同一来源 ×3(缺事件 ID,按来源兜底)」)。
- 【静音三条维度 + 三条归因】appId 与 sender 与 eventKind;规则形态不对报 mute-not-object,缺维度词报 mute-no-dimension,未登记维度报 mute-dim-unknown。**坏的规则一律跳过(fail-open 到照常打断)**:静音错了会漏掉重要提醒,不静音只是吵一点 —— 两害相权取轻。花式写法里**恰好给一个维度键**才认(给两个即形态不明,不猜)。
- 【静音只影响打断,不删消息】这是计划原文逐字要求,故写进判据:_toggleMute 的函数体里**不得**出现 remove 与 clear 与 markRead。判据还配了负控制:往静音里塞一句「顺手 clear 历史」,同款判据当场转红。
- 【时间跨度不补 0】组的 firstTs 与 lastTs 读不出时给 null,durationMs 也是 null —— 不补 0。反向面同时守:真给 0 照常出数(0 是合法跨度)。这一条与 R4-O1 的楼层、R4-O4 的进度、R4-O6 的锚点同族,故本轮第四次写进判据。
- 【视图按组渲染,行口径仍只有一份】通知中心列表体改走 _listHtml → digestOf → 按组渲染:单条组直接用它那一行(_row),多条组给组头(代表条标题 + 条数 + 跨 App 标记 + 已静音标记 + 「展开 N」+ 「静音此 App」)。**既有 _row 一字未动**,展开的成员行也仍走 _row —— 判据明写 _row 只许一份实现。
- 【本版自己抓到的缺陷形态三处,一处在实现两处在工具(合并前逐条修掉,留痕)】一 **真缺陷**:digestOf 对历史里混进的非对象元素(null 与数字与字符串)会解引用抛错;改成先归一成空壳再收拢,且**不丢条数**(丢掉等于把用户的条数改小),B5 当场抓住。二 补丁脚本的构造器锚点带了行尾注释,而那行注释里的分号是全角(U+FF1B)⇒ 零命中;改取真代码两行做锚。三 抬版脚本的 iter seg 断言「不得含方括号」当场拦下两条含数组下标与方括号标签的条目 —— 这条纪律是给「公告块 JSON 化」守门的,如实改写掉。
- 【交棒改写】本版把 R4-O7 的验收从「有没有分组」交棒到「事件身份三级 + 跨 App 归组 + 静音不删消息」那条路;相关各条判据一律写成下限形与真跑形(行为面直接调模块),下一版抬版无需二次改写。
- 【运行时验证边界(如实声明)】本版在无头环境验证的是:四态互不同形、事情身份三级(含空 eventKey 走兜底)、跨 App 同事件归一组、同发送者不同事不被误并、未读与详情对应、代表条 id 可点、时间跨度不补 0、静音三条归因与 fail-open、静音不改入参、空历史与拿不到历史分开、非对象元素不炸且不丢条数,以及视图按组渲染与展开与静音真绑定、行口径仍一份。**未做**真机上「同一约会改期聚为一组」与「静音后是否真的不再弹横幅」的实机旅程;**另:静音规则本版只存视图实例态,不做持久化** —— 按 App 静音的长期记忆属后续增量,如实留白而不假装已做。
