- 【本版自己抓到的缺陷 · 四条】① home-screen.js 只 import 了 resolveAppOrder、漏了 resolveActiveParadigm，而 _activeParadigm 整段包在 try/catch 里，未定义标识符被 catch 吞掉、兜底那一次同样抛错 ⇒ 永久退回生活档，「换挡没反应但界面全绿」；② 首版只对 15 个桌面格子排序，而范式里的优先项（accounting / focus / reading-studio / worldbook）绝大多数是聚合壳**内部成员** —— 换挡后桌面几乎不动，功能看着像摆设，改为先排全部 App、再由壳内最靠前成员的名次推壳次序；③ paradigmIds 与 saveParadigm 一度被门判成死方法（新加即零消费），前者删除转出、后者接上「另存为自定档」真实入口，**没有**塞白名单；④ 判据 F4 自己写错了字段名（账本条目叫 rel，写成 module || file），导致「账本里明明还有这条」时判据照样绿 —— 修法是先钉字段名再下结论，并加「把条目塞回去必须命中」作负控制。
- 【失败必须说出来，不许静默回退】switchTo 遇到未知 id 返回 success=false + reason=unknown-paradigm-id，**不改盘**；写盘抛错返回 persist-failed，不谎报成功。UI 侧把失败记进 View 的 _lastSwitchFail 并在面板底部出一条警示卡，切成功即清痕（否则一次失败会永久挂在界面上，比不显示更误导）。
- 【自定档的取舍：另存不填表】本版只提供「以当前档为底另存一份自定档」一个动作，不做四组输入的表单。理由如实体现在代码注释里：priorityApps 的合法值是 App id 闭集，让用户手打 id，打错就是静默不生效。固定 id 用 custom、重复另存即覆盖 —— 不堆积 custom-1/custom-2，避免范式列表无限变长、也不让用户看见一堆自己没起过名字的档。
