- 【apps/health/health-state-bridge.js：交接账本升级为「事实账 + 事件账」同住一个持久化键（ruby_health_handoff，不新增键、不造第二份真源），两者各自裁剪、互不挤占（entries 50 / events 50）—— 旧实现只有一个数组，上限一到就把最早的记录连同「这件事发生过」一起裁掉，重放判定随之失效】
- 【事件身份 eventKeyOf：宿主可证身份（如 msg:12）优先；宿主给不出身份时回落内容指纹并如实标 identified:false，不假装按事件去重。宿主把空值拼进身份（msg:undefined / msg:null / msg:NaN）时**不当身份用** —— 否则所有取不到 id 的消息共用一个身份，把几件不同的事去重成一件（静默丢事实）。身份里**刻意不含 swipe**：重生成会换 swipe，算进去会把同一条消息的两次生成当成两件事各自生效，正是本版要防的双计】

- 【只读不抛的降级面：账本查询 / 写入 / 底层存储抛错一律降级为「没有痕迹」（宁可重复一次也不静默吞事实），processReply 仍不外抛；事件身份与内容指纹都是纯算术（无随机、无时钟），指纹只取已校验事实的规范串并排序，故改标点、改排版而事实不变的编辑不算换了一件事（不触发二次生效，也不误报重复）】
