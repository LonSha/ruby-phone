## 迭代 247 · v4.113.0 · 第十三期 R13-X3 消息里能就地办

- 【版本升至 4.113.0】R13-X3 消息里就地办：对方说周六有空吗，消息下方就多一条动作条（加日程 记到备忘 回一句），点下去不离开聊天就写进日历，回执写明来自哪个会话的哪一刻（四件内核 + 一层旁路 DOM + 30 项判据，含四道真源码破坏）
- 【本版做什么】四件内核按「认」「算时间」「写」切开：config/inline-action-terms.js 零 import 叶子（三 kind 按写不写盘分界、三态、六因由、四项限额、时间规则与词表），config/inline-action-time.js 只答一句什么时候，config/inline-action.js 只答该不该办，config/inline-action-commit.js 只答怎么办与怎么撤
- 【本版治什么】chat-view.js 实测 946383 字符，是全仓最大也是用户停留最久的一个文件，而它当前是纯看与回：聊天里提到的每件事都要用户自己切 app 记下来，这是拟真与可用之间最大的一道缝
- 【本版做什么】判据定在误报率上而不是召回率上，故提取设双重门槛：时间词与意向词必须同时命中，只命中一个的句子一律不出条（今天天气不错有时间无意向、一起吃饭有意向无时间）。理由很硬：误报的代价是用户点一下就多出一条错数据，漏报的代价只是自己手动加一次
- 【本版做什么】三档按「写不写盘」分而不按句子长什么样分：算得出具体日子才给加日程（唯一真写盘的一档），日子只有模糊说法（改天 过两天）一律不允许填日期、只能进备忘，reply 只把一句现成草稿填进输入框，一个字节都不写盘、也不替你发
- 【本版做什么】标题只从原句剔词得到、不生成新句子（生成要模型，模型会编）；回一句的草稿按命中词从现成四组里挑，挑不到就不给这一档
- 【自己抓到的缺陷形态】时间规则里的反斜杠转义在跨多层字符串写入时被吃掉，于是 10:30 开会别忘了 被判成 no-time、点钟规则也失效。修法不是补回反斜杠，而是整体改用 0-9 字符类回避转义；改完文件内反斜杠计数归零，并加一条文件级自检
- 【自己抓到的缺陷形态】周六有空吗 这句剔掉时间词与意向词之后什么都不剩，被 no-title 丢弃——而它恰恰是本项最典型的一句。修法是剔空则退回原句（只去标点与问句尾巴），不是放宽意向词门槛：退回原话不产生新信息，降低门槛会直接推高误报率
- 【交棒改写】开始拟用一份导出回测的签名敏感参数、把时间规则在两件里各编一份，结果是算得出日子却删不掉那个字；改为时间规则表由时间件独有、主件只向它要类，同一边界只能存在一份
- 【交棒改写】动作条原设计直接挂在消息行内部，而 chat-message 是 flex 行（头像与气泡并排），挂进去会排到气泡右边、还会被右对齐推到对面；改为挂在行之后的兄弟节点并每次重画先摘干净自己
- 【交棒改写】旁路看守器首版靠「正在写」旗标防死循环，实测不行：变化回调是异步微任务，回调进来时旗标已经改回，于是每一帧都重跑。改为对账两侧签名（计划与 DOM 各算一份），一样就不动手；停手条件是 DOM 已长成该长的样子，不是刚才是不是我在写
- 【交棒改写】开关的存储键起初藏在对象属性里，keys 门当场报未登记归属——它按常量声明抽键面，看不见就等于这个键从来没被问过归属。改为独立常量做真源、对象属性只转引，并在登记表声明全局心展开偏好
- 【交棒改写】主件在开发期就没写几个转出口，而转出不等于被用：它们在门禁里会变成无消费导出与绑定级死导出。判据真要用哪个出口就从真源直取，不靠主件转手；仅为判据存在的转出当场拆掉
- 【自己抓到的缺陷形态】判据自带一份迷你 DOM，第一版把「没有候选就不出条」写成了「函数返回 0」，那只能证明函数被调了，证不了它没往 DOM 写；改为同一屏三条消息里有候选者必须紧邻有条、无候选者紧邻绝不许有条，且全屏只出一块
- 【自己抓到的缺陷形态】四道真源码破坏都不能只看返回值：拿掉出处检查后若另有一条路拒掉，就证不了那道检查有用。故破坏版同时断言副作用可见（没出处的条目真写进了日历），依据是日历替身记下的入参
- 【本版做什么】撤销不新画一套：日历删除已经走回收站，恢复后 id 逐字回来，故动作条的撤销就是调它一把；再造一个内联撤销栈等于把用户学到的撤销行为分成两套
- 【本版做什么】条目必须带出处：日历备忘的写入口多一个可选来源标识，不另开存储键、也不改已有无来源调用的行为（空串就是不是从消息来的）。回执上要写来自谁、哪一刻，界面文案会随重绘丢掉，故出处必须落在条目本身
- 【运行时验证边界】判据证明的是口径闭集与分界成文、双重门槛四种拒法各一例、日子与时刻真算得出且跨月进位、提交四种降级各自不冒充成功、回执逐字可复原、撤销走回收站、动作条在假 DOM 里只在有候选时出条、开关关后一个节点不写、事件委托只绑一次，以及四道真源码破坏。不证明真机上的观感与布局（自带的迷你 DOM 不做布局、CSS、伪元素），也不证明复杂句子的识别率：提取质量只保证宁缺勿滥，唐宁少给不许给错
