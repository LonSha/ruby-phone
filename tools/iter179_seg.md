## 迭代 179 — v4.20.0 · 第四期 R4-O8 流程编排用对象选择器
# 占位:下列条目由 tools/bump_v4200.py 写入 ITERATION_LOG.md 与本版 update-log 条目
- 【本版做的是第四期优化项第八件:R4-O8 流程编排用对象选择器,而不是把内部键名摊给用户】计划原文要的是「不输入任何内部 ID,完成整理记录→存草稿→提醒与结算→日历两条流程;已删对象明确要求重新选择;写步骤仍逐项确认」,并明写不做:不增加任意 JS 节点、不造插件市场、不靠扩大动作表来掩盖当前难用。那两条流程各要先能看懂「会替本项目做什么」,故本版把「看得懂」这半边做成本版可无头验收的部分。
- 【修前实测的缺口(读码可复算,不是推演)】apps/workflow/workflow-design.js 的参数那一行直出内部键:键名写着 note 与 title;条件下拉的选项直接是 resume-face 与 settlement-draft;另有已经装配好的 faceOptions 没人用。于是用户看到的是机器话,「会替本项目做什么」只能靠猜 —— 计划点名的正是这句。
- 【新契约件 · config/object-picker.js(纯函数,零 DOM 零存储零联网零时钟)】只做四件事:参数读数 stepParamsOf(每个键一行:中文名、现值、态、一句提示)、输入面读数 opFaceOptions(内部面名换人话)、候选归一 normalizeOptions(去空去重、缺标签用值、超长截断)、会替本项目做什么 flowPreviewOf(逐步骤一句人话)。与 workflow-designer 同分工,可在 node 里直接测。
- 【面名表不许造面】OP_FACES 只收 WD_ACTIONS 真用过的输入面与产出面;判据逐个核对表里每个键都在真表里出现过,另造一个面当场转红。认不出的面原样回显并标认不出,不猜一个很像的名字 —— 猜错比露键名更贵:用户会以为条件设在 A 上,实际设在 B 上。
- 【参数登记表只登记真存在的键】OP_PARAMS 只收 WD_ACTIONS 声明过的动作与它声明的参数键(save-draft:note 与 notify:title 与 add-memo:title);表里没有的键不许顺手加,加了就是幻影参数。判据拿真表逐条核。
- 【四态互不同形(本仓最贵的老账,本轮再次立规)】filled 有值写「已填」;empty 可留空写「可留空」不当缺陷;candidates-missing 候选读不到写「读不到不等于一个都没有,先手填」;unknown-key 草稿里出现了这个动作不承认的键,写「已经不在这个动作的可选范围了,请重新选择」。压平任意两态都会造出处置相反的处境长得一样。空值的表外键不生成垃圾行:空着没有任何可执行的后果。
- 【读不到不等于一个都没有,而本版自己抓到的第一处缺陷正出在这道闸上】原写法先在 stepParamsOf 里判一次来源于是把候选的 null 短路掉,normalizeOptions 里那句「非数组回 null」在仓内任何调用点都到不了 —— 闸口成了死代码,负控制拿假数组打它也命不中(判据自己没被调用那类假绿)。改成单一闸口:读不到与没有都由 normalizeOptions 一句话判,同款负控制当场转红。候选归一另外守住三件:去重按值、裸值补标签、超长截断。
- 【视图不直出裸键,且候选下拉三件齐全】参数行改走 paramRows(中文名加手填框加候选下拉加一句态说明),条件下拉改走 faceOptions 的值与中文名;新增「会替本项目做什么」预览块逐步渲染。候选下拉的绑定写成三件:选择器带标记、改变处理器里接收、写入走 WorkflowDesign.pick。拾取走与手填同一个绑定口,故表外键在方法里被天然拒掉,不需要第二套校验。
- 【候选读不到时传 null,不补空数组冒充没有】视图装配候选时写死「宿主台账读不到就传 null」,让参数行亮 candidates-missing 而不是伪装成「一个都没有」。判据守这一句,盖住「补空数组冒充」这条最容易顺手写错的路。
- 【会替本项目做什么预览:写步计数加条件中文加认不出如实说】预览逐步骤给人话,并在头一句点明「这条流程会替本项目做 N 步,其中写动作 M 步(写步骤逐项确认后才跑)」—— 写步计数是计划原文「写步骤仍逐项确认」在读数上的落地。认不出的动作写「这个动作认不出,跑不起来」;空草稿写「草稿还是空的,没得预览」而不是「读不到」,两态分开判。
- 【本版自己抓到的第二处缺陷在判据自己身上】接线判据原押三处标记:选择器属性、方法调用、方法签名。负控制只把选择器属性改名时,后两处都还在,判据假绿。改成只押「选择器生成」与「改变处理器」两处同一标记,负控制一改就转红。这是本仓「负控制必须真破坏真判据」那条纪律的又一例。
- 【候选来源本版只启用已存模板名,如实留白】OP_PARAMS 里带候选的只有提醒标题与备忘标题,来源都写已存模板名。计划原文还提到选联系人、日期、草稿与结算对象;这些来源本版未接,因为本版能无头验收的只有模板名这条链,接联系人要先有读数口 —— 如实留白而不假装已做。
- 【交棒改写】本版把 R4-O8 的验收从「界面上有没有下拉」交棒到「不输内部 ID 也能编 加 读不到与没有分得开 加 表外键要求重选」那条路;相关判据一律写成下限形与真跑形(行为面直接调模块、端到端拿假宿主装配),下一版抬版无需二次改写。
- 【运行时验证边界(如实声明)】本版在无头环境验证的是:本层这类形态的共性是**看起来没坏但显示不对**(不报错、不崩溃,只把「读不到」说成「没有」)——本版**不能保证**这类形态在真机上一出现就被发现。四态互不同形、面名表覆盖且不造面、登记表只登记真参数、纯函数零副作用、三处参数都有中文名、认不出即说认不出、读不到与没有不同形、候选归一四件、表外键要求重选且空值不生成垃圾行、预览写步计数与条件中文与认不出如实说、空草稿与读不到分开、视图不直出裸键且真消费四口、候选下拉三件齐全、候选读不到传 null、预览块真渲染、假宿主端到端装配与点选真写进草稿与渲染不露键与台账读不到亮态。未做真机上点选一条流程跑一遍的实机旅程,以及联系人与日期候选来源的接入。
- 【定向判据与版本锚】新套件 tests/system-v4200.test.mjs 三十例全绿(A 口径五、B 行为十、C 接线五、D 端到端四、G 负控制五含反向对照、E 版本锚一);抬版按仓内唯一范式 tools/bump_v4200.py 对齐 tools/bump_v4190.py。
