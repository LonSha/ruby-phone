## 迭代 249 · v4.115.0 · 第十三期 R13-X4 手机也会「不在手上」：离线与错过

- 【版本升至 4.115.0（五源同源）】R13-X4 离线与错过：放下手机不再是概念，而是一个真开关与状态机；离开期间消息、来电、提醒全面静默记账、零即时弹窗骚扰；拿起手机时提供完整的「不在的时候」清单，过期标记、分组聚合、一键已阅（新内核 config/away-mode.js + 中枢联动 + 通知中心与设置页接线 + 9 项严密判据含三道真源码破坏）
- 【本版做什么】新内核 config/away-mode.js 实现纯粹离开状态机与错过账本（AwayMode / AWAY_REASONS / getAwayMode）：isAway 默认恒 false、未启用时系统行为零变化；离开期间记录 missed 条目，提供按时段检索与按 App 聚合摘要
- 【本版做什么】中枢联动双向保证：config/system-notification-dispatcher.js 在 isAway 为真时记录 suppressedBy = 'away_mode' 并调用 awayMode.recordMissed(item)，同时严密封堵 _notifySubscribers 广播——确保离开期间「记了账」且「一条都没真弹出」
- 【本版做什么】重新拿起手机无缝收口：markBack 优雅复位离开状态并返回本次错过的完整快照，后续到来的通知立刻恢复正常即时弹窗，不搞回来后连环自动补发二次骚扰
- 【本版做什么】策略与机制严格分离：过期的判定（日程已过、时效优惠失效）不写死在内核中，支持注入 isStaleFn 外部策略，在 missed 摘要中精准标注 stale: true 状态
- 【本版做什么】视图与设置页双向挂载：通知中心 notification-center-view.js 挂载 _awaySection（离开中横幅 / 不在的时候错失清单展开 / 一键已阅）；设置页 settings-app.js 挂载 _getAwayMode 与 _awayModeSnapshot 读数
- 【自己抓到的缺陷形态】测试夹具中 Node 无头环境实例化 SettingsApp 遇到 window is not defined，修法是将对具体实例依赖下沉到对原型方法存在性与只读快照约定的断言，不引入虚假假阳性
- 【自己抓到的缺陷形态】真源码破坏锚点 `this._isAway = false;` 在构造器和 markBack 中重名命中 2 次导致破坏工具拒绝破坏，改为带上下文的多行唯一锚点精确破坏
- 【交棒改写】曾设想在回来时自动补发所有弹窗，但多条弹窗轰炸反而是劣质体验。交棒改为静默归集在「不在的时候」卡片中，由用户按需查阅或一键已阅
- 【交棒改写】离开模式如果硬编码常驻开启，会破坏现有各 App 的单测与行为预期；交棒为默认 isAway 恒 false，只有显式 markAway 后才生效，做到底层零侵入
- 【运行时验证边界】判据证明的是离开状态机生命周期、离开期间通知全部进 missed 且订阅者零弹出、markBack 状态复位与后续恢复弹出、过期策略注入标记、视图与设置页读数口挂接、以及三道真源码破坏。不证明真机振动与物理息屏，也不承诺跨端跨应用唤醒表现；另有一类本仓反复登记的老形态——看起来没坏但显示不对，本版不能保证这一形态在真机上一出现就被发现
