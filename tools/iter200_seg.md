## 迭代 200 · v4.41.0（2026-03-09）

- 【版本升至 4.41.0（五源同源）：第五期 R5-X8 周期日程、单次例外与多人空档选择】日历侧既有 `isRecurringType` 的实现是 `normalized === 'birthday' || normalized === 'anniversary'` —— **只认生日/纪念日**。于是「每周三晚八点的固定时段」在手机里没有落点；更硬的是「四周安排里改第二周、跳过第三周」这件事：修前只有「全系列一起改」或「整条删掉」两种处置。
- 【契约件新增三类各态】周期四态（没有这一条 / 一次性 / 周期 / 读不到）；单次例外三类（改期 / **跳过** / **取消**）；空档三态（空闲 / 冲突 / **未知**）。
- 【★ 单次例外只动点名那一期（本项核心）】验收原文「四周安排中**改第二周、跳过第三周不改全系列**」—— 例外只作用于点名的那一期，其余各期**逐字不变**（连 key 都不变）。判据 D1 锁住它。
- 【★「跳过」与「取消」分形】前者是「这次不办，**系列仍在**」；后者是「这一次不办且**不再生成**」。压成一格会让用户以为整个安排被取消了。
- 【★★「未知」不算空闲（本项最贵的那一类错读数）】有人这一格**没读到**时判 `unknown`，**不得**读成空闲 —— 否则会把人约到一个已经排满的时间。判据 D2 锁住它。
- 【冲突逐人给理由】`busy` 格点名是谁已有日程（「可解释空档」）。
- 【不认识的周期名与动作名都如实具名】`biweekly` 归「一次性」并说清「不认识」；例外动作名不认识 ⇒ 记 `unknown` 并说清「这一次**没被改动**」。
- 【本版自己抓到的真缺陷（当场修）】`expandOccurrences` 首版把入参先归一成 `{}` 再判 `!raw` —— 那**恒假**（`{}` 是真值），于是 `absent`「没有这一条」那一态成为**死码**。修法：空件判定用**原始入参**。这与本仓「判据要落在真的会到达的路径上」同族。
- 【控制器五口】`recurrenceFace` / `recurrenceWithExceptions` / `isWeeklyMonthly` / `commonSlots` / `recurrenceContractSelfCheck`；本层不算规则、不写存储（计划原文「不接系统日历/闹钟」）。
- 【视图日程详情里的「周期与单次例外」区块】三个动作按钮（改第二期 / 跳过第三期 / 取消第四期），例外**只留在内存预览**、不落盘；样式双侧投递（`calendar.css` 与 `phone.css`）。
- 【与上一版的接续：R5-X5 的「判不了 vs 不知情」分形 + R5-X4 的「不硬算」纪律】计划原文写的是「calendar-app/data/view、原提醒调度与 M5-X8 的周期约定映射」——本版把它真正复用起来，不是另起一套：本件的「未知 vs 空闲」与 R5-X5 的「不知情 vs 判不了」同规（**判不了就不硬算**）；而「不认识的周期名/动作名如实具名」与 R5-X4 的「不认识的动作名归 other 并留原名」同规。R5-X5 那两处形态（唯一出处、本机不推）在本版各有一处同族落点（`commonSlotLine` 唯一出处、`unread` 的人不算空闲）。
