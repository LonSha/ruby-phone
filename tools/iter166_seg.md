## 迭代 166 — v4.07.0 · C 包手机侧首项:R3-O3 群聊节奏与角色表达差异
# 占位:下列条目由 tools/bump_v4070.py 写入 ITERATION_LOG.md 与本版 update-log 条目
- 【本版做的是第三期 C 包手机侧首项:R3-O3 群聊节奏与角色表达差异】计划原文要的是「在现调度上加入最近发言冷却、未回应话题与关系相关度;独立组织每位角色可知上下文、措辞偏好与打断与接话;允许沉默,不为人数上限凑发言」。验收三条:六人群连续 20 轮中 @ 可靠命中且不每轮固定前三人;同一往事不被六人复述;角色不知道的内容不进入其请求。
- 【修前实测的缺口(不是推演)】apps/wechat/group-scheduler.js 的 scheduleSpeakers 做的是把模型给的名字映射回成员、去重保序、封顶人数 —— 它**完全不看历史**:没有谁刚说过话,没有这个话题谁还没接,与关系无关。于是验收里那三条一处都不成立。缺的不是数据(群成员与消息与维系度都在),缺的是把读数落成「这一轮该给谁多少台面」的那一层。
- 【新内核 · config/group-pace.js(纯函数,只 import num-gate 一处)】三份读数加一条裁定:最近发言冷却(cooledDown)、未回应话题(topicUrgency)、关系相关度(relationFit)、允许沉默(silence);另有六词归因 GROUP_PACE_REASONS、四档私密度 GROUP_PACE_PRIVACY 与四词私密度归因、七级刻度表 GROUP_PACE_TIERS 与下标读法 tierIndexOf、七项上限 GROUP_PACE_LIMITS、历史归一 normalizeGroupHistory、一行读数 groupPaceLine、自检 groupPaceSelfCheck。所有出口都是纯函数,不改入参(判据钉住);代码本体里没有 window 与 document 与 localStorage 与 fetch 与 eval 与 new Function 与 setTimeout 与 dispatchEvent 与 require。
- 【四条裁定口径,每条都对应一个具体错法】一 @ 是**硬命中**不进权重分配:让人参与加权排序会造出「点了 A 而权重最高的是 B」这种最坏的错误,故点名者直接进台面首位且不受冷却与上限裁掉;二 **冷却不等于禁言**:冷却期里若全场没人可发,宁可少说甚至沉默,也不把刚说过话的人再拉回来 ——「每轮固定前三人」正是靠这一条断的;三 **关系判据是下限而不是排序键**:私密话题只要求 tier 不低于某级,若把人按关系从亲到疏排一遍再切前几个,会造出「永远只有最亲的几个说话」的新毛病;四 **三态互不同形**:readable 与 thin 与 absent 各占一格,把 thin 当成「那就谁都能说」是最坏的处置 —— 它把「不知道」写成了「都行」。
- 【本版自己抓到的一处真缺陷(合并前已修):空历史被当成了读不到】首版把「历史读不到」与「历史为空」混成同一个分支,于是刚建的群永远报 thin、永远排不出人 —— 二十轮模拟里只有 @ 那一次出了一个名字。修法:读不到(不是数组或没给)报 no-recent-face 且不出人;**读到了一份空数组**按初始轮处理,不做冷却罚分也不做话题加减,如实可判。这一步必须显式写出,否则空历史会静默落进「所有人都被冷却」的分支,把一个新群判成「全场刚说过话」—— 那是把「不知道」写成了「都刚说过」。判据 B1 与负控制 D1 把这条两向钉住。
- 【本版自己抓到的第二处真缺陷:`window` 被用作参数名】内核里 isCooled 的窗口参数原叫 window,它**遮蔽了浏览器里的全局 window**,而「内核代码里不得出现 window」是本仓纯函数面的硬边界 —— 判据 A5 正是那么针的。改名 win 并附一句为什么要刻意避开这个名字。
- 【接线三层】数据层 apps/wechat/wechat-data.js 新增 groupPaceReadings(真读真源:消息面取最近若干条带发言者标识的记录、关系刻度从成员行自带 tier 读;读不到一律保持 null 而**不用空数组顶替**)与 planGroupPace(唯一出口,永不抛,异常时如实报 thrown 而不假装没人说话);生成侧 apps/wechat/chat-view.js 在群聊系统提示词里进一段节奏读数,取数失败就不进(宁可没有这段也不附一句假的),且私密度只从会话已存字段读、**不从正文推断**(推出来的私密度会把不该说的话放给不该说的人);诊断侧 apps/diagnose 新增群聊节奏卡(内核自检 + 六词归因 + 四档私密度带归因词 + 上限读数 + 空历史与读不到两种情形的对照)与一行读数出口 groupPaceFaceText。
- 【二十轮模拟实测】六人群连续二十轮,一人一次 @:出场分布六人各十次、极差为零,**不固定前三人**;@ 那一次被点名者排在台面首位;把同一件往事交给已接过的三人之后,台面首选换成另外三人。「接过话题者让位」这一条在判据里用了**冷却不参与**的干净历史(让位只能由话题降权解释),否则让位会被冷却一并解释掉、破坏也看不出差别 —— 那正是本套件负控制 D2 第一版抓出来的「破坏不可观测」。
