## 迭代 184 — v4.25.0 · 第四期 R4-X3 可阅读、可编辑的故事年鉴
# 占位：下列条目由 tools/bump_v4250.py 写入 ITERATION_LOG.md 与本版 update-log 条目
- 【本版做的是第四期拓展项第三件:R4-X3 可阅读、可编辑的故事年鉴】计划原文要的是「从真实会话生成三章年鉴,每条关键事件可回源;改标题不改事实;正文被编辑后相关段提示需重建;导出后离线可读,未读章节秘密不出现在封面/目录摘要」,并明写不做:不新增摘要引擎、不以关键词去八股计数声称文风优秀、不自动外网发布。落点原文点名「reading + creationdesk,接 M4-O6/O9、M4-X2;文稿是草稿,事实修改交上游;复用 R4-O5/O9 保存与迁移。提供作者版/按当前进度阅读版」。
- 【修前实测的缺口(读码可复算,不是推演)】上游 story-annual.js(M3-X7 四要素章册 + M4-X2 成稿面)的八个 storyAnnual 出口在宿主的 LonShaMemory 上早已齐全,而手机侧 grep storyAnnual 在 apps 与 config 下**零命中** —— 建好了没人用(同族第十五例)。后果三件,都不是报错:一是读者回看一章只能一页页翻正文,没有「按卷章读发生什么」的入口;二是年鉴里那些**回源凭证**(ch1#event@2 这种逐条指回楼层的 ref)在手机侧根本不存在,于是「这一条出自哪一楼」无从核对;三是「按进度还不能看的章」与「空的章」在版面上**同形**,读到第几章与能看到什么无关。
- 【新契约件 · config/story-annual-contract.js(纯函数,零 DOM 零存储零联网零时钟)】七格面状态(插件不在场 / 插件在但没这一面 / 本机读不出 / **章面未判** / 被进度挡住 / 确实没有章 / 有章)、三态派发相(读写都在 / 只能读不能改 / 没有建章口)、两版(作者全知 / 按进度阅读)、四上限(章数 / 单章四要素 / 转文本截断 / 封面字数),以及一整套纯判定:章册归一、两版搬运、编辑草稿搬运、过期判定、成稿读数、按进度裁阅读版、封面、目录、导出文本、一行读数,和**真跑判据**的自检(不是数常量)。
- 【跨仓分工:去剧透一律走上游,手机只做上游没有的两件事】上游持有事实、来源、时态与确认写入;手机持有交互、文稿与本地阅读。故去剧透**一律经上游 storyAnnualForPlayer**(它的 gate 由宿主装配),手机**不自己判秘密**;手机只做两件上游没有的事 —— 一是按**本机阅读进度**裁阅读版(读到第几章,其后的章只留占位),二是封面与目录摘要不得含未读章的痕迹(验收原文点名的最后一格)。默认给**阅读版**,作者全知版需显式切换 —— 把作者面当默认就是直接剧透。
- 【未判 ≠ 没有:章面未判单独占一格】上游把「没拿到卷章结构」写在 chaptersChecked:false 里,它与「确实没有章」是两件事。修前写法把它读成 empty,用户看到的是「这一会话没有故事」,而其实只是没读到。本版让它单独占一格,读数逐字写明「章面未判(未拿到卷章结构,不猜章界)—— 不是「没有章节」」。
- 【本版自己抓到的第一处缺陷:传裸章数组被读成空版,导出成了空稿】封面、目录、导出三件原先只认版对象,而调用方把裁章结果的 chapters 数组直接递进来是**极自然**的写法 —— 数组也是 object,于是读出的 chapters 是 undefined,封面报「已读 0 章」、导出只剩一句「离线可读」的**空文件**:一个字符都不报错,用户拿到的是空稿。本版把形状归一收成一处(只认裸章数组与版对象两种),并把这条写进自检与判据。这正是本仓治过多次的同族病(形状不对 ⇒ 静默空结果)在本面再治一次。
- 【本版自己抓到的第二处缺陷:判不了被读成全都新鲜】过期判定在上游没拿到旧章册或新载荷时,stale 是 0 **只因为没比**,而它把「没拿到」写在 why 里。修前写法照报「没有段过期(原稿未变)」—— 用户会把「判不了」读成「原稿没变」。本版给过期判定加一格 judged:判不了时不许与「真比过且没变」同形,界面照实说「过期判定读不到(不假装成「全都新鲜」)」。
- 【回源凭证为什么原样搬运不自己重拼】验收第一条是「每条关键事件可回源」。上游按章号与楼层算出 evidenceRef,本件**只搬不重拼**:自造 id 的后果是回源跳到一个不存在的位置,且不报错。故导出文本里每条都带括注回源凭证,视图里每条也标出来 —— 离线文件与屏幕都能说清「这一条出自哪一楼」。
- 【按当前进度裁阅读版:未读章的标题与摘要一个都不上明面】进度未给(读不出或没记过)时**不裁** —— 宁可言多,不静默藏掉用户自己的文稿。读到第 k 章 ⇒ 章号大于 k 的章:标题、摘要、卷标、四要素、证据一律清空,只留章号与 locked 标记;封面只统计已读章的四要素;目录未读行固定为「第 N 章(未读)」不出现标题;导出里未读章写「未读 —— 内容未展开(读到这一章后再看)」。四项同一口径,一处都不漏。
- 【App 侧接线】新增十四口:年鉴面探测与派发相、建章册、章册读数、两版、两版读数、编辑草稿、过期判定、成稿、按进度裁阅读版、封面、目录、导出文本、本机进度读与写、自检真消费点。阅读进度键 ruby_reading_annual_readthrough 逐字常量定义在 App 顶部(keys 门抽取器认这一形态),0 是合法值(章号从 1 起,0 表示还没读到任何一章),读不出返回空而不是编一个 0。
- 【视图只排版,判定全走内核】新增故事年鉴面:章册读数、重读章册、导出可读文件、阅读版与作者版切换、进度输入与记进度、逐章四要素排版(每条带回源凭证)、改章题(事实位被拒原样显示)、过期核对读数。视图不直呼契约件、不自持面状态字面量、不自己算一份封面或目录。默认给阅读版,切版按钮与进度输入都有事件落点。
- 【创作台侧只取材,不改事实】creationdesk 只消费两件:年鉴面读数(建章册一行 + 派发相),以及把某一版年鉴导出文本取来当**草稿素材**。取稿**不写任何键**、不发布、不写剧情事实 —— 这是计划「文稿是草稿,事实修改交上游」的落地形态。创作台视图只多一行读数,不新建 App、不新建入口。
- 【换会话作废本屏现场】上一会话的章册缓存、选中的版、正在编的章题草稿、过期读数全指着上一会话的故事;只重读书架不清现场,新会话首屏就会画出上一场的读数(不报错,只是错数据)。故与同族功能同规:换会话当场作废现场,并回默认阅读版,不落存储(草稿态不是数据)。
- 【交棒改写】本版把 R4-X3 的验收从「建好了八个上游出口」交棒到「按卷章读得到、每条回得了源、改题不改事实、正文改过提示需重建、导出离线可读且未读章的秘密不出现在封面与目录」:判据写成真跑形(真 App 走完整旅程:建章册、记进度、裁阅读版、导出、改章题、过期核对)与下限形(六格互不同形、三态派发、破坏真源码后同款判据必转红),下一版抬版无需二次改写。
- 【运行时验证边界(如实声明)】本版留下的边界形态，正是本仓反复遇到的那一类：看起来没坏但显示不对 —— 章面未判被读成没有章、判不了被读成全都新鲜、裸章数组被读成空版，三处都是「一个字符都不报错、用户拿到的是错读数」。故本版把三处各自的独立格写进自检与判据，而不是靠界面文案圆过去。本版在无头环境验证的是:章册归一与四态读数、章数上限、回源凭证与楼层原样搬运、两版不合流(去剧透未成立时玩家版给 null 且说清不回退作者版)、事实位逐条拒收、过期逐条具名与整章不在、判不了不与全都新鲜同形、成稿只报结构成稿、按进度裁章四情形、封面与目录与导出的未读痕迹、版形状两种、真 App 走完整旅程(含进度键读回与非法输入不抹掉已记进度)、视图默认阅读版与导出文本、创作台取稿不落盘、换会话作废现场、十项负控制(每条配原版必真的反向对照)。本版不能保证的是:真机浏览器上的实际滚动与长章渲染手感,以及真人大小的整本书上生成年鉴的耗时 —— 后者需要真数据与真设备在场,未实测故不标效果已验。
- 【定向判据与版本锚】新套件 tests/system-v4250.test.mjs 三十六例全绿(口径四、内核行为十、接线十、负控制十一含正向对照、版本锚一);抬版按仓内唯一范式 tools/bump_v4250.py 对齐 tools/bump_v4240.py。
- 【本版顺手收口的跨版遗留(经 4.24.0 基线复现,不是本版引入)】抬版前跑完整门禁实测 15 例红,把六源还原到 4.24.0 后同批重跑,15 例全数复现 —— 即它们自 v4.13.0~v4.24.0 累计遗留,与本版改动无因果(这条复现实验本身就是本版最该留档的一步:不还原就分不清「本版引入」与「历史噪声」,而后者会让判据失去可信度)。逐条收口七类:①v269 前缀型登记纪律硬锁「恰好一条」,而登记表自 v4.15.0 起已按需长出 view_state_ 与 edit_buffer_ 两条(各带版本出处),判据改为「非空 + 含已知那条 + 每条带版本出处标注(vX.Y.0 形态)」;②v3170 搜索闭包字节上限 400KB 是当版量级,而 v4.15.0 起 view-state 进闭包实测 405367,上限抬到 460KB 并保留量级哨兵语义(五条正文库 import 判据一字不动);③边界文档当版实测数字停在 814 文件与 461 文件 809 条,而真跑已是 824 与 466 文件 821 条,按真跑读数落笔并补当版复校行;④v3204 上游仓自 v3.328.0 前进到 v3.347.0,冻读取按 R9 纪律走 --refresh 并写明理由,不沿用旧冻读取;⑤v3730 状态台账停在 v4.20.0 与 263 测试文件,用生成器重跑(台账与磁盘漂移即红);⑥v4120 破坏锚点因 v4.19.0 起撤销路径也调同一函数而不再唯一,锚点重取到删书路径那一处;⑦v4220 负控制镜像未随 memory-app 的真依赖更新(v4.23.0 起 import 阅读侧 reading-data),镜像补 apps/reading。七类同一教训:判据的输入面必须跟着产品面走 —— 产品面动而判据输入面不动,判据就从看守退化成噪声,后来者看到红灯的第一反应会变成「这条判据老是这样」。
