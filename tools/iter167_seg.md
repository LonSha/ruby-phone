- 【本版做的是第三期 C 包手机侧第三项:R3-X5 人物关系回忆册】计划原文要的是「按双方身份建立共同经历册:初识、争执、和解、礼物、约定等由真实事件聚合;允许选素材编纪念页,附出处与关系转折而非只报好感数」。验收四条:切换人物对能看到各自往事;同名不混;撤回事件不再生成纪念页;共同经历与单方听说分开。
- 【修前实测的缺口(不是推演)】contact-insight.js 只答谁最近聊过谁沉了多久;relation-tier.js 只答这对人现在算哪一级;timeweaver 能织信与收藏。三者合起来仍答不了计划点名的那一问:这对人之间发生过什么、是怎么变成现在这样的。上游在 v3.323.0(M3-X2)交付了 relationHistory 面 —— 它答的正是这一问,而本仓零消费(未消费理由台账里写的就是 R3-X5 尚未开工故 relationHistory 没接)。
- 【新内核 · config/relation-album-contract.js(纯函数,只 import num-gate 一处)】三件事:一是双方身份键(优先 id,只有名字时退化并按 byName 如实计数);二是事件按在场名单分三份(共同 / 单方 / 听说)**不得合并**;三是转折直接从上游 relationHistory 读、不在本仓重算(重算就是第二套关系轨迹口径)。另有五态 RELATION_ALBUM_STATES 与五词归因、七类纪念页素材 ALBUM_KINDS(初识 / 争执 / 和解 / 礼物 / 约定 / 同行 / 其他)、三份归属的人读字样、三项上限、一行读数与自检。
- 【本版治的三条口径】一 **「读不到在场名单」不得抬成共同经历**:没有证据说人在场,就按听说处置 —— 把「不知道」写成「我们一起经历过」是把没发生过的事写进两人的回忆。二 **撤回只认 revoked 一个字段**:产品里若认两份写法,就是两份口径(本仓治过的形态);判据里也不用第二个字段名去「多认一份」。三 **无出处不进册**:事件必须带楼层或事件 id,否则如实计 dropped —— 无出处的「共同回忆」与编造无异。
- 【本版接上了上游一面,台账自动收口】登记行 lonsha.relationAlbum(upstreamFace=relationHistory / declaredConsumer=readRelationHistory / declaredFloor=1 / since 3.323.0)、桥契约面标签逐字对齐、未消费理由台账移除该面(它不再是零消费)、滞后台账新增一条 consumer-none(上游账面还写 none@0 而本仓真码已接上)。第十一道门实测绿并报出「已解释 1 条」,R11 台账**首次真实生效**。上游一提交,该条会因「分歧已消失」而转红 —— 那正是双向闭合的用意。
