## 迭代 176 — v4.17.0 · 第四期 R4-O5 未点保存的编辑内容也能恢复
# 占位:下列条目由 tools/bump_v4170.py 写入 ITERATION_LOG.md 与本版 update-log 条目
- 【本版做的是第四期优化项第五件:R4-O5 未点保存的编辑内容也能恢复】计划原文要的是「打了一半的文案、流程参数不因离开页面或刷新丢失;区分正在编辑与已保存与已发布」,验收原文四条:输入但不点保存、离开与重开与刷新均可恢复;A 到 B 再回 A 不串稿;保存失败显示未保存并保留文字;恢复旧缓冲需选择、不自动覆盖新版本。
- 【修前实测的缺口(读码可复算,不是推演)】apps/creationdesk/creationdesk-app.js 的 setDraftNote 只更新 _draftNote,而 input 监听调的就是它;保存走**另一个方法** draftAct;切聊会清实例字段。config/workflow-designer.js 的编辑草稿同样是实例态。仓库里已有的草稿本(creation-multi-draft 与 workflow 模板)只保证**已保存的版本** —— 它回答「我上次存了什么」,而用户问的是「我刚打的那半句话还在吗」。两件事,必须分开一套账。
- 【新契约件 · config/edit-buffer.js(纯函数,零 DOM 零存储零联网零时钟)】只做四件事:把半成品收成恒定形状(文本/光标/目标/版本/已发布标记);判四态;产恢复**选项**(不自动覆盖);处置保存回执。**时钟由参数给而不用 Date.now()** —— 纯函数自己看时间会让「同一输入两次调用得同一结果」这条性质失效,而判据正靠它。
- 【四态互不同形】editing 有未保存的编辑 / saved 与已保存一致 / published **已发布,不许被编辑缓冲反向覆盖** / empty 没在编辑(**不是「丢了」**)。压平任意两态都会造出处置相反的处境长得一样。
- 【判据顺序本身是口径】一 **已发布优先**(内容已经出去了,不管缓冲里是什么都不许顶);二 缓冲空 ⇒ empty;三 文本与已保存一致 ⇒ saved;四 其余 ⇒ editing(用户问的那一态)。
- 【三条红线写在纯函数里,不靠调用方记得】一 已发布 ⇒ 只给 keep-editing 一个选项,且具名说明为什么(published-not-overwritable);二 缓冲为空 ⇒ 只给 use-saved,不假装能恢复;三 **默认什么都不动**(keep-editing)—— 验收原文要求「恢复旧缓冲需选择,不自动覆盖」。
- 【保存回执:失败必须保留文字】**成功**才清缓冲;**失败**一字不丢并如实报原因;**回执读不出**也保留文字(宁可留着)。这三种情形互不同形(saved / unsaved / unknown)。这条直对验收原文的「保存失败显示未保存并保留文字」。
- 【上限与既有同口径】文本上限 2000,与 config/creation-multi-draft.js 的 CMD_LIMITS.textMax 逐字同值(不自写一个数);超长**如实标记 truncated** 而不静默截断(静默截断会让用户以为打完了)。
- 【会话键 edit_buffer_ 登记为前缀型】config/storage.js 的 CHAT_DATA_PATTERNS 加 ^edit_ 一条;keys 门登记表加 edit_buffer_*(与既有 ruby_reading_progress_* 与 view_state_* 同规)。键名以**字面量**出现在产品面上(否则 K3 会判幽灵放行条 —— 这一条在 R4-O3 已被实测教训过)。
- 【创作台接成首个真实消费点】五口:saveEditBuffer(节流 400ms,空缓冲**不写盘**——写一份空的等于把已存的顶掉)/ loadEditBuffer(只读不判)/ decideRecovery(只判不改)/ applyRecovery(显式传 choice,**不给默认值**,兜默认值就是自动覆盖)/ settleSave(成功才清)。既有 draftAct 与咽喉一字未动。
- 【本版自己抓到的缺陷形态两处,都在负控制判据自身上(合并前逐条修掉,留痕)】一 D1 首版检查「EB_STATES.PUBLISHED 这个词还在不在」,而破坏后的副本里 `if (false) return EB_STATES.PUBLISHED;` 仍含那个词 ⇒ 判据永远看不见破坏(负控制假绿);改成检查**那一行的真形态**(`=== true ||` 这个签名)。二 D4 同型(`why: 'empty-not-written'` 残留在破坏副本里);同样改成检查 `!pack.hasText` 这个否定签名。两处都是「判据检错了对象」,与 R4-O4 的 B6 同族。
- 【交棒改写】本版把 R4-O5 的验收从「缓冲有没有落盘」交棒到「四态可分辨 + 三条红线在纯函数里 + 保存失败保留文字」那条路;相关各条判据一律写成下限形与真跑形(行为面直接调模块),下一版抬版无需二次改写。
- 【运行时验证边界(如实声明)】本版在无头环境验证的是:四态互不同形与四句文案两两不同、归一不猜(空白等于没编辑/超长如实标记/0 是合法光标位)、四态逐条、恢复选项三条红线(含默认什么都不动与已发布不可覆盖)、采纳选择的纯性与未登记词不猜、保存回执三态。**未做**真机上的「输入但不点保存→离开→重开→刷新」四条旅程与「A 到 B 再回 A 不串稿」—— 那需要在真机走一遍;自动化只保证结构正确与判定正确,不保证真机上的输入焦点与重绘行为。另:本版只接了创作台一个入口;workflow-designer 的编辑草稿属同一范式的后续增量,如实留白。
