## 迭代 168 — v4.09.0 · C 包手机侧第二项:R3-X3 约会与日程的可玩执行流程
# 占位:下列条目由 tools/bump_v4090.py 写入 ITERATION_LOG.md 与本版 update-log 条目
- 【本版做的是第三期 C 包手机侧第二项:R3-X3 约会与日程的可玩执行流程】计划原文要的是「把一条约定扩为准备到出发到到场到互动到结束的可选步骤;可邀请角色、关联地点与待办,结束生成回顾草稿;使用剧情时钟而非现实闹钟」。验收四条:能从聊天邀请推进一次约会;改期同步待办;没有正文或用户确认不自动判到场或履约;回档后未来步骤不继续触发。
- 【修前实测的缺口(不是推演)】commitment-flow.js 已有五态与事件键幂等,schedule-bridge 与行动中心已有提醒,但一条约定在用户侧仍只是一个**状态**:没有准备与出发与到场与互动与结束这五步,没有邀请与地点与待办三个挂点,结束之后没有回顾草稿,改期不同步待办。更要紧的是**没有任何一处拦住「自动到场」**—— 约定一到日期任何一侧都可以自行把它当成发生了,而正文里那场约会根本没写。
- 【新内核 · config/date-playbook.js(纯函数,只 import num-gate 一处)】五步台面(准备与出发与到场与互动与结束)与五态(做过与可做与等着与需人证与已作废)与八字归因与四项上限与自检;另有推进校验出口(校验准入但**不代替正文或用户**做那一步)。代码本体里没有 window 与 document 与 localStorage 与 eval 与 new Function 与 setTimeout 与 dispatchEvent,且**不读现实时间**(没有 Date.now 也没有 new Date)。
- 【四条裁定口径,每条都对应一个具体错法】一 **到场必须等人证**:这一步是整条流程里唯一不得自行判定的一步 —— 到点了就当到了是把时间当成了事实,故它永远落在「需人证」态,推进时必须带事件键或用户确认二者之一;二 **没互动就不给回顾草稿**:回顾是「发生过的互动」的产物,不是流程走完的副产品;三 **回档即作废**:每一步带出处楼层,楼层在当前之后的步骤一律标作废且**不执行**,而楼层读不到(null)不参与淘汰——无出处的楼层不算证据;四 **用剧情时钟不用现实闹钟**:回档判定只读调用方喂进来的剧情楼层,内核内部不读现实时间(用现实时间判回档会把「玩家回到旧楼层」误读成「约会已过时」)。
- 【计划原文说的是「可选步骤」,这让一处期望值需要重新理解】本版判据首版把「已确认的约定只能做第一步」写成断言,实测发现准备与出发都可做 —— 而那是**对的**:一次约会可以就地出发,不必先做一整套准备。故判据改成「准备与出发都可做,真正必须按序的是后三步(到场等人证、互动在到场之后、结束在互动之后),而到场永远是需人证而非可做」。改的是判据口径而不是实现 —— 实现从一开始就与计划原文一致。
- 【本版自己抓到的两处仓库级纪律(都不是新缺陷,是既有门禁正确抓到」本层新写的东西」)】一 日历层的剧情楼层取数就地写了弱口径写法(Number.isFinite 包一层),被第十道门 W1 当场抓住并经 config/num-gate.js 归门;二 datePlaybookSelfCheck 建好却没人用(本仓记过的「建好了却没人用」),故给它接一个真消费点(诊断卡)而不是加白名单。
- 【接线三层】日历层 apps/calendar/calendar-app.js 新增两个出口:commitmentPlaybook(按约定 id 算五步台面;约定从本层已有的账读、步骤读数从约定自带的 steps 字段读、楼层从剧情时钟读且读不到传 null)与 advanceCommitmentStep(校验准入但把写留给上层;到场步骤无人证必须具名拒);诊断侧新增约会可玩流程卡(内核自检 + 五步与人读字样 + 八字归因逐条 + 四项上限 + 一个样本跑三遍分别验证当场能做什么与到场等人证与回档作废)与一行读数出口。
