## 迭代 174 — v4.15.0 · 第四期 R4-O3 跨 App 返回恢复实际页面状态
# 占位:下列条目由 tools/bump_v4150.py 写入 ITERATION_LOG.md 与本版 update-log 条目
- 【本版做的是第四期优化项第三件:R4-O3 跨 App 返回恢复实际页面状态】计划原文要的是「搜索到详情到聊天再到返回后继续原任务;本轮做真正的状态捕获和恢复,而不是再增加恢复成功读数」,并明写不做:不造第二路由、不要求所有低频 App 一次重构。
- 【修前实测的缺口在两头,都不是推演】一 **返回键只回桌面**:phone/phone-shell.js 的 bindBackButton click 分支写着「if (this.isAtHomeScreen()) return; this.goHome();」—— 从搜索跳进某个 App 再按返回,用户被**直接丢回桌面**;而右滑那条路(SWIPE_BACK)是逐层退。两条路给出两个语义,而用户看到的是**同一个「返回」**。二 **状态没人捕获**:apps/taskentry/taskentry-app.js 的 markLeft 注释逐字写着「本件不做恢复动作」,全仓 restorePlan 的唯一消费点是「给恢复读数」—— 读数是「恢复了没有」,不是「恢复」。
- 【新契约件 · config/view-state.js(纯函数)】只做两件事:把任意来源的状态收成恒定四格(页签 / 查询 / 锚点 / 滚动),以及在恢复前问一句「这份快照还是这个会话的吗」。不碰 DOM、不写存储、不建路由——页面栈早就存在,本项**不是**「再建一个返回栈」。
- 【五态互不同形】ok 有快照且会话一致 / no-snapshot 从来没捕获过(第一次打开这个 App,不是「丢了」) / empty 捕获过但四格全空(用户没动过,也不是「丢了」) / wrong-session 快照属于**另一个会话**(拒绝恢复,不是「没有快照」) / unreadable 形态读不出(畸形 JSON 或非对象,与「没捕获过」分开)。压平任意两态都会造出处置相反的处境长得一样。
- 【会话围栏为什么必须在这里】键前缀(^view_)保证的是**存储位置**按会话隔开;它**不**保证「我手上这份快照是给谁的」。用户在 A 会话捕获了一份快照、还没写盘就切到 B —— 此时内存里那份是 A 的。故快照里带 appId 与 chatId 两格身份并逐次比对,不一致即拒绝恢复。空串对空串算一致(调用方拿不到身份时,那是唯一不产生错贴的选择;物理位置已由键前缀隔开)。
- 【四格不猜】字符串 trim(空白查询等于没查询);scroll 只认有限数且**0 是合法滚动位**(不得被读成「没给」)。判据同时守两向:怪值必须如实 null,0 与 '320' 必须如实出数。
- 【宿主:返回键改逐层退,且**包装既有真源不重写**】新增 phone/phone-shell.js 的 backOneLayer():它只调既有的 _dispatchSwipeBackWithFallback(压栈/弹栈 + 250/550ms 兜底全在那里),**不自己动 viewHistory**。返回键 click 改成「先逐层退;退不动(已在第二层 / 无当前层)才回桌面」—— 回桌面仍是最后一档,不取消。归因覆盖四种情形:at-home / last-layer / no-current-layer / dispatch-threw。
- 【搜索接成首个真实消费点】apps/search 新增 captureState 与 restoreState 两口(只转交纯函数 + 读写那一个会话键),视图 render() **先读快照再画**(画完再贴会先闪一下空面),并把页签与查询词贴回;输入与来源切换后**捕获**一次(节流 400ms,且**不用定时器** —— view 不持未登记定时器,改用「上次写的时刻」做时间闸门)。
- 【换会话必须丢内存里那份】onChatChanged 把视图的 _restored 置 null。理由与其它会话态同源:键前缀只管存储位置,不管「手上这份是给谁的」。
- 【新会话键 view_state_ 登记为前缀型】config/storage.js 的 CHAT_DATA_PATTERNS 加 ^view_ 一条;keys 门登记表加 view_state_*(与既有的 ruby_reading_progress_* 同规,一条覆盖全部 view_state_<appId>)。
- 【本版自己抓到的缺陷形态三处,全在判据与锚点上(合并前逐条修掉,留痕)】一 C4 首版按 'setContent' 定位,命中的是守卫行 `if (!shell?.setContent) return;`(它排在 restoreState 之前)⇒ 判据假红;改成取**调用点** `shell.setContent(`。二 D4 的破坏锚点带着行尾块注释,而判据用的是 stripComments 后的代码 ⇒ 锚点零命中,「锚点必须恰中一次」当场抛。三 补丁脚本连跑两次导致 import 与常量**重复插入**(syntax 门报 Identifier already declared)—— 教训是补丁要幂等或一次性,重复执行必须能被锚点纪律拦住。
- 【交棒改写】本版把 R4-O3 的验收从「返回后原查询还在不在」交棒到「返回语义唯一(与右滑同一条路)+ 恢复判定五态可分辨」那条路;相关各条判据一律写成下限形与真跑形,下一版抬版无需二次改写。
- 【运行时验证边界(如实声明)】本版在无头环境验证的是:五态互不同形与五句文案两两不同、四格归一不猜(含 0 是合法滚动位)、会话围栏三态(一致 / 两向不符)、捕获与恢复五态逐条、返回键逐层退优先且包装而非重写、搜索 App 与视图两侧真接线、键登记前缀型与产品面字面量。**未做**真机浏览器上的「四条旅程分别用按钮、滑动、浏览器返回往返」与「滚动恢复到同条目」—— 那需要在真机走一遍;自动化门禁只保证结构正确与接线完整,不保证真机上的视觉与滚动行为。另:本版只接了 search 一个入口(计划原文要求 search/memory/creationdesk/reading 四个高频入口),其余三个入口的接线属同一范式的后续增量,如实留白而不以「一个入口通了」冒充四个都通。
