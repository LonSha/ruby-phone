## 迭代 139 — v3.82.0 · B 清单八件（写作面：氛围池 / 关系七级 / 判定归脚本 / 平行线 / 状态字段 / 二级摘要 / 只记事实 / 人工纠错）

- **【定位 · 附件 B 清单八笔的落地口】** 附件给出的 B 清单（B1–B8）原本是为**角色卡侧**提的写法纪律。本版把它们落成**手机侧的八份纯函数真源 + 一个唯一消费口**：写作面上「写正文要用到的那几件事」此前在本仓没有任何可点的真源，副模型只能从训练里最顺手的那批意象里挑，而「她心里五味杂陈」这类**叙述语言**无处可拦。
- **【B1 新模块 · config/ambience-pool.js】** 氛围池：十类（天候 / 光 / 声 / 气味 / 触感 / 场所 / 时令 / 城市 / 人群 / 物件）× 每类六条 = 六十条，每条必带「用在」（什么场合该用）与「写法」（白描写法的示范）。关键在后者：只给「雨天」两个字，模型还是会写「细雨如丝」；给它一句示范的白描，它才有得抄。取用面给 pickAmbience（筛 + 有界）与 ambienceSpan（本场去重，跨场可复用），三态为 picked / filtered / exhausted。**刻意不做随机撒**：环境不是贴纸，随机撒的后果是「咖啡馆的雨」与「主角在医院」同框。
- **【B2 新模块 · config/relation-tier.js】** 关系七级（陌生人 / 点头之交 / 熟人 / 朋友 / 挚友 / 亲密 / 羁绊）+ 好感底色（warm / neutral / cold）+ 信任落点。**主判据是承压兑现率，不是条数**：一个人可以发两千条消息而从不接住你的难处 —— 把「聊得多」当成「关系好」是最容易被做出来的错分类（读数好看、语义全错）。信任落点**只在受检验的那一次**才允许改写（四种检验：求过助 / 托付过秘密 / 起过冲突 / 缺席过约定），且必须有读数；没有读数就换落点等于把「我觉得」写成了「发生过」。
- **【B3+B4 新模块 · config/scene-rules.js】** 判定归脚本：把判定从模型手里拿走的理由不是「模型算不准」，而是**把成败交给模型得到的不是随机而是倾向**（骰子替叙事服务 ⇒ 玩家换个做法也提高不了胜率）。故切成两半：模型只写「难度 + 四个落点」，脚本摇骰并裁决；**四个落点缺一即拒判**（只写「成功时会怎样」的行文，一旦摇出失败就得现编）。平行线（不在场的那条线）三条约定：照样记状态 / 本场人不知道 / 将来可以撞上；被塞进本场注入面必须**点名**（leaks）—— 那是错，不是一种状态。
- **【B5+B7 新模块 · config/state-fields.js】** 状态五格：doing（此刻在做）/ want（想要）/ afraid（怕）/ will（接下来会做）/ unsaid（没说出口）。前四个是驱动力，第五个是**成品**：台词是给对方的，unsaid 是给对方**听不到的**。每格三态：set / empty / absent —— 把 absent 报成 empty，调用方会以为「模型想过这一格、结论是空」，而它其实**没被要求过**。拼表规则（B7）：只许出现可核事实（who / when / where / what / said / did / amount / object / promise），推断键出现在表里即判红；混流行保留事实部分并如实报非事实键。
- **【B6 新模块 · config/archive-digest.js】** 二级摘要：一级「原文 → 档案」只许记事实，二级「档案 → 正文」只许读档案、不得再看原文。修前是**单级**通道（原料整段丢给副模型直接出成品），两个病：① 副模型会把原文的**叙述语言**一起搬进成品（生成者与改写者没有分工，模型就自己扮演叙述者）；② 原料一长产出就漂（同一遍里既要压缩又要重写，两件事互相抢注意力）。三态：two-stage / flattened（**如实降级**并说清第二级拿到的是原文）/ refused。
- **【B8 新模块 · config/memory-correction.js】** 人工纠错四通道：重算 / 单独重算 / 删掉 / 加上。四者的差别不是「程度」而是**方向** —— 重算与单独重算改的是**抽取**，删掉与加上改的是**内容**；并成一个「编辑」，用户就再也无法表达「这条不该存在」与「这条存在但抽错了」的区别，而处置方式恰恰相反。人工补的条目带 source: human 标记（**永远不许**被自动抽取覆盖），且不许被 remove 通道悄悄带走。
- **【唯一消费口 · config/craft-cards.js】** 八份纯函数若没有消费点，就是本仓被 dead-export 门点名过六次的「内核建好了、导出挂出来了、产品端零消费」。本文件把八笔收成八张卡（每张给一行活读数），由**诊断中心**统一读出去 —— 与投影面 / 注入面 / 证据面同一族：本仓一切「上游读数」的可见出口就是那里。它**不替调用方使用**这些能力（不替它挑氛围、不替它摇骰、不替它纠错），只回答「这八件事各自的真源在不在、读数是什么」。
- **【诊断侧接线】** apps/diagnose/diagnose-data.js 新增 craftFace（八张卡 + 自检 + 一行总读数）与 craftFaceText（三态文案：面缺席说「读不到」、有问题逐条点名）；apps/diagnose/diagnose-view.js 新增 _craftHtml 与一张诊断卡。取数一律走全仓唯一口径 numOrNull。
- **【新增套件 · tests/system-v3820.test.mjs（22 用例）】** A 结构面 3 条（八份真源与导出面 / 唯一消费口与诊断内核真读它 / 三态纪律贯穿八笔）、B 行为面 7 条（八笔各自的真功能断言）、C 接线面 1 条（**真跑 collectDiagnose**：craftFace 与八张卡必须真被取到，缺席态与就绪态不许同形）、D 负控制 10 条（每份真源一条：三态塌格 / 主判据错位 / 未经检验即改写 / 拒判退化成纵容 / 平行线泄漏 / 推断行留下 / 降级伪装成两级 / noop 报成 applied / 消费口塌一张）、E 版本锚 1 条（下限形）。
- **【本版自己抓到的缺陷（三处，都由真门与新套件当场报出）】** ① 写作面取数初版写成 Number.isFinite(Number(x))，被 weak-coercion 门（W1）当场点名 —— 那不是「更宽松」而是把 null / 空串 / 空数组全读成 0 的弱口径形态，已改走全仓唯一实现 numOrNull；② B7 判据夹具把 mood 当「非事实键」写，而它本就属**推断键**（会整行剔除）⇒ 夹具与真口径不同形，已改用真正的非事实键并补记「混流行保留事实部分」这条；③ D10 的破坏锚点与真源码不符（行里多了一层拼接），锚点当场没命中 —— 这正是「判据自己写错伪装成被测对象不一致」，已按真源码逐字改回。

- **【边界 · 诚实三条】** ① 八份真源都是**纯函数**：本版证明的是「口径成立、判据会响、接线没断」，**不是**「模型会照着写」—— 从「池子在手」到「正文真的不油」之间隔着提示词装配，那一段归交付侧；② 氛围池的六十条**不设自动风格判据**（好不好是读者的事，机器只能保证「有得抄、不重复」）；③ 关系七级的读数是**行为口径**（消息条数 / 承压兑现 / 双向投入），不是「感情深浅」的度量 —— 任何行为口径都会被「不说话但一直在」这类形态漏掉，本版对此不装作能覆盖。
