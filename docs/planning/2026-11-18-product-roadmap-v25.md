# 第二十五期路线图 · RubyPhone（R25-O1~O9 / R25-X1~X9）

> **状态：排队中，非现行排序。** 现行唯一排序是第二十四期（见 `PLAN.md` 顶部）。
> 本文件是「超大更新到 26」的前半；后半见 `docs/planning/2026-11-18-product-roadmap-v26.md`。

## 0. 为什么这一期合并成一份，以及证据状态

本仓惯例是「优化九项 + 拓展九项 + 证据书」三份分开。本期起**合成一份**，原因不是省事：

1. `code_runner` / `package_proxy` 卡死，`grep` 在 linux 环境路径解析失效 ⇒ 本轮**不能检索消费点、不能跑门禁、不能提交**。
2. 在这种条件下把「待复核」拆到三份文件里，只会让未验证的断言散落三处，更容易被后续会话当成已证。
3. 所以本文件每条都带状态：`【实读】`＝本轮真打开过该文件/数过字节；`【待复核】`＝只有文件名或历史文档读数，**开工第一步必须复跑**。

纪律不变：**关键词命中不能当判据**；把「模块在盘」当「机制生效」是上一轮连着翻车的根因（全局搜索、撤销、VFS 沙箱、租约内核、跨 App 事务五条都已存在）。

## 1. 本期判断：现在最贵的东西是「四座单体 + 一层缺席的失败面」

R21~R24 一路在加**整机能力**（事件总线、事实通道、权限、装载、可携、离线、i18n、锁屏）。加到 R24 时有一个反差变得刺眼：

- 手机已经能「像一台手机」了，但**四个文件大到没法安全改一行**：`index.js` 918,927 B、`data/cheats.js` 27,611 行、`apps/settings-app.js` 12,362 行、`apps/wechat/chat-view.js` 18,449 行（收口后）；`【实读：字节/行数取自本仓已落盘读数】`
- 而「**某个 App 出错了会怎样**」至今没有答案：没有边界、没有单 App 重启、没有「已恢复」回执。用户看到的是整机白屏或静默失灵。

所以本期两件事：**拆骨**（把四座单体拆成可安全修改的形状）+ **兜底**（把失败面补齐，错了要能说清、能恢复）。

## 2. 优化九项（R25-O1~O9）

| 编号 | 项 | 为什么它是最缺的（带状态） | 验收口径 |
|---|---|---|---|
| O1 | 四座单体拆分 | 单文件改一行要全量重载，热修、审查、定位都做不了；`data/cheats.js` 27,611 行是最大风险点 `【实读：行数/字节】` | 拆分后 import 解析与 browser 门全绿，**行为逐条对拍一致**（不是「看着没坏」） |
| O2 | 长列表虚拟滚动 | `apps/wechat/chat-view.js` 内注释自认「只出读数不改渲染」 `【待复核：行号】` | 1 万条消息滚动帧率与内存有前后实测值；滚动位置与草稿在切 App 后一致 |
| O3 | 媒体内存 | 相册原图/语音大对象无显式释放路径 `【待复核】` | 连开 20 张原图后内存回落到基线 ±10%；释放动作有回执 |
| O4 | 启动真收益 | `config/boot-timing.js`（258 行）头注释明写「78 处动态加载零时计」「本版一条加载路径都不改」`【实读】` ⇒ 读数在、优化没做；样式仍整包加载 | 冷启动到可交互时间给出前后实测值；样式也懒加载；未触达的 App 样式不入首屏 |
| O5 | 设置面信息架构 | `apps/settings-app.js` 12,362 行、`bindEvents` 5,374 行，设置项靠位置记忆 `【待复核】` | 设置项可搜索、按组收拢、可恢复默认；为此新增的行数有上限（不许再造一个巨型文件） |
| O6 | 数据增长治理 | `config/storage.js`（1,748 行）已有 `STORAGE_SCHEMA_VERSION = 2` 与迁移台账，但**没有「每 App 条数/字节/增长趋势」面** `【实读 1,748 行；增长面缺席】` | 每个 App 的占用可看、可排序；超阈值有清理建议且**清理前出差异预览** |
| O7 | 无障碍：字号/动效/对比 | R22-O3 只补了 aria-label 字符串，字号缩放、减弱动效、高对比三档都没有 `【待复核：基线 350/115/17】` | 三档各自可开、界面不破版；减弱动效下无位移过渡 |
| O8 | 键盘与焦点 | 焦点陷阱、Esc 语义、Tab 顺序未成体系 `【待复核】` | 全键盘可完成「开 App → 发消息 → 回桌面」；焦点永不掉到被遮挡层 |
| O9 | 错误可读化 | 异常目前是控制台原文，用户侧无解释、无建议、无诊断包 `【待复核】` | 每类错误有人话 + 建议动作 + 一键复制诊断包（含版本、模块、最近动作） |

## 3. 拓展九项（R25-X1~X9）

| 编号 | 项 | 为什么它是最缺的 | 验收口径 |
|---|---|---|---|
| X1 | 崩溃边界与自愈 | R24 自己写的「谁来兜住崩溃」至今无人接。一个 App 抛错 → 整机白屏或静默失灵 | 单 App 抛错只挂该 App，边界捕获后**单 App 重启**，桌面可用，回执写清哪个 App、什么错 |
| X2 | 状态回放（时光机） | 有存档台/备份桌，但没有「回到某时刻的手机长什么样」。排查与复盘都缺证据 | 选一个时刻 → 消息/未读/钱包/日程按当时值展示；**只读**，不写任何键 |
| X3 | 敏感信息遮蔽 | 截图与分享是全量原文，手机号、金额、指定联系人一律裸露 | 按规则脱敏后截图/分享；规则可编辑；遮蔽处与原值不同形（不是打码后仍可搜） |
| X4 | 时区与日期格式 | 剧情钟 × 系统时区 × 12/24 小时制 × 日期格式四者未统一，跨时区会话会对不上 | 四者组合矩阵逐格验；同一时刻在全 App 显示一致 |
| X5 | 多设备布局 | 平板/横屏/窄屏无断点语义，宽屏是一列巨宽 | 三档断点各有明确布局；横竖切换不丢状态 |
| X6 | 通知语义分级 | 有通知中心，但没有「重要/普通/静默」分级与免打扰时段 | 三档行为不同形（静默不弹横幅但进中心）；免打扰时段内零打扰且有回执 |
| X7 | 外接键盘与快捷键 | 桌面浏览器场景无快捷键，全靠鼠标 | 一组最小快捷键（返回/搜索/发送/切 App），可在设置里查看与改 |
| X8 | 整机 A/B 对照台 | 每次改动只能靠人肉点，没有「同一操作序列两版本对拍」 | 给一段操作序列 → 两版本各跑一遍 → 输出差异清单（**产品面，不是门禁**） |
| X9 | 剧情钟推进的全 App 联动 | 钟一跳，消息时间戳/日记日期/日程/锁屏摘要各算各的 | 改钟一次 → 上述四处同时变；任一处不同步即不合格 |

## 4. 批次与依赖

- **A 批（拆骨，先做）**：`O1` → `O4` → `O6`（不拆完就动性能，等于在单体上做微调）
- **B 批（兜底，与 A 并行）**：`X1` → `O9`（边界先立，错误才有人话可写）
- **C 批（可达）**：`O7` → `O8` → `X7`
- **D 批（整机语义）**：`X2` / `X3` / `X4` / `X5` / `X6` / `X9`
- **E 批（最后）**：`X8`（它需要一个稳定基线才有意义）、`O2` / `O3` / `O5`

## 5. 本期纪律

1. **不许再新增「登记面」**：任何一项必须有一个用户能点、能看、能改的消费点。
2. **三态不塌**：`unknown` / `denied` / `absent` / `suppressed` / `degraded` 各自成态。
3. **不许拿「文件在盘」当「能力在」**：本文件每条 `【待复核】` 在开工前必须先给出实读证据，否则该项当轮不进交付。
