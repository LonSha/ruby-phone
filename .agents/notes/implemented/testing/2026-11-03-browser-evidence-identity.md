# Agent Note: 浏览器冻结证据与本次观测分别对账

Status: implemented

## Problem
新增 X6 场景后必须重跑浏览器矩阵以补齐覆盖证据。旧 v4100 D2/D4 却把 v4.100 的冻结失败清单强制等同于 v4.117 的失败清单，129 条现测失败对 138 条历史冻结被判失败。即使某旧失败本次通过也会报幽灵；按其要求重写冻结账本会洗掉历史证据并可能把真新增冻结进去。

## Decision
冻结总数依自身 entries.hits 复算，distinct 与条目数一致；同版本快照逐条核对失败，跨版本保留冻结证据但要求场景仍存在。本次 readings 的覆盖、总数与逐场景数仍独立校验。生产包装门继续根据冻结清单逐条拦新增失败，既不刷新 known，也不延长期限。本次观测不会自动成为新的豁免证据。

## Alternatives considered
- 重写冻结账本最快通过旧判据，但会抹去尚未证明稳定修复的记录，也可能把新增失败合法化，因此不采用。
- 保持旧 readings 能避开比较，但缺新增场景覆盖，不是诚实证据。

## Consequences
历史失败本次偶发通过不再迫使人洗账。跨版本不再要求每个历史失败本次重现，真正的新增失败仍由未改动的 browser-gate-run 判错。本次矩阵 13 场景四视口、503 读数、129 FAIL，不能宣称浏览器全绿。D2 新增不存在场景与同/跨版本对照，D4 用总数篡改验证计数判据。
