# Agent Note: 本地备份、迁移与灾难恢复

Status: implemented

## Problem

v3.91.0 之前，本仓的数据虽然全部落在本地（会话档与全局档两层容器），但**没有一处能把它们搬走**：全仓只有三处导入导出，且都属单一功能的预设（生图预设与工作流），回答的是「几套参数搬不搬得走」，不是「我这一整部手机搬不搬得走」。修前实测四条后果：换设备只能重来（几千楼会话里攒的账本与日程无法导出）；包体没有身份（无 schema 版本、无会话与分支范围、无敏感标记）；倒进去就回不去（无预览、无冲突检测、无部分导入、无撤销）；旧版本包无处置（该迁移还是该拒，没有任何定义）。

## Decision

四维范围（App / 会话 / 项目 / 素材）**取交集**——并集会把「我只要这一部的会话」变成「这一部加其他所有」。包体带完整身份：魔标 / schema 版本 / 宿主版本 / 来源 / 会话范围 / 分支范围，以及**逐键的敏感标记**（已知敏感 / 明确非敏感 / 未知，三事分开）。两个分面（会话面 / 全局面）不许互换：把会话键写进全局档等于把 B 角色的数据交给 A 角色。旧包只走两条路：逐版迁移（每一跳必须带为什么与改写规则、不许跳步）或明确拒（无版本号 / 未来版本 / 迁移链断层），「不认识的字段静默丢掉」不在这两条里。导入只产计划：逐条分五态（新增 / 还原 / 逐字相同 / 冲突 / 拒收），计划阶段连对象都不碰，落盘只在确认后发生，且写后逐条回读确认。逐字相同的条目**既不写、也不计入跳过**——混进任一边都会让「导了两次多出一堆记录」这种事故变得看不出来。撤销清单按写入**逆序**列出，且只列本次真写成的那些。

内核不写存储、不联网、不碰 DOM、不读文件系统，键面与存量全由调用方给；存储层只加一个**只读**的键枚举口（不写入、不删除、不触发迁移），并把三态分开：容器读不到 / 读到了但零键 / 读到了有几键。

## Alternatives considered

- 复用既有的 portable-payload：它是**单功能预设**的载荷口径（少数几个键、宽松归一），与整机迁移的「严格比对 + 五态 + 逆序撤销」是两件事；合并会让两边的判据互相将就。故两套口径各守其职，并在判据里对账（C1）。
- 按「已知键名清单」枚举要备份的键：清单总会漏（本仓清单式回收反复漏项），故改为向存储层要一个枚举口。
- 迁移时遇到不认识的字段就地丢弃：最省事，但正是「静默丢字段」这一族，故不做。

## Testing

定向套件 `tests/system-v3910.test.mjs` 六面 19 条：A 结构面（四维 / 两分面 / 迁移表 / 存储只读枚举口 / 三道注册面 / **四一致与 REBIND 表登记**）；A2 纯函数与零网络（剥注释后判）；B 行为面（包体身份 / 五态互不同形 / 幂等 / 迁移 / 分面 / 冲突 / 分支 / 交集 / 撤销 / 导入前不改现有数据）；C 接线面（与既有便携负载的指纹口径各守其职 / 咽喉守卫顺序）；D 负控制（八处真源码定点破坏，破坏副本上同款判据必转红，第八处两向对照自证）；E 版本锚。探针基线由 `tools/refresh_baselines_v3910.py` 现场对平。

## Consequences

**本版修掉的三处缺陷，两处是判据抓的、一处是门禁抓的，全部在合并前落地：**

① **缺席与零被塑成同一件事**（负控制基座抓到）：`numOrNull(null)` 返回 0（`Number(null) === 0`），使 `migrateBackupPack` 里「无版本号」分支**根本不可达**——无版本号的包被走成「v0 的包」，两条路都是拒、但拒的理由完全不同，破坏那个分支完全不生效。修法是先把「缺席」单独认出来。

② **自写的弱口径取数**（weak-coercion 门当场抓到）：本版在 `config/data-backup.js` 里自写了一份 `numOrNull`，把 `[]` 与 `false` 都读成 0（探针实测 `emptyArr:0 false:0`）。这是「同一口径不许有第二份实现」纪律的活标本：删掉自写实现、改用 `config/num-gate.js` 的唯一实现，门禁转绿。

③ **判据射程静默退化**（全量回归暴露，根因不在本版而在 v3.61.0）：`scripts/lifecycle-audit.mjs` 的 L1 用「index.js 里的字面写法 `VirtualPhone.X = new module.Class`」反查槽位，而 v3.61.0 起 67 个 App 改成表驱动装配（`VirtualPhone[lazyRoute.key] = new module[lazyRoute.cls]`）——槽位名在 index.js 里是**变量**，字面反查必然落空，于是反查不到槽位的类被 `continue` 静默跳过。**实测射程：81 个含出口的 App 类里只剩 13 个仍被扫到，68 个从判据里消失**（含本版新建的 backupdesk）。判据没坏、没报错，只是再也不看它们了。这正是本版漏登记 `backupdeskApp` 时门禁全绿放行的原因。修法：L1 反查面补上表驱动映射（读 `config/app-lazy-routes.js` 的 cls→key），并新增两条 fail-closed——表读不到即拒判（**不得退回旧射程**）、可反查到槽位的类占比低于 80% 即拒判（枚举面与判定面脱钩时，总数完全看不出来）。负控制见 `tests/system-v265.test.mjs` 的 N6 / N7。

与这三处并列的还有两处**交付口径**缺陷（全量回归首跑暴露，与 R-X6 同族）：两份新建 App 都用了别名文件名（`backup-app.js` / `creation-workbench-app.js`）与不挂钩目录名的类名，违反全仓「目录 ↔ 文件 ↔ 类 ↔ 槽位」四一致约定。这不是命名洁癖：约定被打破时，凡按 `<dir>-app.js` 派生路径的判据（v3270 / v3550 / v3590 / v3650 与 audit 通用面）都会**静默漏过**这个 App。已整层改名，并把该约定固化进两版判据的 A 面。

浏览器实机与全量 `npm test` 仍属第二期收官验收范围；不得用定向测试冒充完成。
