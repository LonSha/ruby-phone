# Agent Note: R14-X7 行程进行中操作与预览边界

Status: implemented

## Problem
旅行板保存路线及共同费用，但缺少当前站、跳站、晚到和临时会合的用户操作。直接修改路线会丢失历史；预览后来源变化可能让确认写入过时状态。

## Decision
旅行页提供当前站、跳站、晚到分钟数和会合对象按钮。progressAction 只修改站点显式字段，normalizeStop 保留这些字段。跳站保留原站；推进当前站把上一当前站记为 visited。partyAct 在预览和确认时重读并比较完整归一行程，确认后沿用原保存入口并回读，拒绝来源变化及未确认保存。
后续站点在确认框列出供复核，未知交通时间不推算；原日历、剧情钟和费用不被该操作修改。支持逐站输入有效日期并预览确认重排行程板；日历接续由用户逐站选择已有日程，单独预览确认后调用 CalendarData.updateMemo，保留日程 ID、时间及原有生活线更新；不按同名推断关联，本记录不代表 X7 整体验收完成。

## Alternatives considered
直接删去跳过站点便于缩短路线，但会丢历史，故保留 skipped 状态。按晚到分钟数自动平移全部日程可减少输入，但缺少交通和约定依赖证据，因此当前仅保存用户声明并展示受影响站点。

## Consequences
三项定向测试覆盖历史保留、未知时间、预览无写、旧确认拒绝及归一重读。界面按钮已接入，Chromium 页面五条读数通过，覆盖取消、跳站、显式日期和新实例重开；真实宿主尚未验证。新增日历接续专项五项通过，完整旅行浏览器场景十一条读数通过。约定投影与周期日程拒绝旁路修改，要求返回原入口；不自动创建日程。站点 calendarMemoId 随 tv_party 会话键保存，重开复用；解除只清引用，原日程保留。确认使用 session-gate 双维令牌拒绝换会话后的旧预览。日历成功而关联保存失败时明确报告部分完成，可重试。存储回读仅证明当前 owner 可见记录，不能证明异步后端崩溃原子性。真实宿主仍待验证，不能以夹具替代整项验收。
