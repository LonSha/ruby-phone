# Agent Note: 声明式工作流的执行证据边界

Status: implemented

## Problem

R-X5 的初稿有声明与 UI，但执行层把回滚当正常写入、续跑只改状态、回读先于写入；纯函数自检无法发现这些跨层缺陷。

## Decision

流程表只描述内置动作，不执行用户脚本。纯内核负责计划与状态，注入端口的运行器负责串行执行、暂停和逐步检查点，index.js 只适配真实 owner。写前记录 running，写后记录步骤结果；中断后仍在 running 的步骤视为结果未知，禁止自动重做。确定失败的步骤可重试，已成步骤必须复用输出。回滚按收据逐项逆序委托，撤销失败不冒充成功；不能撤真实余额，仅撤本机确认记录。

会话身份、分支和宿主世代在每次异步边界两侧核对；换会话不得接受旧按钮确认或向新会话写旧台账。台账保存回读只证明本地接口读回一致，不证明宿主磁盘 durable。最多保存 40 个运行，幂等保证限于保留窗口；结果未知的检查点需要人工核对，不自动猜测。

## Alternatives considered

- 保留内存台账：最简单，但刷新后失去步骤证据，重试会重复写入，故不采用。
- 仅给旧实现加状态断言：修改少，但无法发现 owner 返回 null、保存失败和回滚误入写分支，故测试必须执行运行器和真实适配器。
- 宣称跨多个 owner 的原子事务：接口没有事务能力，无法兑现；采用逐步检查点与补偿，明确结果未知窗口。

## Testing

定向测试覆盖纯内核、注入运行器、index.js 真实函数提取、owner 拒绝与异步换段、源码破坏负控制。浏览器实机与全量 npm test 仍在第二期收官验收范围；不得用定向测试冒充完成。

## Consequences

多一次检查点写入换来可恢复性与失败可见性，但不提供跨 owner 的原子性；明确拒绝结果未知的重跑，比无证据重复通知或记账更安全。
