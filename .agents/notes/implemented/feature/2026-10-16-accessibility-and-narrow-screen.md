# Agent Note: 无障碍、窄屏与个性化操作层

Status: implemented

## Problem

v3.93.0 之前，本仓有八十七个 App、两期计划沉淀下来的大量机制，但**没有一处**回答「这个手机对操作不便的人是什么样」。修前四条实测（不是推演）：

① **键盘用户进不去主屏**：桌面图标与 dock 只挂了 `onclick`，没有 `role` / `tabindex` / `aria-label`，Tab 键根本落不到图标上；② **焦点可见性反着做**：`focus-visible` 全仓只写在五个文件的具体控件 id 上，图标与 dock **一处都没有** —— 结果是鼠标用户全程亮框、键盘用户全程没框，恰好与需要相反；③ **状态只靠颜色**：`app-badge` 一族十余处只给色块，色觉障碍用户读不出「成功」与「失败」；④ **没有窄屏概念**：全仓没有 320px 断点（两条 `max-width: 320px` 是宽度取值不是断点），且主屏翻页容量**写死四列**，与 CSS 的列数分属两处 —— 改一处必然与另一处漂移。

侦察时另撞到一条比上面四条更重的：**键审计的抽键正则不认连字符**。`scripts/keys-audit.mjs` 的 `CALL_RE` 字符集是 `[A-Za-z_][A-Za-z0-9_]*`，于是全仓 **142 个带连字符的键**（`phone-font-scale`、`phone-image-*` 一族、`offline-*` 一族、`story-*` 一族等）从未进入过 K1 / K2 / K3 任何一道判据的射程。其中 3 个（`pending-contacts`、`story-current-time`、`story-initial-time`）**真的**命中 `CHAT_DATA_PATTERNS` 的会话隔离正则 —— 也就是说，**该按会话隔离的键，从来没有任何门禁问过它归谁**。这不是漏了一个键，是判据自身的射程错：它让「键归属全登记」这句结论在此前每一版都是**假的绿**。

## Decision

判定内核 `config/access-layers.js` 是三档操作层、四态状态、窄屏计划、字号档、遮挡守卫、可读名四级真源、主题解析、自检的**唯一实现**。零 IO：不读时钟、不读存储、不联网、不碰 DOM，环境与真源全由调用方注入。

五条口径决定了它的形状：

- **四态不得压平**（空 / 未知 / 失败 / 成功各带文字与符号 `○` / `？` / `×` / `✓`）。归一化一律「认不出归未知、空串归空」，两者处置相反 —— 空是「这里本来就没有」，未知是「没测到」，压平会造出「本来没有」被写成「故障」的假故障。
- **读不出不得猜**。宽度读不出**不得**判窄屏、字号读不出**不得**判大字号：判窄会让标准屏用户看到缩排布局、判大字号会让没设过的人看到换行，两个方向都难看。读数缺席一律走标准档，并在界面上**如实写明依据**。
- **遮挡守卫三格各自独立**（按钮换行 / 状态行高度自适应 / 文字标签保留）。并成总开关会在放大字体时把状态行压成定高、文字顶到下一行；判据直接断言三格不得同时为真或同时为假。
- **可读名四级真源且不编名字**：`aria-label` > `label` > `text` > `icon`，四级都取不到就**如实空串**，绝不编「按钮」二字 —— 假名字会让读屏用户以为点对了，比空名字难排查得多。
- **同一件事不留第二个存储位**：低动画**复用** `sys_motion_level`、字体缩放**复用** `phone-font-scale`，本 App 只写 `sys_access_level` / `sys_access_compact` / `sys_access_theme` 三键。

咽喉（`index.js`）沿用 R-X1..R-X8 同族范式：白名单 `ACCESS_ACTION_KEYS` 声明在取数口**之前**；`refreshAccess` 是唯一取数口（缓存挂 `vp._access`，含 `readable` / `why`）；`applyAccessAction` 是唯一动作口（白名单 → 取数 → 世代检查 → 写 → 重取）；`writeAccessKey` **写后回读三态**（confirmed / pending / mismatch）—— 写失败最贵的形态是「按钮看起来点了、值没落盘」，写后回读是唯一能当场发现它的时机。三个动作写键收敛在唯一一处。

App 三层（`apps/accessdesk/`，类前缀族 `.axd-*`）：动作白名单四个值 `level` / `compact` / `theme` / `preview`，其中 **`preview` 是纯视图态** —— 不进白名单、不经过咽喉、不写任何东西。

## Alternatives considered

- **把 `narrow` / `narrowReason` 两格都透给视图**：一开始就是这么写的。但视图随即从这两格**各自还原一次**排版口径 —— 同一件事有了两个来源。判据 C1（「App 必须透出 plan」）报红后改为**只此一格** `plan`，两个派生字段由视图从它算出来。
- **在图标上直接写 `aria-label="按钮"`**：短、稳、永远不为空。但给读屏一个「看着正常」的假名字，会让用户以为点对了目标 —— 内核 `a11yNameOf` 因此对取不到名字的图标返回空串，属性**压根不加**，让「这个图标没名字」这件事在无障碍树上显形。
- **抽键正则只放宽不加登记**：放宽即可让 142 个键进入 K1 判据。但判据只问「登记了没有」，于是最省事的做法是**用通配**把一批键一次登记完 —— 通配会让「归属」变成「看着像对」。故 142 条**逐键显式登记**（3 会话隔离 · 139 全局），宁长不糊。
- **窄屏判定用 `<=` 与 `<` 之争**：判据定了闭区间（320 判窄、321 不判），因为「320 窄屏手机」是设计目标里的一个具体宽度，把它排在外面等于没做这一档。

## Testing

定向套件 `tests/system-v3930.test.mjs` 六面 39 条：A 结构面 / A2 纯函数只读（剥注释后核内核无存储无 DOM）/ B 行为面（四态守恒 · 320 闭区间 · 读不出不猜 · 三格独立 · 名字不编 · 主题三段解析）/ C 接线面（缓存逐格对齐 · 白名单先于取数口 · 只读口现采 · 列数派生 · 焦点环与断点共处一份样式 · 写键收敛一处 · 抽键口径认连字符）/ D 负控制八处真源码定点破坏（破坏副本上同款判据必转红，第八处两向对照自证）/ E 版本锚。

`keys` 门读数由 301 升到 443（443 个使用点 / 106 条 pattern / 443 条登记：会话隔离 250 · 全局 190 · 历史键 3），`registry` 门读数 APPS id 87 · 懒加载分支 87 · 样式投递 77 · 未覆盖 0。

## Consequences

**本版自己抓到的三条真缺陷，都不是本版新写的代码造成的，但都只有把门禁真跑一遍才会现形 —— 且都不报错，只错数据/只错结论：**

① **键审计射程本身的盲区**（见 Problem 末段）。这是**判据自身的射程错**，比任何一条业务缺陷都贵：它让此前每一版的「键归属全登记」都是假的绿。

② **longlist 基线跨五版未刷**。`tests/audit/longlist_scale_baseline.json` 的 `readings.after_motion_css.css_files_scanned` 停在 85，而真仓全仓 .css 枚举面实测自 v3.89.0 起 86 → 87 → 88 → 89 → 90（探针 `allCssUnder` 递归全仓统计）。用三棵 worktree（v3.89.0 / v3.91.0 / v3.92.0）加本版 HEAD 逐版对照确证：**读数判据 B1/B2 连红五版，每版都看着像「本版引入的新红」**。这正是本仓最忌讳的形态 —— 一条老是红的判据会让人失去对红灯的信任。修法不是改判据，是把刷新做成**可复算的脚本动作**：新建 `tools/refresh_baselines_v3930.py`（零手抄、幂等、冻结 `measured_at`、嵌套格名单不一致即拒判），刷新后两条转绿、二次跑报「已与现场同源，跳过」。

③ **R-X8 遗留的事件字面量误判**。`config/capability-health.js` 第 226 行的 JSDoc 参数标注里写了「参数名 `phone` 紧跟冒号类型」的样例，被 v226 的全仓扫描面（`phone` 加冒号加标识符）当成**手机事件名**，报 `契约外: [...]`。该红**自 v3.92.0 就存在**（三棵 worktree 对照确证），本版把注解措辞改名为 `phoneVersion` 修掉。

**本版自己抓到的两处实现缺陷：**

① 三层透出的排版依据此前分成 `narrow` 与 `narrowReason` 两格、视图又各自还原一次口径 —— 改后**只此一格** `plan`（见 Alternatives）。② **本版新写的基线刷新工具自己也踩了一坑**：探针读数段在 `readings` 里，而对账代码直接在上面一层找 ⇒「格格都在、却一处也对不上」，对账静默空转（写盘 0 处，看着像「已同源」）。修法是先取 `readings` 段再对，并保留「找不到就不动、不猜」的降级。同一形态还以第三副面孔出现：**条目正文里照抄了缺陷的样例字面量**，于是叙述缺陷这件事本身又造出一个契约外字面量（v226 同一判据再次报红）—— 判据没错，错在正文里写了可被执行面命中的样例。

另外三处**读数漂移**随抬版一并刷新（都属「不报错、只错读数」）：`tests/audit/status-ledger.json` 落盘台账（v3.91.0 → v3.93.0，由 `node tools/gen_status_ledger.mjs --write` 重算，测试 236 门 14 场景 12 unknown=0）与 `docs/runtime-verification-boundary.md` 边界文档读数（syntax 756→760、import 432/740→435/744，由 `python3 tools/refresh_doc_readings.py --write` 现场跑门写回）。

**本版挡得住「看起来生效了、其实没生效」这一族里的四个具体形态**：键盘进不去主屏、状态只有色块、放大字体压住旁边的按钮、窄屏溢出。

**本版不能保证**：① 真机触屏与读屏的实际观感（本版是按属性与样式核的，**没有实机跑过**）；② 深色模式下第三方素材与缩略图的实际对比度；③ 字体缩放取自既有设置项的百分比，若那一项日后改成分档文本，字号档会退回「读不出」而不是猜错（这是刻意的：宁可少一条判据，不可多一条假判据）。与 `docs/runtime-verification-boundary.md` 同源。

浏览器实机与全量 `npm run check` 属收官验收范围；不得用定向测试冒充完成。
