# Agent Note: RubyPhone 优化提升计划（第二期 · v3.72.0 核实基线）
Status: proposed

## 为什么有第二期
第一期（`2026-10-04-optimization-plan.md`，v3.56.0 基线）的 O1–O8 与拓展计划 X1–X8 均已落地（v3.65.0→v3.72.0）。第二期不是把第一期改个名重发，而是按当前 HEAD 重算后的真实缺口。本期只交付规划：不实施、不抬版、不声称当前全量通过。

## 事实起点（2026-10-08 实测）
- 版本 v3.72.0，HEAD `9a27979`，工作区干净，`main` 与 `origin/main` 同点。
- `index.js` 778915 字节 / 13259 行；`config/*.js` 67 件；`apps/` 81 个目录；`config/apps.js` 82 条 id；`tests/*.test.mjs` 215 件；`scripts/*.mjs` 14 件；`phone.css` 619586 字节。
- 十道静态门禁全绿（syntax / keys / dead-export / import-resolve / source-derivation / lifecycle / registry / bridge-contract / weak-coercion / upstream-face）。
- 全量 `node --test tests/*.test.mjs`：3191 例 / 3159 通过 / 32 失败 / 约 145s。
- 32 例失败**全部**来自 `system-v243` / `system-v244` / `system-v245` 三个历史套件（版本锚与基线读数失配，每次抬版必红），本次 X8 改动**新增失败为零**。

## R-O1 · 真实浏览器与 SillyTavern 宿主验收层（P0，规模 L）
**真实需求**：当前 215 个套件全部运行在 Node 纯函数与假宿主上。假宿主通过**不证明**按钮可点、元素可见、布局不塌、宿主回调真触发。历史教训已有两条：返回按钮缺席、设置页空白，两者都能通过静态存在性检查。

**工作**：
1. 保留零依赖 Node 门，新增独立浏览器运行层（Chromium 已可用）。
2. 第一层覆盖：桌面分页、打开 App、返回、锁屏、设置保存、搜索取消、切会话、清当前数据、重开面板。
3. App 首屏按**空态**与**有数据**两组各跑一遍，入口按 `config/apps.js` 的 82 条 id 枚举。
4. 取真实 DOM 与生产 `phone.css`：可见性、尺寸、点击命中、滚动、焦点、控件可达性。
5. 第二层接真实 SillyTavern：宿主事件、持久化、与记忆插件双扩展共装。

**验收**：
- 320 / 390 / 768 / 1280px 四档视口完成核心流程。
- 四类「看起来没坏但显示不对」必须能转红：入口被遮挡、宽度为零、按钮未绑定、保存后重开丢失。
- 每条证据带版本号、浏览器版本、fixture/host 标记。
- 环境缺能力必须报**未执行**，不得计通过。

**边界**：独立浏览器无宿主接口时，只结论布局与模块交互；宿主批次须有可访问的测试 SillyTavern，否则如实登记未执行。

## R-O2 · 清退 v243–v245 历史失败与版本锚失配（P0，规模 M）
**真实需求**：全量回归 32 例失败已连续多版存在。它们不来自产品缺陷，但让「当前是否健康」这一判断失真 —— 真缺陷会淹没在既有红里。

**工作**：
1. 逐套件判定每一例失败的归因，只允许四种结论：
   - 历史行为已被合法替换；
   - 测试版本锚写法错误；
   - 真实回归缺陷；
   - 测试自防护失效（破坏锚点恰中 0 次之类）。
2. 版本锚一律改为**钉自己那一版**（读 `log.versions[SELF]`），不随抬版漂移 —— 这条口径错在本仓历史上已被抓到过一次（v3270/v3280/v3290 三处）。
3. 行为已被合法替换的旧套件，迁移为**兼容性测试**，不是删除。
4. 与 R-O9 联动：把「每次抬版必红」的套件列入显式清单，抬版流程不再把它们当噪声。

**验收**：
- 全量回归 0 失败；或剩余失败全部有明确分类 + 单独复现命令。
- 禁止以降低断言、刷新 baseline、删除套件三种方式「洗绿」。
- 新增一个抬版演练：抬版后全量回归不得因版本锚而新增红。

## R-O3 · 跨会话异步写回统一栅栏（P0，规模 L）
**真实需求**：v3.58.0 已交付栅栏的裁决口径与七族写回口的接线，但接线在场 ≠ 真宿主那一轮真跑对。生图、搜索、微信生成、总结、通知都可能在切聊/删楼/重生成之后回信。

**工作**：
1. 以 `chatId / branchId / revision / epoch` 为唯一身份面，逐个写入口核对：捕获时机、await 前后复核、拒绝路径。
2. 旧会话回信只允许结束自身资源，**不得写当前会话**；拒绝必须给出可读原因（不是静默丢弃）。
3. 面板重开重点观察监听器、计时器、对象 URL、重试调用是否累积。
4. 页面前后台切换后重取当前状态，不沿用切换前的缓存身份。

**验收**：
- A 发请求 → 切 B → A 回信，B 状态逐字不受影响。
- A 清空 → 旧保存回调不得复活数据。
- 删楼 → 旧召回返回必须被拒。
- 反复开关面板 20 次，监听器/节点/定时器回到基线。
- 至少一批序列在真宿主里可复现（与 R-O1 合批）。

## R-O4 · 写入回执三阶段统一（P1，规模 M）
**真实需求**：不同 App 的写包装返回口径不一（`ok` / `saved` / `confirmed` 并存），典型事故形态是「界面显示已保存，重开读不回来」。纯函数处理成功、存储提交成功、重开可回读是三个不同阶段。

**工作**：
1. 以 `PhoneStorage` 实际契约为准，统一回执模型：`prepared / written / confirmed / failed / partial`。
2. 关键 App 的写路径加**回读确认**，不以写入副作用当成功。
3. 多键写入记录完成范围；失败保留草稿与旧有效值。
4. 明确每个数据桶的唯一写入 owner，禁止渲染层顺手修数据。
5. 审计对象值与 JSON 文本混用的历史兼容路径。

**验收**：
- `set` 返回 false、抛错、`get` 抛错、多键中途失败，四种情形都不得显示「已保存」。
- 重开 App / 切会话 / 切分支后能读到同一记录。
- 清除单个 App 不连坐其他桶。
- 不新增第二套数据库。

## R-O5 · 搜索与大数据量交互性能治理（P0，规模 M–L）
**真实需求**：全历史搜索已交付，下一步不是重做搜索，而是让它在手机上**不阻塞界面**。当前实现按 2000 条分组但函数本身不让出事件循环，取消只在渲染层生效。

**工作**：
1. 索引构建、命中评分、结果收束全部纳入可中断任务；片间让出宏任务或帧。
2. 保留并强化代际取消：换词、改楼、换会话都不得提交旧结果。
3. 源适配器若先同步物化全数组，必须计入耗时并改为分批取数。
4. 建立 1000 / 5000 / 10000 楼与 60000 条上限的设备基线，先量后定阈值。

**验收**：
- 搜索进行中，计时器与点击事件可执行（证明真让出）。
- 取消后确实少扫描（以扫描计数证明，不只看返回值）。
- 旧搜索结果不得覆盖新结果。
- 无取消路径的结果与现同步基线逐字一致。
- 记录首结果延迟、完整延迟、取消延迟、峰值内存。

## R-O6 · 长列表、面板重开与后台恢复性能（P1，规模 M–L）
**真实需求**：`boot-timing`、perf_probe、内存趋势探针已存在，缺的是真实 DOM 读数 —— 现在还没有任何证据能说明浏览器里大列表滚动流畅。

**工作**：
1. 用 R-O1 的浏览器层测：首屏、面板重开、长列表、搜索、健康仪表。
2. 按证据选择分页 / 窗口化 / 合并 DOM 更新 / 源版本缓存 / 非关键懒加载。
3. 优先移除**非必要动画与粒子**（已知会明显拖慢渲染）。
4. 后台降频与恢复后重取一起设计，避免恢复瞬间全量重算。
5. 性能读数被动采样、有界保存，守护器自身不得常驻拖累。

**验收**：
- 典型与极端数据都有 before/after 对比。
- 保留选择态、滚动位置、键盘焦点。
- 反复复开资源不增长。
- Node 拼串耗时不得写成浏览器帧耗时；目标设备读数未取得时保留证据缺口。

## R-O7 · 诊断从「有读数」变成「能处置」（P1，规模 M）
**真实需求**：诊断页读数已很多，但用户看到红格后不一定知道下一步做什么。空、未知、缺席、失败、部分成功常常同形。

**工作**：
1. 统一五态显示语义（空 / 未知 / 缺席 / 失败 / 部分成功），互不同形。
2. 每个失败给出：失败阶段、影响范围、可否重试、是否需要切宿主、是否需要用户确认。
3. 为续玩交接、财务、搜索、存储、生命周期统一错误码与回执格式。
4. 诊断项可直接跳到对应 App 或恢复操作。

**验收**：
- 「没有数据」「读取失败」「模块不存在」三种情形文案不同形。
- 诊断读数必须来自生产 trace 或真实回执，**不允许视图自行猜测**。
- 用户能从诊断项一步到达处置入口。

---

## R-O8 · 重复实现与维护半径治理（P1，规模 L）
**真实需求**：行数已不是目标（第一期 O6 的方向已消化）。真实问题是同名函数、重复 fallback、失效兼容分支带来的维护半径。

**工作**：
1. 依据真调用图，优先治理四簇：懒加载映射、生命周期接线、更新公告数据、跨 App 注入装配。
2. 先迁纯数据与无状态装配，再迁带副作用模块。
3. 每次迁移保持 App 加载顺序、单例、旧键名与异常退路。
4. 清理同名不同实现的函数，核对动态路径与缺席退路。

**验收**：
- 每刀必须能证明**重复实现减少**或**加载收益可解释**，不接受「文件更小」当唯一理由。
- dead-export / import-resolve / registry / lifecycle 四门不得退化。
- 真实打开 App、切聊流程行为不变。
- 入口行数只作附属读数，不设新的任意数字目标。

## R-O9 · 计划、版本、门禁与基线自动同源（P1，规模 M）
**真实需求**：`PLAN.md`、`TODO.md`、`ITERATION_LOG.md` 与真实 HEAD 之间仍存在历史快照混杂（例如 PLAN 的版本行停在 v3.65.0，而实际已是 v3.72.0）。台账表**没有判据看守**，每次抬版靠人肉复算。

**工作**：
1. 建立机器可读的当前状态台账，自动生成：当前版本、已完成切片、未执行验证、已知失败、门禁数量、测试耗时、真宿主缺口。
2. 历史计划与当前计划分层：历史内容标注快照版本，不再出现在「待办」。
3. 门禁分档展示：`npm test` / 定向套件 / 浏览器门 / 真宿主门。
4. 干净检出依赖 `.sourcematerial` 的用例按「公开夹具验机制 / 私有真素材验保真」两组分报。

**验收**：
- 新会话只读仓库即可辨别已完成项与本次待办。
- 未知不报 0，未执行不报通过。
- 干净检出后能重建同一份基线。
- 测试优化不得减少关键负控制与运行时覆盖。
