# 第二十四期 · RubyPhone 拓展九项（R24-X1~X9）

> **主题：让手机「更像一台手机」，而不是 101 个登记面。**
> 本期拓展不给「再加一个案头 App」名额。R21~R23 的 27 个拓展项绝大多数是**同一形态**：
> 一个纯函数桥 + 一个登记面 + 一组三态读数（`config/v23-trace.js` 九座就是典型）。
> 这类桥已经饱和。真正缺的是**整机级能力**：App 之间怎么说话、谁有权限读谁、谁来兜住崩溃、
> 怎么把整台手机端走。九项全部是整机级或跨 App 级。

## 0. 立项前核对（X 侧，2026-11-18 实读 `config/` 后）

> 检索通道限制（必须如实记）：本轮 `grep` / `code_runner` 均不可用，故「某内核有没有被消费」**没有实测证据**，

## X1 · 手机事实通道：跨 App 的「现在是什么值」

**缺什么**：本仓**有事件总线**——`config/phone-events.js`（316 行）是跨模块事件契约单一真源，
登记 16 个事件名（`phone:goHome` / `phone:openApp` / `phone:timeUpdated` …），实测 29 处订阅、83 处派发，
由 `tests/system-v226` 双向对账（字面量必能映射 + 登记项必有真实使用）。
**但事件传的是「发生了什么」，不传「现在是什么值」**：想知道「现在几点（剧情钟）」「我跟谁在聊」
「今天花多少钱」，订阅方仍然得自己去翻别人的键或全局对象 —— 于是又长出一份新账（一物多账，R21-O7 治过一轮）。
两者缺一不可：事件驱动界面动作，事实驱动数据展示。**

**做什么**：
1. `config/phone-facts.js`：**值**的发布/订阅层（不是事件层的替代，是它的补集），事实由唯一持有者发布
   （钟 / 未读 / 钱包 / 在场角色 / 当前会话）；
2. 发布者登记制：谁发布哪个事实由登记表声明，**同一事实两个发布者直接拒判**；
3. 订阅方只拿快照 + 变更通知，**不许**直接读别人的 storage 键；
4. 事实三态：`known` / `stale`（超过时效）/ `unknown`（发布者未上电）——三者不同形，界面不许用同一个「无」；
5. 与 `phone-events.js` 的分工写进两个模块的头注释：**事件 = 动词，事实 = 名词**，新代码不得混用。

**验收口径**：断开某发布者后，订阅方读数变 `unknown`（不是 0、不是旧值冒充）；
同一事实双发布者时启动即拒判；`apps/wechat` 与 `apps/wallet` 的钱包读数逐笔对账一致。

## X2 · 权限与隐私面：App 间的访问授权

**缺什么**：`CONTEXT.md` 明写「一个 App 不读另一个 App 的表」，但这是**纪律**，不是机制。
345 个 `config/` 模块相互 import 无任何声明；「相册能不能被小红书读」「通讯录能不能被商城读」
这类问题今天只能靠人记。

**做什么**：
1. 资源登记：`contacts` / `album` / `messages` / `wallet` / `location` / `calendar` 六类资源；
2. 每个 App 在 `config/app-permissions.js` 声明它要读哪些资源，**未声明的读取即不返回数据**（fail-closed，返回 `denied` 而不是空数组）；
3. 用户可见：设置里能看到「谁在用什么」，可逐项撤销；
4. 访问留痕：最近 N 次跨 App 读取记进一条台账，用户可查看（**不记内容，只记谁读了什么**）。

**验收口径**：未声明权限的读取返回 `denied` 且与「没有数据」不同形；
撤销权限后该 App 立即读不到（不用重启）；台账条数与实际读取次数对得上（不虚增不遗漏）。

## X3 · 应用市场：第三方 App 的注册与装载

**缺什么**：新增 App 要改四处注册（`config/apps.js` / `phone.css` / `index.js` 分支 / 可选标签监听），
`CONTEXT.md` 与 `scripts/registry-audit.mjs` 都写死了这条。于是「第三方写个 App 装进来」**结构性不可能**。
已有 `apps/widget`（自定义组件）是个登记面，不是 App。

**做什么**：
1. App 清单改为**声明式**：`{id, name, icon, color, entry, styles, permissions, schema}`，注册表运行时可增删；
2. 装载器：按声明加载 `entry`（ESM），样式按需注入，权限走 X2 校验；
3. 卸载：撤图标、撤样式、撤权限、**数据保留或清除由用户选**（不许静默删）；
4. 内置 App 与第三方 App 走**同一条装载路径**（不许有「内置特权分支」，否则第三方永远二等）。

**验收口径**：把 `apps/weather` 以第三方包形态装回来，功能与内置版逐条对拍一致；
卸载后无残留样式与图标；非法清单（缺 entry / 权限越界）装不上且给出原因。

## X4 · 整机可携：人类可读的手机档案

**缺什么**：有存档台（`apps/archive`）、有备份桌（`apps/backupdesk`），但两者都是**包治理**
（一份包的结构/版本/覆盖性），不是「把整台手机端走再放回来」。用户换设备/换会话，数据搬不走。

**做什么**：
1. 导出为**人类可读**目录结构：`phone/<app>/data.json` + `manifest.json`（版本、App 清单、每 App 条数）；
2. 导入支持**三种模式**：全量替换 / 合并（同 id 取新）/ 只补空 —— **三模式界面上必须不同形**，不许一个按钮猜；
3. 导入前出**差异预览**（会新增多少、覆盖多少、丢弃多少），确认后才写；
4. 与 O1 的 schema 迁移联动：旧版档案导入走同一迁移链。

**验收口径**：导出 → 清空 → 导入，全 App 数据逐字段一致（差异逐条列出）；
三种导入模式在同一份档案上产生三种不同结果（可复跑）；
导出文件用文本编辑器可读，字段名是英文标识而非内部键。

## X5 · 离线演示模式：不依赖宿主也能跑

**缺什么**：整个扩展强依赖 SillyTavern 的 `chatMetadata` 与事件总线。想给没装宿主的人看效果、
想在 CI 里跑真界面、想在没有会话时演示，都做不到。现有测试是纯函数级（`node --test`），
**没有一次「真界面在跑」的证据**。

**做什么**：
1. 宿主适配层：`host-adapter.js` 提供 `storage` / `eventBus` / `chat` 三个接口，宿主实现与内存实现二选一；
2. 内存实现带**演示种子**（一份 30 条消息的会话、8 个联系人、20 张登记图片），启动即可交互；
3. 打开方式：`index.html?offline=1`（或独立 `demo.html`），不污染生产入口；
4. 演示数据与生产数据**物理隔离**（不同的 storage namespace）。

**验收口径**：离线模式下能完成「打开微信 → 看消息 → 发一条 → 回桌面 → 开相册」全链路；
同一份配置在宿主模式与离线模式下界面逐像素一致；离线模式跑完不往宿主写任何键。

## X6 · 多语言：中英双语最小闭环

**缺什么**：全仓中文硬编码（`config/` 345 个模块、`apps/` 101 个目录、`apps.js` 里的 name 都是中文）。
SillyTavern 本身是国际项目，非中文用户装上就是一堆方块字。**没有 `i18n` 目录，没有语言切换**。

**做什么**：
1. `i18n/zh-CN.json` + `i18n/en-US.json`，键按 `app.<id>.<slot>` 命名；
2. 取词唯一出口 `t(key, vars)`，缺键**返回 `⟪key⟫` 而不是空串**（空串会让界面静默少一行）；
3. App 名与图标文字走同一出口（`config/apps.js` 的 `name` 改成键）；
4. 语言选择：跟随宿主 / 强制中文 / 强制英文，三态；切换即时生效（不重启）。

**验收口径**：两语言包**键集合完全相等**（缺键逐条列出）；切到英文后界面无中文残留（可扫）；
缺键时显示 `⟪key⟫` 且控制台报一次（不静默）。

## X7 · AI 角色的自主行为预算

**缺什么**：所有现有桥都是「记录 AI 说了什么 / 推断状态」，**没有一个让 AI 主动做事**：
主动发一条消息、发个朋友圈、改个状态、拒接电话。而「拟真手机」的核心体验恰恰是
「手机自己会动」。仓库有 `config/smart-trigger.js` 之类阈值触发，但不是角色自主。

**做什么**：
1. 行为登记：`send_message` / `post_moment` / `change_status` / `reject_call` / `set_reminder` 五类，每类带**预算**（每小时/每会话上限）；
2. 决策来源：只消费已到手的事实（X1 总线 + 现有桥的三态读数），**不新起模型调用**（模型调用归宿主生成侧）；
3. 静默规则：夜间/勿扰/连续未回时不发（禁用 → `suppressed` + 原因码，不静默吞）；
4. 用户可见：设置里能看到「角色最近自主做了什么」，可关停可限额；
5. 每次行为留**回执**：因为什么事实、触发了哪条规则、预算剩多少。

**验收口径**：预算耗尽后不再产出（`exhausted` 与 `suppressed` 不同形）；
关停后零行为但事实通道仍可读；每条行为都能回源到具体事实（点开可查，不许「AI 觉得」）。

## X8 · 多任务与后台：App 状态保留与回收

**缺什么**：有返回栈、有 `releasePhoneInactiveResources`、有会话级回收，
但**没有「后台 App 保留多久、恢复时状态还在不在」的语义**。用户切走再切回，有的 App 状态还在、
有的重置了，这不是设计，是各处实现差异。

**做什么**：
1. 定义 App 生命周期四态：`foreground` / `background`（状态保留）/ `suspended`（状态丢弃、可重建）/ `closed`；
2. 每 App 声明自己能被 `suspended`（重建成本低的）还是必须 `background`（有未保存草稿的，如微信输入框）；
3. 内存压力下的回收顺序：先 `suspended` 后 `background`，**有未保存草稿的永不自动回收**；
4. 恢复语义：`background` 恢复必须**逐字段一致**（滚动位置、草稿、展开态），`suspended` 恢复回到首页且明说「已重置」。

**验收口径**：微信打一半草稿 → 切到相册 → 切回，草稿与光标位置一致；
无草稿 App 被回收后恢复不报错且回到首页；八 App 连续切换后内存不增长（读数可复跑）。

## X9 · 锁屏与「今天」：手机的门面

**缺什么**：本仓有主屏（图标墙）、有通知中心、有洞察，但**没有锁屏**——
手机最第一眼的那一屏（时间、日期、未读、今日摘要、快捷入口）不存在。
用户打开手机直接落到图标墙，等于跳过了「这台手机今天怎么样」这一层。

**做什么**：
1. 锁屏面：剧情钟时间 + 日期 + 天气（`apps/weather` 的登记读数）+ 未读数 + 今日摘要（今日消息数/日记/日程）；
2. 解锁：上滑/点击，或直接点通知进入对应 App；
3. 摘要**只聚合已有事实**（X1 总线），不新算、不猜；无数据显示「今天还没有什么」而不是 0；
4. 可关：设置里能关掉锁屏直接进桌面（尊重用户习惯）。

**验收口径**：锁屏读数与各 App 内读数逐项一致（同源，不许各算一遍）；
关掉锁屏后启动路径与 v4.157 一致；点通知能直达对应会话/条目（不是只打开 App）。

- **A 批（通道与规则，先做）**：`X1` → `X2`（总线是其他项的输入，权限是装载的前置）

## 本期纪律

1. **不许再造「登记面」**：每项都必须有真实消费点（用户能点、能看、能改），只登记不消费即不算交付。
2. **三态不塌**：`unknown` / `denied` / `absent` / `suppressed` 各自成态，禁止合并成一个「无」。
3. **跨 App 只走总线与权限面**：新代码出现 `直接读别人 storage 键` 即视为返工。
