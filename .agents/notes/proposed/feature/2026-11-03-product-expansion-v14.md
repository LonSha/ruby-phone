# Agent Note: RubyPhone 第十四期拓展创新计划

Status: proposed

## Problem

第十三期留下了可复用的能力，也留下了实现覆盖、真实交互和宿主证据之间的差距。本计划以2026-11-03本地源码为基线；完整侦察范围与旧提案分类见[证据与批次](../../../../docs/planning/2026-11-03-product-evidence-v14.md)。

## Proposal

在既有机制上新增跨步骤的用户操作和结果；每项都写出相对旧题目的行为增量，不重复宣称首次发明底座。与[另一份九项计划](../architecture/2026-11-03-product-optimization-v14.md)共18项，两仓共36项。以下均为待实施提案，不升版、不代表已经修复；先沿真调用链确认缺口，已满足的子能力只作复用依据。

### R14-X1 · 一段交流的待回应清单

- **现有底座与差距**：复用comm-thread、comm-time与微信真消息。
- **本期交付**：把消息、错过来电和已确认约定按交流线聚合，逐项选择已回应/稍后/无需回应并回到原处。
- **玩家入口**：会话台→待回应。
- **验收旅程**：回应一项不关闭整段交流；无源未读不猜；手动标记与实际消息回执区分，刷新保留且会话隔离。
- **实施规模**：L–XL，包含数据owner、控制器、界面与定向运行验证；不能只交内核或登记表。

### R14-X2 · 多人邀约的邀请到散场

- **现有底座与差距**：复用group-deliberation、group-vote-handoff、日程和affair-state。
- **本期交付**：在已有协商基础上新增邀请对象、候选时段、逐人答复、改期与活动结束回执的同一旅程。
- **玩家入口**：群聊议题→邀约卡→日历。
- **验收旅程**：改期使旧答复待复核，不默认全员参加；只确认后建日程，取消不删除相关聊天，重复确认不重复建。
- **实施规模**：L–XL，包含数据owner、控制器、界面与定向运行验证；不能只交内核或登记表。

### R14-X3 · 等一件事发生再提醒我

- **现有底座与差距**：复用workflow-runtime、事件源和通知落账。
- **本期交付**：提供面向用户的条件提醒：收到指定人的有效回复、任务完成、地点有新记录；带预览和触发来源。
- **玩家入口**：提醒页/日历的条件提醒编辑。
- **验收旅程**：条件未满足不提醒；重复事件只触发一次；条件无真源显示暂不可用；禁用后不再触发，不要求后台模型常驻。
- **实施规模**：L–XL，包含数据owner、控制器、界面与定向运行验证；不能只交内核或登记表。

### R14-X4 · 共同清单与分工交割

- **现有底座与差距**：复用errand-store、多人活动和财务回执。
- **本期交付**：将本月个人待办扩成多人分工、代办、部分完成和有据分摊；付款仍走原财务确认。
- **玩家入口**：这个月清单→共同事项。
- **验收旅程**：甲代办不自动宣告乙付钱；部分完成保留余项；作废不改账；分摊总额守恒，未确认不扣款。
- **实施规模**：L–XL，包含数据owner、控制器、界面与定向运行验证；不能只交内核或登记表。

### R14-X5 · 到了那天才打开的时光信封

- **现有底座与差距**：复用timeweaver、照片/消息引用与剧情钟。
- **本期交付**：用户选择真素材，设剧情日或明确事件解封，允许延期/撤回；解封展示保存时的快照边界。
- **玩家入口**：织光机/收藏中的时光信封。
- **验收旅程**：未到期不暴露正文；无剧情钟不提前打开；来源删去说明快照/引用差异；不自动生成对方回信。
- **实施规模**：L–XL，包含数据owner、控制器、界面与定向运行验证；不能只交内核或登记表。

### R14-X6 · 一次经历的可审阅分享页

- **现有底座与差距**：复用sharing-boundary、creator bundle、来源投影。
- **本期交付**：把选中的消息片段、照片、日程和作品组成一次经历包，逐项预览接收人可见范围及缺失附件。
- **玩家入口**：分享/迁移面→经历包。
- **验收旅程**：仅勾选素材出包；秘密及未授权内容不随嵌套引用漏出；重导不重复；不把界面文字当事实回填上游。
- **实施规模**：L–XL，包含数据owner、控制器、界面与定向运行验证；不能只交内核或登记表。

### R14-X7 · 行程进行中的改道与接续

- **现有底座与差距**：复用现有旅行/多人活动、日程和剧情时钟。
- **本期交付**：在已有行程之上新增当前站、晚到、跳站、临时会合与确认后的后续时段重排。
- **玩家入口**：旅行/活动原页的进行中面板。
- **验收旅程**：跳过一站不删除历史；改道先预览受影响约定；未知交通时间不编造；费用仅提供草案不自动结算。
- **实施规模**：L–XL，包含数据owner、控制器、界面与定向运行验证；不能只交内核或登记表。

### R14-X8 · 一件事的跨App实况页

- **现有底座与差距**：复用affair-state、incident-workspace、today及source-locator。
- **本期交付**：为用户选定事件提供持续来源集合和上次查看以来的变化：新回复/改期/新作品/来源失效。
- **玩家入口**：事务台→事件实况。
- **验收旅程**：三类真实来源能增量刷新；同条不重复；源改动标明而非复制成新事实；删除实况不删除原内容。
- **实施规模**：L–XL，包含数据owner、控制器、界面与定向运行验证；不能只交内核或登记表。

### R14-X9 · 回来以后分批处理错过的事

- **现有底座与差距**：复用away-mode、通知中心、inline actions与待回应清单。
- **本期交付**：在已有错过清单上新增分组分批审阅：稍后、已看、去处理、无需处理，保留中途游标。
- **玩家入口**：通知中心→不在的时候→分批处理。
- **验收旅程**：处理半批关页重开可接续；已看不等于已回复；过期项不自动执行；每个写动作仍单独确认且回执可追溯。
- **实施规模**：L–XL，包含数据owner、控制器、界面与定向运行验证；不能只交内核或登记表。

## Dependencies and delivery

O1/O2/O3先保障入口、取消与定位；O4/O5/O6为写操作提供保护；X2/X4依赖O5的幂等回执，X7依赖真实剧情钟与既有日程owner，X8依赖O3，X9复用X1与O5但基础审阅可独立交付。

六个大批次A–F见证据页。每批每仓三项，可并行侦察、独立编写；改同一文件时串行合并。每批预计3–5个有效开发日，整期约18–30日的双仓并行容量；这是工作量预算，不是无人值守时长承诺。

## Alternatives considered

- **沿用第十三期未勾选项**：便于快速排队，但状态已与源码错位，故保留历史并按行为增量重排。
- **一次增加九个独立内核/App**：实现隔离直观，但会重复制造无人消费的能力；优先复用已有入口和owner，确无承载位置才建新模块。
- **先清空全部审计及文档债**：可降低部分维护成本，但会延迟主题功能；验证只随本批交付补齐，不独立扩成第二套平台。

## Acceptance criteria

1. 九项各完成上述用户旅程；原版已有的行为不计为本期新增成果。
2. 每项验收记录包含真实入口、读/写owner、成功/失败/取消/重复/换会话与重开适用项；只读功能证明不写源。
3. 涉及权限和秘密复用既有裁决；未知、缺席、空内容和被挡住不得互相冒充。
4. 定向测试在真实代码及真实桥上运行；必要负控制用字节副本，禁止在工作树破坏后与扫描并发。
5. 手机侧遵守AGENTS：实施期只做定向验证，整期收口跑一次`npm run check`；浏览器通过与存量允许失败分别报告，禁止仅以退出码0宣布全绿。
6. 真SillyTavern验证以实际可访问宿主为准；不可执行的触摸、宿主事件和模型表现列为未验，浏览器独立页或jsdom不能顶替。

## Risks

跨owner写入、晚到任务、旧档迁移和来源失效是主要风险。先收窄操作范围、预览差异、按owner提交并保留部分失败结果；不承诺跨账原子回滚。发现底座已有完整行为时停止重复施工，转向本项的薄弱旅程，并在证据页记录调整。模型生成的文字始终是草案，未经事实准入不得写回正史。
