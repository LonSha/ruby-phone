# Agent Note: RubyPhone 第四期拓展九项——阅读、群像与创作的完整旅程

Status: proposed

## Problem

基线为 2026-10-15 的 `main@fe5f04f` / v4.12.0，与远端同步。手机已有问答、关系回忆册、约会、旅行、阅读、创作与流程编排；继续增加同类 App 图标不会自动提高可玩性。上游记忆插件已有 lore-import/story-annual/branch-canon/fated-recall 等内核，但手机 `apps/` 与 `config/` 对这些命名出口的检索未发现直接消费；这只能证明该调用形态缺失，不能替代对动态调用的逐项复核。

本期选择“用户此前不能完成的任务”，尽量增加在既有页面内，不重建手机、不复制记忆库。九项是提案，不是功能完成声明；读码事实、底层自动化与真实体验分开。

## Proposal

### R4-X1 · 可追问的往事会话（P1 / L）
- **现状证据｜读码**：`apps/memory/memory-app.js::askPast` 单次传 question + 空 opts；memory-view 是单输入单结果区。R3-X2 已实现单次有据查询，但“那后来呢”“另一个人呢”没有会话语义承接。
- **用户收益与增量**：连续追问同一件事，保留所选人物、时间、分支；可返回旧问题、改条件重问，明确显示“本次沿用哪些条件”。
- **落点与依赖**：memory App 承担对话 UI；M4-X4 负责问题上下文与消歧，R4-O1/O2 提供回源和取消。手机只存问句、条件及引用，结果换代后重取，不长期镜像上游正文。
- **验收**：真宿主完成五轮追问，明确换人后旧人物不残留；换会话/分支后旧结果不混入；歧义时让用户选择；真实模型参与的回答须逐句核来源，未实测不标效果已验。
- **不做**：不把它变成通用 AI 聊天 App，不无限保存对话全文，不由手机自己猜角色身份。

### R4-X2 · 设定资料导入向导（P1 / L）
- **现状证据｜读码**：阅读器可导 TXT/EPUB，sourcebook 实际围绕时光信等功能，不是上游分层设定导入页；上游已有 `loreImportParse/Entities/Preview/Plan` 但多为纯预览。
- **用户收益与增量**：从手机选一份资料，逐段看分类、同名角色映射与冲突，确认导入；知道哪些是设定、哪些是前史，不把看过一本书当成角色经历过。
- **落点与依赖**：在 reading/memory 增加“作为创作资料导入”；依赖 M4-O5/O6、M4-X1。手机负责文件/选区/预览，最终写入在记忆插件原生确认页完成，现有跨仓桥仍只读；没有经评审的交接能力时不得私开写桥。
- **验收**：完整长文含尾章事实、同名角色、混合规则与前史；逐段可改类、可取消；确认后能查询且重启保留；拒绝项不入库、重复提交不重复导入。
- **不做**：不抓取网络小说、不默认上传整本书、不新增事实数据库。

### R4-X3 · 可阅读、可编辑的故事年鉴（P1 / L）
- **现状证据｜读码**：上游 `story-annual.js` 已有四要素/证据/编辑白名单；`_storyAnnualChapters/_storyAnnualSummary` 在生产代码检索只见读取，手机未见其直接消费。不能把模块存在当作已有年鉴阅读产品。
- **用户收益与增量**：按卷章读“发生什么、人物怎样变化、留下哪些问题、值得记住的原话”，编辑文稿、导出本地可读文件。
- **落点与依赖**：reading + creationdesk，接 M4-O6/O9、M4-X2；文稿是草稿，事实修改交上游；复用 R4-O5/O9 保存与迁移。提供作者版/按当前进度阅读版。
- **验收**：从真实会话生成三章年鉴，每条关键事件可回源；改标题不改事实；正文被编辑后相关段提示需重建；导出后离线可读，未读章节秘密不出现在封面/目录摘要。
- **不做**：不新增摘要引擎、不以关键词去八股计数声称文风优秀、不自动外网发布。

### R4-X4 · 支线结局选择与接续工作区（P2 / L）
- **现状证据｜读码**：`config/branch-contrast.js` 已能对照，记忆侧 branch-canon 已能列冲突/生成选择计划；手机没有把它接成“比较结局→选择→创建后续”的操作旅程。
- **用户收益与增量**：选择哪条结果成为后续正史，保留其他支线供回看；不让两条互斥结局同时进入新卷。
- **落点与依赖**：archive/memory 既有入口，接 M4-O6、M4-X3；手机只读选择预览并转原生确认，分卷写入和撤销归上游 owner。
- **验收**：两支线三个冲突位，选择部分时不能假装完成；确认后新卷只读选中结局；撤回只撤本次接续，原分支原文不变；缺上游能力显示不可用。
- **不做**：不把游戏存档管理重写一遍，不自动判定哪条故事更好，不暗改原聊天。

### R4-X5 · 角色信息差与证词对照页（P1 / M）
- **现状证据｜读码**：手机已有 perspective-card-contract，聊天已消费视角；但聊天过滤不等于作者能并排阅读“甲亲历、乙听说、丙误信”。上游 relation-history/perspective-card 可复用。
- **用户收益与增量**：写群像、悬疑时看清不同人对同一事的理解，点证词回原文；角色扮演模式只看当前角色可知内容。
- **落点与依赖**：chars/memory 中增加并排视角，已有视角出口先交付；证词冲突深读接 M4-X5。作者与角色模式显式选择，切换不把全知正文塞入角色生成上下文。
- **验收**：三人信息差案例，同一事件三种认知各自对应来源；时间拉回揭穿之前不显示后来真名；作者比较不改变知识账；手机窄屏改为逐人切换而非挤成三列。
- **不做**：不再造知识权限规则、不新增好感度算法、不以一票多数裁真相。

### R4-X6 · 可操作的线索与未完事项板（P2 / M）
- **现状证据｜读码**：plotline/playbook、日历和约定已有；上游 causal-chain 已实现确认边/推测边及追溯。手机未见 causalChain 命名出口消费，尚需逐项核对动态入口。
- **用户收益与增量**：按人物/地点查看未结约定、伏笔和因果线；选“追这条线”打开相关聊天或地点，避免只看计数。
- **落点与依赖**：plotline 增列表/详情，不新造无限画布；读既有 causal-chain/commitment/seed；行动用原 App owner，依赖 R4-O1，完成状态仍由剧情事实决定。
- **验收**：一条未结约定、一条已解决伏笔、一条仅推测因果同屏可区分；点击回源和去行动均到正确对象；选择追踪不自动标已解决；重新生成后视图跟随有效证据。
- **不做**：不扩大 MAX_OPEN、不增加第二套任务事实库，不把“提醒过”当“履约”。

### R4-X7 · 群聊投票与协商式活动安排（P2 / L）
- **现状证据｜读码**：wechat 群调度、date-playbook、traveldesk 已有，检索这些生产路径未见投票产品。现有行程确认不等于多人表达不同意见。
- **用户收益与增量**：群里提出时间/地点选项，人物按已知偏好回应、弃权或反对；用户综合结果再确认活动，形成可玩的协商过程。
- **落点与依赖**：wechat 内投票消息 + 既有日历/旅行入口，复用稳定成员 ID 与约定 owner；表决不直接变成承诺，只有明确接受者进入参与名单。
- **验收**：四人群两轮改方案，缺席者不被代投、平票不自动拍板、重复回复不重复计票；确认一次只生成一份活动；真实模型检查角色意见有依据，不要求每人机械发言。
- **不做**：不接真实通讯平台、不引入常驻群聊代理、不用关系分数伪造角色同意。

### R4-X8 · 阅读研究笔记与全文找句（P1 / M）
- **现状证据｜读码**：reading 已有 TXT/EPUB、正文附件、段落摘录；reader UI 主要为章选择/主题/字号/上一下一章，未见书内全文查找和带个人批注的研究组织。
- **用户收益与增量**：搜全书原句，给摘录加批注与标签，汇成创作素材清单；从笔记回到对应章段，区分原文与自己的解释。
- **落点与依赖**：reading 复用附件、摘录 owner 与 creationdesk；R4-O6/O9；只增本地可重建索引和笔记字段，不把全书送进每轮提示词。接 M4-X9 属后续联合查证，不阻塞本地功能。
- **验收**：命中位于末章和跨段的文字均可找到；改版书籍提示旧摘录锚点需确认；批注不是原文；导出/恢复后标签、批注、原文定位保留。
- **不做**：不再交付一次“摘录功能”，不默认把笔记提升为剧情事实，不建设云端知识管理平台。

### R4-X9 · 面向下一幕的写作取材板（P2 / L）
- **现状证据｜读码**：creationdesk 已有多素材多目标草稿；place/约定/视角/关系入口分散。现有“发布草稿”没有按下一幕目标合成可控取材集合。
- **用户收益与增量**：选择人物、地点、时间和写作目标，预览该用的旧事、尚未兑现的约定及禁知内容边界，再选择用于主聊天或创作草稿。
- **落点与依赖**：creationdesk 复用 context-compose/注入预算 owner；M4-X8 负责按任务组织事实，手机负责取舍和目标选择。引用动态重取，不存第二套世界状态。
- **验收**：同一人物分别准备“重逢”“赴约”“冲突后和解”三幕，材料有任务差异且均可回源；取消不触发生成；选定时点之后的事实不提前进入；最终生成需真宿主/真模型体验核验。
- **不做**：不自动编造未发生事件，不替用户推进时间，不新建导演代理或注入框架。

## 批次与跨仓分工

先交付 X1/X2/X8（问、导入、查资料），再 X3/X5/X6（回顾和群像），最后 X4/X7/X9（分支与创作玩法）。可按上游准备度调整并行，但不能以假数据 UI 宣布完成。

记忆插件持有事实、来源、时态、角色知识与确认写入；手机持有交互、文件选择、文稿和本地阅读。现有桥只读不抛不猜，写入流程通过上游原生确认页交接；若后续确需新命令通道，先评审契约，不在本计划里假称接口已存在。

本篇保留第四期的理由、版本与验证边界；后续排序由[第五期X九项](2026-10-20-product-expansion-v5.md)接管。两篇部分重叠而非完全替代：已有模块继续复用，第五期按具体语义/真实消费缺口补闭环，并明确区分新能力；不得将本篇历史“当前缺口”直接复活成从零任务。

## Alternatives considered

- **每项新建 App**：入口显眼，但手机已有大量 App，会进一步分散流程；优先在已有页面增加任务入口。
- **手机自行实现上游新算法**：可减少跨仓等待，却会出现两套身份/时态/事实解释；上游负责推理和事实，手机负责交互。
- **只消费纯函数输出就标完成**：容易自动化验收，但不能证明资料已导入、接续已落盘；必须验原生确认与重开回读。

## Acceptance criteria

恰九个 X 编号，均有用户任务、已有底座、增量、依赖、验收和不做范围。跨仓同一旅程按 owner 分开验：上游不能拿手机截图代替事实验证，手机不能拿上游单测代替点击旅程。真实模型缺席时只报告机制通过，内容品质保留待验。

计划阶段仅修改 Markdown，使用定向格式/链接检查；不增加守卫脚本、App 注册、依赖包或版本号。本轮提交推送的是计划，不是九项实现。

## Risks

新交互容易被技术术语淹没：默认显示任务与结果，诊断细节折叠。上游最新能力中存在未接真实数据的面，须先完成 owner 链路。群聊与写作效果需要真实模型，不以模板文本或纯函数稳定性假报成功。
