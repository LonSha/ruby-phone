# Agent Note: 第八期 RubyPhone 拓展创新——让手机成为可被用户塑造的生活媒介

Status: proposed

## Problem

第七期已经把地点机会、节庆传统、创作者生涯、场景作者台、社群自治、共同收藏、互动连载、师徒实践和平行生活做成了产品底座。第八期不再重复“再做一个世界模块”或“再做一个剧情 App”，而是回答一个更具体的问题：用户能不能把 RubyPhone 的生活规则、视觉表达、内容资产和人物关系塑造成自己的长期媒介，并在多个场景中反复使用。

当前代码已经具备 `scenario-authoring-desk`、`workflow-design`、`relic-collection`、`multimedia-serial-studio`、`community-autonomy`、`creator-career-market`、`parallel-life-sandbox` 等构件，但它们仍主要以单个项目为单位。独有机制应来自“手机主题包 + 可复演规则 + 有来源的生活资产 + 跨场景发布”的组合，而不是依赖外部网络、无限自治代理或大量新图标。

## Proposal

### R8-X1 · RubyPhone 主题包：把一套生活美学与交互规则保存为可切换媒介（P0 / XXL）

- **核心体验**：用户创建或导入一个主题包，主题包不仅改变颜色，还能定义首页结构、状态语言、通知语气、常用工作包、声音/图片资源和角色呈现方式。
- **真实落点**：以 `phone.css`、`config/apps.js`、`scenario-authoring-desk`、`workflow-design`、`l0-assets` 和设置层为基础；主题包只引用仓库内或用户明确提供的资源，不动态执行代码。
- **区别于第七期**：第七期是黑曜石视觉重构和若干 App 样式；本项是可持久化、可复制、可预览、可回退的“主题作为内容资产”。
- **验收**：制作生活主题与创作主题两包，切换后入口/文案/资源正确；主题缺资源时逐项降级；导入预览不写数据；重开、换会话和恢复旧主题不串状态。

### R8-X2 · 规则剧场：用户不写代码也能编排会改变生活的条件规则（P1 / XXL）

- **核心体验**：用户用“当……并且……时，提出……；如果拒绝，则……”编排规则，让日程、人物联系、场景和作品产生可复演后果。
- **真实落点**：复用 `scenario-authoring-desk`、`workflow-runtime`、`causal-board-contract`、`proactive-proposal` 和 `branch-contrast`；规则采用有限词法和白名单动作，绝不执行任意 JS。
- **区别于第七期**：第七期场景作者台描述一场可演出内容；本项是可复用、可测试、可暂停的生活规则层，作用于多个场景但不拥有 App 数据。
- **验收**：至少一条规则覆盖消息、日历和创作三个 owner；条件缺失时不触发；规则冲突时用户可选择优先级；暂停/复制/删除规则不改历史结果；同一规则可在平行分支独立运行。

### R8-X3 · 有因果的城市经济：地点、人物、物品和承诺形成可观察的交换网络（P1 / XXL）

- **核心体验**：街区不是静态地点列表；店铺、角色、活动和有限资源会因用户的选择、缺席、合作或拒绝改变机会。
- **真实落点**：组合 `district-opportunities`、`place-roam`、`wallet`、`shop`、`creator-career-market`、`life-events` 和 `relic-collection`；只做虚构世界内的本地账，不接真实支付或实时地图。
- **独有机制**：交换的不只是钱，还包括时间、信任、材料、名额和作品引用；每次变化都有来源和可回退的事件链。
- **验收**：三个地点、四名角色、两种资源形成至少两条相互影响的机会链；拒绝和缺席造成不同后果；价格/名额变化可追溯；重开和分支隔离；无数据时不编造城市事实。

### R8-X4 · 可变化的角色居所：把房间变成关系和记忆的空间接口（P1 / XL）

- **核心体验**：角色的房间、工作台、收藏和摆设会随着共同经历变化，用户可以通过空间进入关系事件、作品或回忆。
- **真实落点**：复用 `freehome`、`relic-collection`、`personal-dossier`、`character-presence`、相册和音乐 owner；居所保存物件引用、布置版本和可见范围，不复制原始聊天。
- **区别于第七期**：不是新增一个家居 App，而是让已有物件、事件和关系拥有空间化的入口，并且空间变化有真实来源。
- **验收**：至少两个角色居所、同一物件的不同摆放与解释、一次赠送/撤回/遗失；空间能回到来源事件；秘密物件不因进入居所而公开；旧布置可回看。

### R8-X5 · 角色共同媒体台：从聊天内容共同制作可留存的节目或作品（P1 / XXL）

- **核心体验**：用户和角色可以围绕一个主题制作播客、杂志、歌单、图文帖或小剧场，分工、审稿、删改和发布形成过程。
- **真实落点**：组合 `multimedia-serial-studio`、`creationdesk`、`commission-pipeline`、`sound`、`moments/blog` 和版本谱系；内容生成仍由宿主模型完成，手机负责项目、素材和审批。
- **独有机制**：每个节目既有公开成品，也保留“谁提出、谁反对、哪一版被舍弃”的制作关系，不把协作压缩成一条最终文本。
- **验收**：完成两期不同媒介节目，至少一次返修和一次成员退出；发布版可回到素材来源；私密素材不外泄；下一期能继承栏目规则但不复制错误状态。

### R8-X6 · 可交易的生活资产：让作品、物件、名额和承诺有明确的持有与转让故事（P1 / XL）

- **核心体验**：用户可以保存、赠送、借用、交换或授权一件有来历的生活资产，资产的历史和当前持有人分开显示。
- **真实落点**：深化 `relic-collection`、`asset`、`sharing-boundary`、`creator-career-market`、`commission-pipeline` 和 `portable-payload`；资产不等同文件，不因缺原媒体而伪装可用。
- **区别于第七期**：第七期共同收藏侧重多人不同记忆；本项增加持有权、使用权、授权期、转让条件和履约后果。
- **验收**：一件资产经历借用、转赠、失约和追回；历史持有人不被覆盖；无原媒体显示不可用但来源仍可查；跨项目复制先预览授权与冲突；撤销只撤未来使用。

### R8-X7 · 可复演的生活节目录：把一次复杂经历保存成可重播但不覆盖正史的节目单（P2 / XXL）

- **核心体验**：用户可以把一次旅行、争论、庆典或创作过程保存为“节目目录”，以后以不同角色视角复演，比较选择与后果。
- **真实落点**：组合 `scenario-authoring-desk`、`multimedia-serial-studio`、`parallel-life-sandbox`、`resume-workbench`、`lineage-versioning`；复演读取快照和引用，不改原始生活账。
- **独有机制**：保存的不只是分支结果，还包括当时的入口、可见信息、错过的机会和参与者的选择顺序。
- **验收**：一份至少八节点目录含两种入口和三个结局；不同角色看到不同信息；修改作者版本不改旧演出；用户可从中途继续或丢弃演出；未解锁内容不提前泄露。

### R8-X8 · 手机内生的创作者生态：用户制作的主题、规则、工作包和节目可以组合发布（P1 / XXL）

- **核心体验**：用户可以把自己的主题包、规则、工作包、资产清单和节目目录组成一个可分享的“手机扩展包”，接收者可逐项选择，不必全量接受。
- **真实落点**：以 `portable-payload`、`data-backup`、`sharing-boundary`、`workflow-design` 和 `lineage-versioning` 为基础；包格式可离线解析，不提供远程脚本执行或真实外部市场。
- **区别于“导出”**：普通导出搬运数据；本项导出的是可解释的创作者作品，带依赖、许可、版本、预览、冲突和撤销边界。
- **验收**：发布者与接收者分别预览依赖，缺资源/缺 App/私密内容三类都不混淆；接收者只装规则或只装主题也能工作；更新包可比较；撤销接入不删除接收者已经自己的内容。

### R8-X9 · 双人共建的手机世界：让角色和玩家共同决定手机长成什么样（P2 / XXL）

- **核心体验**：角色不只是被联系对象，也可以提出主题、房间、节目、规则和收藏建议；用户批准、修改或拒绝后，手机世界逐步形成共同历史。
- **真实落点**：组合 `character-presence`、`community-autonomy`、`proactive-proposal`、`personal-dossier`、`scenario-authoring-desk` 和授权边界；角色只能提出可审阅提案，不能后台自行改机或发送不可逆动作。
- **独有机制**：共同世界的变化同时保留“谁提出、谁批准、谁反对、最终采用哪一版”，把关系变化落实到手机形态，而不是只增加好感数值。
- **验收**：两个角色提出冲突建议，用户选择后只影响对应世界版本；拒绝不会被记录成已完成；连续三轮提案能回顾演进；暂停主动性后没有后台生成；重开后共同历史仍可解释。

## Delivery sequence

- **A：媒介底座**：R8-X1、R8-X2。先让主题和规则成为可预览、可复制、可暂停的用户资产。
- **B：生活世界**：R8-X3、R8-X4、R8-X6。再让地点、居所和资产拥有可追溯的关系后果。
- **C：共同创作**：R8-X5、R8-X7。把协作制作和复演节目做成长期使用内容。
- **D：生态闭环**：R8-X8、R8-X9，并与 R8-O1/O6/O7/O8 联合验证导入、授权、恢复和提案边界。

## Alternatives considered

- **做一个对外联网的素材市场**：会引入账号、外部支付、远程代码和隐私风险，也偏离本仓的离线/本地定位；本期只做离线可解析的创作者包。
- **让角色完全自治地改造手机**：演出强但不可控，且会把主动机制膨胀成第二系统；所有角色行为都先变成用户可审阅提案。
- **把主题只做成换色皮肤**：无法形成差异化产品资产；主题必须同时影响入口、工作包、状态语言和资源引用。
- **把复演直接写回正史**：会破坏真实经历和分支边界；复演始终使用快照，不覆盖原始 owner 数据。

## Acceptance criteria

每项拓展都必须提供可参与的生产行为、用户选择、持久化成果、退出/暂停路径和恢复入口。静态素材、单个 JSON、展示页、虚构数值或测试套件本身都不能独立结项；真实外部网络、支付、定位和任意代码执行不在范围内。

## Risks

主题包、规则包和创作者包可能膨胀成插件平台。每种包都必须有有限 schema、依赖清单、权限声明、版本差异和无代码执行边界；任何无法离线预览或无法撤销的包都不能进入默认接入路径。
