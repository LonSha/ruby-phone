# Agent Note: ruby-phone 第五期拓展、拓宽与新功能九项

Status: proposed

## Problem

用户要求以真实代码重排下一轮产品方向，而不是沿用历史勾选或继续扩建守卫。规划基线为 **v4.30.0 / main@5edf59a**，核实日为2026-10-20；两仓已 fetch，规划起点均与 origin/main 同步。本轮只交付计划，不实现下面九项、不抬运行时版本。

第四期有真实实现，但接口存在、模块自检或派发事件不等于完整操作完成。本篇把已复现的问题、读码风险与新产品设计分开：优化项补既有能力，拓展项必须给出既有底座之外的新增结果。阅读范围是两仓规范、四期路线图与相关生产链路，**不是宣称通读全仓所有代码**。

## Proposal

恰好九个 R5-X 编号，全部待实施。P0=正确性/内容损失先处理，P1=高频可用性与新流程，P2=进阶创作；M/L 表示相对改动面，不是承诺工时。每项的验收都是未来实施目标，不能读成这次已经通过。

### R5-X1 · 随身物品与借还事项的可操作卡片（P1 / L）

- **现状证据与既有底座**：已有微信赠礼、商品和记忆物品状态；不是再建商城，也不把一条赠礼聊天当实物已转移。
- **用户收益与明确增量**：在现有联系人/来源页提供物品卡：当前持有人、所有者、借出证据、应还日期；可发起归还确认、查看历次交接，并从到期提醒打开同一事项。
- **实现落点与职责归属**：复用 memory/联系人 UI 与 M5-X1 投影，所有事实写入经原生确认；手机只存筛选/草稿/引用。
- **依赖与先后**：M5-X1、O2；可先做只读卡。
- **验收旅程**：借书→查看乙持有→申请归还→确认→卡片回到甲；取消不改持有人；无插件明示只可写草稿；同名物品可按来源区分。
- **不做范围**：不复制物品账、不扣真实钱包、不新增孤立App图标。

### R5-X2 · 把大目标拆成可推进的剧情任务（P1 / L）

- **现状证据与既有底座**：plotline-board 已能操作线索与未完事项，workflow 已能编排动作；新增的是用户目标分解与依赖，不是再造待办列表。
- **用户收益与明确增量**：在事项板加入目标树、前置条件和下一步入口；将既有约定、资料、地点或草稿附到目标。勾选只表达用户计划，事实达成必须由证据/确认产生。
- **实现落点与职责归属**：apps/plotline + M5-X2；复用导航/对象选择器，不新建工作流运行器。
- **依赖与先后**：M5-X2、O1；先做计划编辑后接事实状态。
- **验收旅程**：“搬家”目标展开三层，签约未完成时取钥匙显示受阻；点下一步打开原约定；撤回签约后UI同步，目标重开仍在；无插件保留纯计划模式且不称已记忆。
- **不做范围**：不做团队协作平台，不以九宫格计数充当任务推进。

### R5-X3 · 多人行踪时间带与会面证据（P2 / L）

- **现状证据与既有底座**：apps/place 已有地点探索与上游 scene 投影；本项不是重复建设地图漫游。
- **用户收益与明确增量**：选两到五名角色与时间窗，按角色展示有据的在场片段、未知区间和互斥地点；点击片段打开出处或地点，寻找可能会面的重叠区间但不自动认定见面。
- **实现落点与职责归属**：apps/place 的现有详情/导航 + M5-X3；手机只呈现派生数据，不推算位置。
- **依赖与先后**：M5-X3、O9；读侧功能不写故事。
- **验收旅程**：两人相同场所在不同时间不显示已见面；重叠但无互动证据仅标可能共处；未知区间不画连续线；320/375px 下可切人物和时段，返回保持视窗。
- **不做范围**：不接现实定位/地图API，不用动画代替准确时间。

### R5-X4 · 传闻源头图与证词回溯（P1 / L）

- **现状证据与既有底座**：跨社媒事件和证词对照已存在；“热度高”与“独立来源多”是不同结果，本期只新增后者的可用操作。
- **用户收益与明确增量**：从一条群消息/社媒事件进入“来自哪里”，显示转述链、共同根、独立证词与被撤回源；可沿边回到原消息，对照反证。
- **实现落点与职责归属**：现有社媒事件/来源定位/记忆证词页 + M5-X4；原消息不复制，秘密节点只显示允许的占位信息。
- **依赖与先后**：M5-X4，O3 可复用稳定事件身份。
- **验收旅程**：三次转发同一消息呈一个根，另一个目击者另列；删除根消息后引用显示失效；反证可点开；没有证据链时不画编造连线。
- **不做范围**：不重复实现舆论热度，不给人物贴骗子标签。

### R5-X5 · 群聊前的共同往事选择器（P1 / M）

- **现状证据与既有底座**：关系回忆册与个人视角卡已存在；新增是为当前整个参与者组挑安全共享材料，不是再列一个单人回忆页。
- **用户收益与明确增量**：在群聊/多人重逢入口选参与者和时点，预览所有人可共享的旧事，选择后交给原聊天草稿；增减成员即时重新核可共享范围。
- **实现落点与职责归属**：微信群聊/creationdesk + M5-X5；交接沿 O1，只有用户发送才调用原生成链。
- **依赖与先后**：M5-X5、O1/O3；旧草稿需刷新判定后才能发送。
- **验收旅程**：甲乙共享秘密可在两人草稿出现；加入丙后重新预览移除秘密，不能沿旧草稿一键误发；无知情数据提示无法判定，取消不发送。
- **不做范围**：不自动群发；不从亲密度推定群成员知情。

### R5-X6 · 作者改设定的影响预览页（P2 / L）

- **现状证据与既有底座**：记忆纠错、导入更新和年鉴编辑已有入口；本项处理有意修改成立设定及其后续，不是又一个纠错面板。
- **用户收益与明确增量**：选择原事实→输入新设定→看哪些约定/章节/人物引用受影响→逐项保留或重算→原生确认。完成后可打开受影响对象、撤销此次改写。
- **实现落点与职责归属**：apps/memory + 现有对象导航/确认入口 + M5-X6；UI保存未确认草稿，不自写上游账。
- **依赖与先后**：M5-X6、O6；只消费上游可执行能力。
- **验收旅程**：改人物住所的预览列出相关会面而不误改无关财务；取消零写；确认后重开与撤销可回读；未追踪关系明确标未知覆盖，不展示“全库无遗漏”。
- **不做范围**：不批量覆写聊天原文；不为本功能新建事务服务。

### R5-X7 · 可丢弃的假设场景双栏试写（P2 / L）

- **现状证据与既有底座**：正史选择和分支接续已存在；新增是未创建正式分支前的假设工作区，可直接丢弃，不把预演当既成结局。
- **用户收益与明确增量**：选择基线时点与两种假设，分别预览材料/约束并可显式试写；对照文本保留为草稿；只有用户选择转为正式分支后才调用原接续确认。
- **实现落点与职责归属**：creationdesk/pvdesk 既有草稿和生成队列 + M5-X7；复用 O1 交接，取消沿原请求生命周期。
- **依赖与先后**：M5-X7、O1；必须验证生成通道不会隐式登记假设事实。
- **验收旅程**：A接受邀请、B拒绝邀请同基线输出可比；试写前后正史事实不变；关页重开保留草稿但不自动生成；丢弃清临时选择，正式采纳不双建分支。
- **不做范围**：不自动多模型竞赛，不后台无限续写，不增加第二套生成API。

### R5-X8 · 周期日程、单次例外与多人空档选择（P1 / L）

- **现状证据与既有底座**：calendar-data.js 的 isRecurringType 仅生日/纪念日；现有约会安排、提醒、协作旅行已在，不能重新报“新增行程”。
- **用户收益与明确增量**：在原日历增加每周/每月重复时段、单次改期/跳过、持续时间及参与者冲突提示；选择共同空档后确认新安排，旅行复用该选择器而非另存日程表。
- **实现落点与职责归属**：calendar-app/data/view、原提醒调度与 M5-X8 的周期约定映射；投票通过 O2 进入此表单。
- **依赖与先后**：O2，M5-X8 为记忆同步依赖；本地日历可先独立交付。
- **验收旅程**：四周安排中改第二周、跳过第三周不改全系列；两名参与者冲突提供可解释空档；未知日程显示未知非空闲；从旅行页改期后相关日历引用一致，提醒不重复。
- **不做范围**：不接系统日历/闹钟，不后台常驻轮询；不重做旅行分工和结算。

### R5-X9 · 跨书专题夹与带来源的研究成稿（P2 / L）

- **现状证据与既有底座**：阅读已有单书全文找句、摘录/批注与研究清单；新增是用户选多书后围绕一个问题形成可编辑论证，不再重复全文搜索底座。
- **用户收益与明确增量**：建立专题，选资料范围并跨书查找，把原句、解释、反证分栏组织成稿；段落可回到原书，导出时带书名/章节/版本/定位；可显式交给取材板。
- **实现落点与职责归属**：apps/reading + M5-X9，复用附件和摘录owner，研究夹只存题目/引用/用户文字；无插件可做本地资料夹，联合记忆查询明确不可用。
- **依赖与先后**：O7/O8/O1，M5-X9；跨书研究能力与性能修复分别验收。
- **验收旅程**：三本书同名人物不混引；删除/改版后相关引文提示失效/需核；冷启动可回源；专题导出不包含未选择资料，批注不伪装原文；交接草稿可打开。
- **不做范围**：不全库上传、不复制整书到上下文、不自动认定研究结论为剧情事实。

## 执行批次与跨仓分工

第一包：O3/O4/O1及O2，先让投票、健康与交接不误操作；第二包：O5/O6/O7/O8/O9，完成找得到、导得准、读得顺；第三包：X1/X2/X4/X5/X8，形成高频剧情操作；第四包：X3/X6/X7/X9，形成进阶创作旅程。上游条件未就绪的手机项可先完成不撒谎的本地流程，但不得把降级模式标作完整交付。

所有手机状态沿 PhoneStorage；正文继续使用已有本地附件例外，不引入第二数据库。记忆事实仍由上游 owner 承担，手机以引用/草稿/选择为主。一个交接必须有目标实际消费与可打开结果，不能把一个事件名、owner字符串或“成功”通知当作终点。

## 历史决策当场裁定

- [第四期优化](../architecture/2026-10-15-product-optimization-v4.md)与[第四期拓展](../feature/2026-10-15-product-expansion-v4.md)为**部分重叠**：O1补R4-X9交接；O2/O3补R4-X7；O6补R4-X2；O7/O8补R4-X8；O9补R4-X1。本期明确每条缺口，不再报“新增取材板/投票/研究/追问”。
- O5是在R3-O4自然语言搜索底座上修日期/类型/候选链；O4修既有健康交接的应用前幂等，不增一个健康App。
- 旅行协作行程（R3-X6）、关系回忆册（R3-X5）、地点漫游（R3-X9）、时间胶囊、里程碑、任务入口/最近使用均已存在，**排除从零再做**。X8只扩周期时段与例外、共同空档，不重复旅行分工/费用。
- X1借还卡、X2目标依赖、X3行踪时间带、X4独立来源、X5共享往事、X6有意改设定、X7临时假设试写、X9跨书专题，各自新增结果已列于条目；它们复用底座而不是另增九个孤立App。
- 第一/二/三期排序均为历史；既有 declarative-workflow 与 host-capability-health 决定**不受影响**。没有完全吸收的旧决定，不删除/归档历史；旧笔记格式债另留，不占产品名额。

## Alternatives considered

- **继续逐个添纯函数出口和自检行**：易定位、易测，适合作为实现配套；但本轮已看到交接返回无人消费、语义判错仍可自检绿，不能作为独立产品名额。选择以真实入口到结果的旅程交付。
- **重写架构或每种需求新建账库**：可获得统一接口和独立开发边界，但会复制事实、持久化、预算与回滚职责。选择复用原 owner，只在有新语义时扩字段或关系引用；不成立时不硬建模块。
- **让模型自动解释、裁真相并执行**：适应自然语言能力强，但不可验证的裁决会污染长期状态。模型只在既有配置通道内作建议/表达，确定性约束、未知态与用户确认保留；不擅自开新外部服务。
- **照历史勾选继续推进或把全部旧项判未完成**：前者省调查成本，后者容易统一口径，却都会掩盖“有底座但链路某段失效”。选择具体记录已实现部分与新增验收，不抹掉历史交付。

## Acceptance criteria

本次规划交付：四份各九项、共36项；每项有事实依据或明确的设计边界、相对旧功能的增量、owner、依赖、用户验收与不做范围；根导航只指向第五期。守卫、审计、发布、台账、测试不单独占名额。计划文件提交并推送，两仓版本保持不变。

后续实施逐项记录三种结论：①代码/定向自动化；②真实宿主操作；③模型内容效果或不适用。前一层不代替后一层。新API/事件如现状不存在，先验证真实能力再设计窄契约，不把计划中的名称当已存在函数。浏览器/模型验收进对应功能，不另扩一套“第二系统”。

实施中只做相关定向验证；全部实施收口时才按仓规全量。此次计划编写任务自身收口的提交检查不等于36项功能已实现。验证日志与当前限制见证据文档。

## Risks

- 旧档字段缺失、同名实体和分支身份可导致错误推断：迁移保守、歧义显式确认，任何未知不得伪装空或否定事实。
- 引用派生减少重复存储，但源删除/改版会造成悬空：呈现失效引用，重算前验证源版本；不为避免悬空静默复制敏感正文。
- 新交互与语义范围会增加维护成本：优先扩现有页面/owner，不为每个名词建新App；数据规模上限与异步取消须随对应功能验。
- 本轮仅有代码与合成模块探针，未运行真实浏览器/宿主/模型旅程。性能目标是待验收目标，非已达读数；新功能缺口描述不以关键词无命中作为全仓不存在的证明。
- 两仓不同步升级时允许明确降级，但写操作不得假成功。本计划不授权生产部署、云同步、现实日历/财务改动或自动发送用户消息。
